Comandos de repetição

Repetição e números aleatórios

Estas são as notas da terceira aula: as três construções de repetição da linguagem C (while, for e do-while), os comandos break e continue que alteram seu fluxo, e a geração de números pseudoaleatórios com rand(). Os exemplos interativos logo abaixo colocam parte dessa teoria em prática, passo a passo.

Repetições e geração de números (pseudo)aleatórios

Uma estrutura de repetição (ou laço) executa um bloco de comandos várias vezes, enquanto uma condição permanecer verdadeira — em vez de copiar e colar o mesmo trecho de código a cada repetição necessária. O C oferece três construções para isso: while, for e do-while. As três são equivalentes entre si (qualquer uma pode ser reescrita nas outras duas) — a escolha de qual usar é uma questão de qual delas deixa a intenção do código mais clara em cada situação.

Construção while

O while é a construção mais simples: while (condição) { comandos; } testa a condição antes de cada repetição (por isso é chamado de laço de pré-teste) — se ela já for falsa na primeira vez, o corpo do laço nunca chega a executar. Quando a condição é literalmente a constante 1 (sempre verdadeira), o resultado é um laço infinito, que só termina por um break em seu interior — é exatamente essa a estrutura do exemplo Adivinhe o número: while (1) { ... } repete a leitura do palpite indefinidamente, e só um acerto do usuário aciona o break que interrompe o laço.

Construção for

O for reúne em uma única linha as três partes que normalmente aparecem juntas em um laço controlado por contador: for (inicialização; condição; incremento) { comandos; }. A inicialização roda uma única vez, antes da primeira verificação da condição; a condição é testada antes de cada repetição, como no while; e o incremento roda ao final de cada repetição, antes do próximo teste da condição. O exemplo Fatorial usa exatamente esse padrão para multiplicar de 1 até n: for (int i = 1; i <= n; ++i) factorial *= i; — note que i é declarado dentro do próprio for, existindo só enquanto o laço roda. O exemplo Potência mostra dois fors alternativos, escolhidos por um if: um multiplica a base exponent vezes (expoente positivo), o outro divide -exponent vezes (expoente negativo) — a mesma construção sintática usada para duas lógicas diferentes.

Construção do-while

O do-while inverte a ordem do teste: do { comandos; } while (condição); executa o corpo do laço primeiro e só então verifica a condição, repetindo enquanto ela for verdadeira. Por ser um laço de pós-teste, ele garante que o corpo execute pelo menos uma vez, mesmo que a condição já comece falsa — diferença que faz dele a escolha natural para validar (ou, de forma mais geral, repetir a leitura de) uma entrada do usuário, já que é preciso ler o valor pelo menos uma vez antes de poder testá-lo, como em do { printf("Escolha 1-3: "); scanf("%d", &opcao); } while (opcao < 1 || opcao > 3);. É exatamente esse padrão que o exemplo Soma com do-while usa para ler números do teclado: o corpo do laço (pedir e ler um número) sempre executa pelo menos uma vez, e só depois de ler é que while (numero != 0) decide se pede outro número ou encerra — não haveria como testar numero != 0 antes de ter lido o primeiro valor. Compare com Adivinhe o número, que resolve um problema parecido (repetir até uma condição de parada) com pré-teste: while (1) { ... break; ... } força a primeira execução com uma condição sempre verdadeira e sai manualmente com break, em vez do pós-teste automático do do-while.

Interrupções com break e continue

Os comandos break e continue alteram o fluxo normal de um laço a partir de dentro dele, tipicamente dentro de um if que testa alguma condição especial. O break interrompe o laço imediatamente, pulando para a primeira linha depois dele — é o que o exemplo Adivinhe o número faz assim que o palpite do usuário acerta o número sorteado, encerrando o while (1) que, de outra forma, rodaria para sempre. Já o continue não encerra o laço: ele pula direto para o teste da condição (no while e no do-while) ou para a expressão de atualização (no for), abandonando apenas o restante do corpo na iteração atual. O exemplo Soma com do-while mostra esse uso típico: ao ler um número negativo, if (numero < 0) { printf(...); continue; } descarta aquela entrada sem somá-la e sem sair do laço — o continue pula direto para while (numero != 0), pedindo o próximo número normalmente.

Geração de números (pseudo)aleatórios

Gerar números "aleatórios" em um programa determinístico como um executável em C é, na prática, gerar números pseudoaleatórios: uma sequência calculada por uma fórmula que parece aleatória, mas é inteiramente determinada por um valor inicial chamado semente.

Funções rand(), srand() e time()

A função rand(), declarada em stdlib.h, devolve a cada chamada um inteiro pseudoaleatório entre 0 e RAND_MAX (uma constante que depende da implementação, tipicamente INT_MAX). Sem nenhuma configuração, a sequência de valores devolvida por rand() é sempre a mesma a cada execução do programa — porque a semente usada internamente começa sempre com o mesmo valor padrão. É a função srand(semente), também de stdlib.h, que define essa semente e, com ela, toda a sequência de números que rand() vai gerar a partir dali.

O exemplo Rand chama srand(10) — uma semente fixa, escolhida deliberadamente para que a sequência gerada seja sempre a mesma a cada execução (útil para depurar ou reproduzir um resultado). Já os exemplos Dados e Adivinhe o número chamam srand(time(NULL)), usando o instante atual (em segundos desde 1970, devolvido por time(NULL), de time.h) como semente — como esse valor muda a cada segundo, a sequência de números sorteados também muda a cada execução, o que é o comportamento esperado de um dado ou de um jogo de adivinhação.

Gerando números aleatórios em intervalos específicos

Como rand() devolve um valor num intervalo fixo e tipicamente grande, obter um número num intervalo menor exige alguma aritmética sobre o resultado bruto. Para um intervalo de inteiros [1, N], o padrão é rand() % N + 1 — o resto da divisão por N cai sempre entre 0 e N - 1, e somar 1 desloca para [1, N]; é assim que o exemplo Dados sorteia um valor entre 1 e 6 (rand() % 6 + 1) e Adivinhe o número um valor entre 1 e 100 (rand() % 100 + 1). Para um intervalo de ponto flutuante, o exemplo Rand usa outra abordagem: divide o inteiro sorteado pelo maior valor possível (((double)rand()) / INT_MAX, um valor entre 0 e 1) e multiplica pelo tamanho do intervalo desejado (* 10), obtendo um double entre 0 e 10.

Fatorial

#include <stdio.h>

// Define o maior valor de fatorial calculável com int
#define MAX_FACTORIAL_VALUE 12

int main()
{
    int n;

    printf("Enter an integer: ");
    scanf("%d", &n);

    if (n < 0)
    {
        printf("Factorial is not defined for negative numbers.\n");
    }
    else if (n > MAX_FACTORIAL_VALUE)
    {
        printf("Factorial for values greater than %d cannot be computed with int data type.\n", MAX_FACTORIAL_VALUE);
    }
    else
    {
        int factorial = 1;

        // Calcula o fatorial usando um laço
        for (int i = 1; i <= n; ++i)
        {
            factorial *= i;
        }

        printf("Factorial of %d is %d\n", n, factorial);
    }

    return 0;
}

Como funciona o laço

for (int i = 1; i <= n; ++i) executa três passos a cada volta: testa i <= n, roda o corpo do laço se o teste for verdadeiro e, em seguida, incrementa i. A variável factorial acumula o produto — é o padrão clássico de "variável acumuladora" em um laço for.

Pergunta de checagem

O laço está escrito como for (int i = 1; i <= n; ++i). O que aconteceria se a condição fosse trocada para i < n (sem o igual), mantendo o resto do código como está?

  • ANada mudaria — i < n e i <= n produzem o mesmo conjunto de valores de i neste laço.
  • BO laço passaria a rodar uma vez a mais, multiplicando por n + 1 no lugar de n.
  • CO laço pararia uma iteração mais cedo, deixando de multiplicar por n — o resultado passaria a ser (n-1)! em vez de n!.
  • DO programa entraria em laço infinito, pois i nunca alcançaria n.

Certo! Com i < n, a última rodada em que o corpo ainda executa é i = n - 1 — o fator n nunca entra na multiplicação, então factorial termina valendo (n-1)!, não n!.

Não é isso. A resposta certa é que o resultado passaria a ser (n-1)!: com i < n, a rodada com i = n nunca acontece, então o laço para um fator antes do necessário.

#include <stdio.h>

float calculate_power(float base, int exponent)
{
    float result = 1.0f;

    if (exponent >= 0)
        for (int i = 0; i < exponent; ++i)
            result *= base;
    else
        for (int i = 0; i < -exponent; ++i)
            result /= base;

    return result;
}

int main()
{
    float base, result;
    int exponent;

    printf("Enter the base: ");
    scanf("%f", &base);

    printf("Enter the exponent: ");
    scanf("%d", &exponent);

    result = calculate_power(base, exponent);

    printf("Result: %f\n", result);

    return 0;
}

Como funciona o laço

A função escolhe entre dois laços for conforme o sinal do expoente: multiplica result por base, exponent vezes, se o expoente for positivo; ou divide, -exponent vezes, se for negativo. Em ambos, result começa em 1.0f — o elemento neutro da multiplicação.

Pergunta de checagem

O que aconteceria se o usuário digitasse exponent = 0, considerando que result começa em 1.0f antes dos dois laços for?

  • Aresult permaneceria 1.0f: como 0 >= 0 é verdadeiro, entra no primeiro laço, mas a condição i < 0 já é falsa na primeira checagem, então o corpo nunca executa.
  • BO programa entraria em laço infinito, pois nenhum dos dois laços tem uma condição de parada para expoente zero.
  • Cresult viraria 0.0f, já que qualquer número elevado a zero é multiplicado por zero.
  • DO segundo laço (divisão) seria executado, já que -exponent valeria 0.

Certo! Com exponent = 0, a condição exponent >= 0 escolhe o primeiro laço, mas i < 0 (com i começando em 0) já é falsa antes da primeira volta — o corpo nunca roda e result fica no valor inicial, 1.0f, que é matematicamente correto (qualquer base elevada a 0 é 1).

Não é isso. A resposta certa é que result permanece 1.0f: o primeiro laço é escolhido (exponent >= 0), mas sua condição i < exponent (isto é, i < 0) já começa falsa, então o corpo nunca executa.

Rand

#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <limits.h>

int main()
{
    /** Set a seed based on the current time
     * In Linux, the time() function returns the elapsed time in seconds from
     * January 1, 1970, 00:00:00 (UTC) to the present moment.
     */
    // srand(time(NULL));
    srand(10);

    // Generate and display 5 random numbers
    printf("Random numbers generated:\n");
    for (int i = 0; i < 50; i++)
    {
        double random_number = (((double)rand()) / INT_MAX) * 10;
        printf("%lf\n", random_number);
    }

    return 0;
}

Como funciona o laço

Um computador não gera aleatoriedade "de verdade": rand() usa uma fórmula determinística que parte de uma semente (seed) definida por srand(). A mesma semente sempre produz a mesma sequência — por isso este exemplo usa srand(10) em vez de srand(time(NULL)).

A expressão ((double)rand() / INT_MAX) * 10 converte o inteiro bruto devolvido por rand() (entre 0 e INT_MAX = 2147483647) em um valor double entre 0 e 10.

  • AO programa não compilaria, pois rand() exige que srand() seja chamada antes.
  • BA sequência de números continuaria sempre a mesma entre execuções — sem srand(), a semente interna do gerador usa um valor padrão fixo.

  • Drand() passaria a devolver sempre o mesmo número em todas as chamadas dentro da mesma execução.

Certo! Sem uma chamada a srand(), o gerador de rand() começa com uma semente padrão fixa (equivalente a srand(1)) — a sequência de números continua determinística e igual em toda execução, só que com uma semente diferente da escolhida deliberadamente aqui (10).

Não é isso. A sequência continuaria sempre igual entre execuções: sem srand(), o gerador usa uma semente padrão fixa internamente — é srand(time(NULL)), não a ausência de srand, que faz a sequência mudar a cada execução.

Como funciona a função

void roll_dice() não devolve nenhum valor — ela só executa uma ação (sortear e imprimir o resultado) e devolve o controle para quem a chamou. O operador % (resto da divisão) é o que limita o sorteio ao intervalo de um dado: rand() % 6 dá sempre um resto entre 0 e 5; somando 1, o intervalo vira 1–6.

result é uma variável local: existe só enquanto roll_dice() está executando e desaparece quando a função termina.

Adivinhe o número

#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main()
{
    int number_to_guess, user_guess;
    srand(time(NULL)); // Seed the random number generator

    // Generate a random number between 1 and 100
    number_to_guess = rand() % 100 + 1;

    printf("Welcome to the Guessing Game!\n");
    printf("I have selected a number between 1 and 100. Try to guess it!\n");

    // Loop until the user guesses the correct number
    while (1)
    {
        printf("Enter your guess: ");
        scanf("%d", &user_guess);

        if (user_guess < number_to_guess)
        {
            printf("Too low! Try again.\n");
        }
        else if (user_guess > number_to_guess)
        {
            printf("Too high! Try again.\n");
        }
        else
        {
            printf("Congratulations! You guessed the correct number: %d\n", number_to_guess);
            break;
        }
    }

    return 0;
}

Como funciona o laço

while (1) nunca vira falso sozinho — 1 é sempre verdadeiro. Esse laço só termina quando o break lá dentro é executado, o que só acontece quando o palpite está correto. É o padrão "laço infinito + break", usado quando não se sabe, de antemão, quantas repetições serão necessárias.

Soma com do-while

ver no GitHub ↗ 
#include <stdio.h>

int main()
{
    int numero;
    int soma = 0;
    int quantidade = 0;

    printf("Digite numeros para somar (negativos sao ignorados; digite 0 para parar):\n");

    do
    {
        printf("Numero: ");
        scanf("%d", &numero);

        if (numero < 0)
        {
            printf("  (ignorado, numero negativo)\n");
            continue;
        }

        if (numero > 0)
        {
            soma += numero;
            quantidade++;
        }
    } while (numero != 0);

    printf("\nSoma dos %d numeros positivos digitados: %d\n", quantidade, soma);

    return 0;
}

Como funciona o laço

do { ... } while (numero != 0); é um laço de pós-teste: o corpo (pedir e ler um número) executa primeiro, e só depois a condição é avaliada — por isso o programa sempre lê pelo menos um número, mesmo que o primeiro digitado já seja 0. Dentro do corpo, um número negativo aciona continue, que pula direto para o teste while (numero != 0), sem passar pelo segundo if nem somar nada — diferente de break, o laço continua rodando normalmente na próxima volta.

Pergunta de checagem

O que aconteceria se o continue; dentro do bloco que trata números negativos fosse trocado por break;?

  • ANada mudaria — para um número negativo, continue e break têm o mesmo efeito neste laço.
  • BO programa ignoraria o número negativo e pediria o próximo normalmente, exatamente como acontece hoje.
  • CO programa encerraria o laço assim que o primeiro número negativo fosse digitado, sem chance de digitar mais números — mesmo que ainda não tivesse digitado 0.
  • DO programa entraria em laço infinito ao encontrar um número negativo.

Certo! break interrompe o laço imediatamente, pulando para depois do while — diferente de continue, que só pula para o teste da condição e permite que o laço continue. Trocar um pelo outro faria o programa parar de pedir números assim que encontrasse o primeiro negativo, em vez de simplesmente ignorá-lo.

Não é isso. A resposta certa é que o laço terminaria ali mesmo: break sai do laço por completo, enquanto continue (o comando usado de fato no código) só pula para o teste da condição, deixando o laço seguir pedindo números.

Para lembrar. Use for quando o número de repetições é conhecido antes do laço começar (como percorrer de 1 até n). Use while quando a repetição depende de uma condição que só pode ser avaliada durante a execução — como no jogo "Adivinhe o número", que repete até o usuário acertar. Use do-while quando o corpo do laço precisa executar pelo menos uma vez antes de a condição poder ser avaliada — como em "Soma com do-while", que só sabe se deve parar depois de ler o primeiro número.
