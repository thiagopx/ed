Listas encadeadas

Estas são as notas da aula sobre listas encadeadas: uma estrutura que aloca memória para cada elemento no momento em que ele é inserido, e que liga os elementos por ponteiros em vez de guardá-los lado a lado. Partimos da lista simplesmente encadeada de inteiros e chegamos às variações — recursiva, circular, duplamente encadeada, de tipos estruturados e heterogênea —, todas como TADs em projetos com vários arquivos e Makefile.

Listas encadeadas

Até aqui, para representar um conjunto de dados usamos vetores. Um vetor ocupa um espaço contíguo de memória, e é isso que permite o acesso direto a qualquer elemento por v[i] — o chamado acesso aleatório. O preço é a rigidez: um vetor precisa ser dimensionado. O vetor dinâmico do módulo anterior ameniza o problema com realloc, mas cada realocação pode custar a cópia de todos os elementos, e nem sempre esse custo é aceitável.

A alternativa é uma estrutura que cresce e diminui um elemento por vez: a cada inserção, aloca-se memória só para o novo elemento; a cada remoção, libera-se só a memória dele. O espaço total ocupado fica proporcional ao número de elementos armazenados, sem reserva ociosa e sem realocações. Como cada elemento é alocado separadamente, não há garantia de que fiquem contíguos na memória — e, portanto, não há mais acesso direto. Para alcançar todos os elementos, cada um precisa guardar explicitamente onde está o próximo. Essa é a ideia da lista encadeada, que também é a base de várias estruturas que veremos nos próximos módulos.

Listas simplesmente encadeadas

Uma lista encadeada é uma sequência de nós. Cada nó guarda, conceitualmente, dois campos: a informação armazenada (info) e um ponteiro para o próximo nó (next). A partir do primeiro nó alcança-se o segundo seguindo esse ponteiro, depois o terceiro, e assim por diante. O último nó guarda NULL como próximo, sinalizando que a lista acabou. A lista em si, então, só precisa conhecer o endereço do primeiro nó.

Isso leva naturalmente a duas estruturas: uma para a lista e outra para o nó. A do nó é autorreferenciada — além da informação (aqui, um int), ela tem um campo que é um ponteiro para outra estrutura do mesmo tipo. No projeto 01_linkedlist, as duas estruturas são definidas só em linkedlist.c: 

// Define a structure for the linked list.
struct list
{
    ListNode *first; // A pointer to the first node in the linked list.
};

// Define a structure for a node in the linked list.
struct list_node
{
    int info;       // An integer value stored in the node.
    ListNode *next; // A pointer to the next node in the linked list.
};

Função de criação

Uma lista vazia é uma lista sem nós, e isso se representa guardando NULL no ponteiro para o primeiro nó. ll_create aloca dinamicamente a estrutura da lista, faz l->first = NULL e devolve o ponteiro para ela. Daí em diante, todas as operações recebem esse ponteiro (LinkedList *l) como primeiro parâmetro.

Função de inserção

A inserção mais simples coloca o novo elemento no início da lista. Ela aloca um nó, guarda nele a informação, faz o novo nó apontar para o que era o primeiro e, por fim, atualiza first para o novo nó. A ordem dessas duas últimas atribuições importa: se first fosse atualizado antes, o endereço do antigo primeiro nó — e com ele o resto da lista — seria perdido. 

// Function to insert an element at the beginning of the linked list.
void ll_insert(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode)); // Allocate memory for a new node.
    node->info = v;                                        // Set the 'info' field of the new node to the provided value.
    node->next = l->first;                                 // Make the new node point to the current first node.
    l->first = node;                                       // Update the 'first' pointer to point to the new node.
}

Adaptado de: Celes, W. Estrutura de Dados.

Essa operação tem custo constante: não importa quantos elementos a lista já tenha, são sempre as mesmas quatro atribuições. A consequência é que os elementos ficam na ordem inversa à de inserção — inserir 0, 1, 2, …, 9 produz a lista 9 8 7 … 0.

Função que percorre os elementos da lista

Para percorrer um vetor usamos um índice inteiro; para percorrer uma lista, a variável auxiliar é um ponteiro para nó. Ela começa em l->first, avança com p = p->next e o percurso termina quando ela vale NULL: 

// Function to display all elements of the linked list.
void ll_print(LinkedList *l)
{
    for (ListNode *p = l->first; p != NULL; p = p->next)
    {
        printf("%d ", p->info); // Print the 'info' field of each node.
    }
    printf("\n"); // Print a newline character to separate the output.
}

Duas limitações ficam evidentes. O percurso só vai do primeiro ao último, porque cada nó só conhece o próximo. E não há acesso aleatório: para chegar ao k-ésimo elemento, é preciso passar por todos os anteriores. O mesmo padrão de percurso aparece em ll_size (conta os nós) e em ll_is_in (devolve 1 assim que encontra o valor procurado, ou 0 se o percurso chega ao fim sem encontrá-lo).

Manutenção da lista ordenada

Quando a ordem dos elementos importa — por exemplo, manter os inteiros em ordem crescente —, cada novo elemento precisa ser inserido na posição correta. Isso exige percorrer a lista até encontrar o primeiro nó cujo valor não é menor que o novo, guardando durante o percurso um ponteiro para o nó anterior (prev): é ele que vai passar a apontar para o novo nó, enquanto o novo nó aponta para o que vinha depois de prev.

Se o percurso termina com prev ainda igual a NULL, o novo elemento é menor que todos (ou a lista está vazia) e o caso recai na inserção no início. Inserir no final não é um caso à parte: equivale a inserir "no meio" com prev apontando para o último nó e o próximo valendo NULL. Essa operação, ll_insert_sorted, custa um percurso; por isso, se a ordem não for relevante, prefere-se a inserção no início, de custo constante. A implementação completa está no exemplo Lista simplesmente encadeada, abaixo.

Função que retira um elemento da lista

Retirar um elemento é parecido com inserir em ordem: busca-se o nó com o valor desejado guardando o anterior. Se o nó for o primeiro (prev == NULL), first passa a apontar para o segundo; se estiver no meio, o anterior passa a apontar para o seguinte do nó removido. Nos dois casos, só depois de refeito o encadeamento o nó é liberado com free. Retirar o último nó, de novo, não é caso especial.

No módulo, ll_remove retira só a primeira ocorrência e devolve 1 se encontrou o valor, ou 0 caso contrário. Esse valor de retorno permite escrever ll_remove_all em uma linha, repetindo a remoção enquanto ela tiver sucesso: while (ll_remove(l, v));.

Função para verificar se vazia e função para liberar

Uma lista está vazia quando seu primeiro nó é NULL; ll_is_empty devolve exatamente o resultado dessa comparação. Já ll_free destrói a lista: percorre os nós liberando um a um e, por último, libera a estrutura da lista. O cuidado aqui é guardar o endereço do próximo nó antes de liberar o atual — depois do free(p), ler p->next seria acessar memória que não pertence mais ao programa. 

// Function to free the memory used by the linked list.
void ll_free(LinkedList *l)
{
    ListNode *p = l->first;
    while (p != NULL)
    {
        ListNode *t = p->next; // Store a reference to the next node.
        free(p);               // Free the memory allocated for the current node.
        p = t;                 // Move to the next node.
    }
    free(l); // Free the memory allocated for the list structure itself.
}

Adaptado de: Celes, W. Estrutura de Dados.

TAD Lista de inteiros

Reunidas, essas funções formam um tipo abstrato de dados, na linha do módulo de TADs: linkedlist.h declara os tipos LinkedList e ListNode só por nome (typedef struct list LinkedList;) e exporta as operações ll_*; as structs ficam escondidas em linkedlist.c. Note que até o tipo do nó é encapsulado: o cliente (main.c) nunca vê um nó, nunca segue um next — só chama ll_insert, ll_remove, ll_print e as demais.

Nos projetos deste módulo, o cabeçalho costuma declarar mais operações do que o .c implementa (por exemplo, ll_append, ll_reversed e ll_concatenate). Essas funções sem corpo são exercícios: ficam para você implementar. Por isso, nos exemplos abaixo, os cabeçalhos aparecem só com as operações implementadas, e cada exemplo lista quais protótipos ficaram como exercício.

Implementações recursivas

O encadeamento de uma lista tem uma definição recursiva natural: ele é vazio (nenhum nó, ponteiro NULL) ou é um nó seguido de um subencadeamento — e o next desse nó é, ele mesmo, o primeiro nó de um encadeamento menor, do mesmo tipo.

A recursão é sobre o encadeamento de nós, não sobre a estrutura da lista. Por isso, no projeto 02_linkedlist-recursive, cada operação pública (ll_print, ll_size, …) apenas chama uma função auxiliar static — _ll_print, _ll_size, … — que recebe um ListNode *. A auxiliar segue a definição ao pé da letra: se o nó é NULL, é o caso base; senão, trata o primeiro nó e delega o resto (p->next) à própria função. _ll_size, por exemplo, devolve 0 para o vazio e 1 + _ll_size(p->next) caso contrário.

Em alguns casos a versão recursiva é bem mais simples que a iterativa. Imprimir a lista de trás para frente, numa lista simplesmente encadeada, exigiria percorrê-la várias vezes; recursivamente, basta imprimir primeiro o subencadeamento e só depois o nó atual. A remoção também fica mais curta: a auxiliar só sabe remover o primeiro nó do encadeamento que recebe, e devolve o (eventual) novo primeiro nó — que quem chamou precisa reatribuir: 

static ListNode *_ll_remove(ListNode *p, int val)
{
   ListNode *aux;
   if (p != NULL)
   {
      // found!
      if (p->info == val)
      {
         aux = p;
         p = p->next;
         free(aux);
      }
      // continue to search
      else
         p->next = _ll_remove(p->next, val);
   }
   return p;
}

// Function to remove nodes from the list by their value.
void ll_remove(LinkedList *l, int val)
{
   l->first = _ll_remove(l->first, val);
}

Adaptado de: Celes, W. Estrutura de Dados.

É essa reatribuição (p->next = _ll_remove(...) e l->first = _ll_remove(...)) que refaz o encadeamento quando o nó removido estava no meio ou no início. A liberação também é recursiva: libera-se primeiro o subencadeamento, depois o nó. Ainda assim, recursão é uma opção, não uma regra: cada chamada de função tem custo, e a versão iterativa costuma ser mais eficiente. A comparação de duas listas (ll_equals) ilustra bem o raciocínio recursivo: dois encadeamentos vazios são iguais; se só um é vazio, são diferentes; senão, os primeiros nós precisam ter a mesma informação e os subencadeamentos precisam ser iguais.

Listas circulares

Algumas aplicações representam conjuntos cíclicos — as arestas de um polígono, os jogadores de uma partida em rodízio. Numa lista circular, o último nó aponta de volta para o primeiro, em vez de NULL. A rigor, não há primeiro nem último: a lista é representada por um ponteiro para um nó qualquer do ciclo, que serve de ponto de partida.

Sem NULL no fim, o critério de parada do percurso muda: visitam-se os nós a partir do ponto de partida até voltar a ele. Como o ponteiro auxiliar começa justamente no ponto de partida, um while comum pararia antes de entrar; a solução é um do-while, protegido por um teste de lista vazia: 

// Function to display all elements, starting from the first.
void ll_print(LinkedList *l)
{
    ListNode *p = l->first;
    if (p != NULL)
        do
        {
            printf("%d ", p->info);
            p = p->next;
        } while (p != l->first);
    printf("\n");
}

Adaptado de: Celes, W. Estrutura de Dados.

O projeto 03_circular-linkedlist usa esse mesmo padrão em ll_size. Ele também mostra os dois lados da circularidade: inserir no início fica mais caro, porque é preciso achar o último nó para que ele passe a apontar para o novo primeiro; em compensação, mudar o ponto de partida (ll_rotate) é uma única atribuição, l->first = l->first->next. Para liberar a lista, ll_free primeiro quebra o ciclo — e daí em diante a libera como uma lista comum.

Listas duplamente encadeadas

Na lista simplesmente encadeada, cada nó só conhece o próximo. Isso tem dois custos: não há como percorrer a lista de trás para frente com eficiência, e retirar um nó exige achar o anterior — mesmo que já se tenha um ponteiro para o nó a retirar. Numa lista duplamente encadeada, cada nó guarda também um ponteiro para o anterior (prev), e a estrutura da lista guarda, além do primeiro, um ponteiro para o último nó (last). O prev do primeiro e o next do último valem NULL.

No projeto 04_doubly-linkedlist, a estrutura da lista ainda tem um terceiro campo, count, atualizado a cada inserção e remoção — e com ele ll_size passa a ter custo constante, sem percorrer nada: 

// Define a structure for the linked list.
struct list
{
    int count;       // Number of elements in the linked list.
    ListNode *first; // A pointer to the first node in the linked list.
    ListNode *last;  // A pointer to the last node in the linked list.
};

// Define a structure for a node in the linked list.
struct list_node
{
    int info;       // An integer value stored in the node.
    ListNode *next; // A pointer to the next node in the linked list.
    ListNode *prev; // A pointer to the previous node in the linked list.
};

A inserção no início precisa acertar os dois sentidos: o novo nó tem prev = NULL e next igual ao antigo primeiro; se a lista não estava vazia, o prev do antigo primeiro passa a ser o novo nó; se estava, o novo nó também é o último.

A remoção, por outro lado, fica mais simples de raciocinar: achado o nó p, o anterior passa a apontar para o seguinte (p->prev->next = p->next) e o seguinte, para o anterior (p->next->prev = p->prev), sem precisar de nenhum ponteiro auxiliar. As condições de contorno são as extremidades: se p é o primeiro, não existe p->prev, e quem muda é first; se é o último, não existe p->next, e quem muda é last. Com o ponteiro last e os prev, percorrer a lista do fim para o início (ll_print_reversed) é tão simples quanto percorrê-la do início para o fim. Uma lista circular também pode ser duplamente encadeada, permitindo percorrê-la nos dois sentidos a partir de qualquer nó.

Listas de tipos estruturados

Até aqui a informação de cada nó foi um int, para que a atenção ficasse no encadeamento. Mas a informação pode ser de qualquer tipo, e o encadeamento não muda nada por isso. Uma forma particularmente interessante é guardar no nó um ponteiro para uma estrutura, em vez da estrutura em si: assim, qualquer que seja a informação, o nó tem sempre o mesmo formato — um ponteiro para a informação e os ponteiros de encadeamento. No projeto 05_linkedlist-struct, a informação é um aluno, representado pelo TAD Student (nome e CPF): 

// Define a structure for a node in the linked list.
struct list_node
{
    Student *info;  // Data associated with the node (in this case, a Student structure).
    ListNode *next; // A pointer to the next node in the linked list.
    ListNode *prev; // A pointer to the previous node in the linked list.
};

Isso tem duas consequências práticas. Inserir um elemento passa a envolver duas alocações: a do aluno (st_create) e a do nó. E liberar a lista passa a exigir, para cada nó, liberar também a informação para a qual ele aponta (free(p->info)) antes de liberar o próprio nó — senão a memória dos alunos vaza. Note também que a lista usa o TAD Student só pela interface (st_create, st_print): ela não conhece os campos do aluno.

Listas heterogêneas

Guardar a informação por ponteiro abre caminho para listas heterogêneas, em que cada nó pode guardar um tipo diferente de informação — no projeto 06_linkedlist-generic, alunos (Student) e professores (Professor) na mesma lista. O ponteiro para a informação precisa ser genérico, void *, porque não se sabe de antemão para que tipo ele vai apontar. Só que, de posse de um void *, não é possível acessar a memória apontada: o compilador não sabe que tipo há lá. Por isso, cada nó guarda também um identificador de tipo, aqui uma enumeração NodeType: 

struct list_node
{
    NodeType type;
    void *info;     // Data associated with the node (generic pointer).
    ListNode *prev; // A pointer to the previous node in the linked list.
    ListNode *next; // A pointer to the next node in the linked list.
};

A rigor, a lista continua homogênea — todos os nós têm os mesmos campos; o que varia é o tipo do objeto apontado por info. As operações consultam type para decidir como tratar cada nó: em ll_print, um nó TYPE_STUDENT é impresso com st_print e um TYPE_PROFESSOR, com pr_print. Em C, o void * é convertido implicitamente para o ponteiro do tipo esperado pela função chamada — e é exatamente por isso que o identificador de tipo precisa estar certo: se ele mentir, o compilador não tem como perceber.

O mesmo vale para liberar a memória: uma ll_free heterogênea precisaria liberar cada objeto de acordo com o seu tipo. Neste projeto, ll_free é um dos protótipos deixados como exercício — e, por isso, o programa de teste termina sem liberar a lista, os nós, os alunos e os professores (o exemplo abaixo mostra o que isso significa em bytes).

#include "linkedlist.h" // Include the user-defined header file for the list data structure.
#include <stdio.h>

int main(void)
{
    LinkedList *l; // Declare a pointer to a linked list.

    // Create a list with 10 elements
    printf("Create a list with 10 elements\n");
    l = ll_create(); // Create an empty linked list and assign its pointer to 'l'.
    for (int i = 0; i < 10; i++)
        ll_insert(l, i); // Insert elements into the list using ll_insert.
    ll_print(l);         // Show the elements of the list using ll_print.
    printf("------------\n\n");

    // Remove zero
    printf("Removing the first zero\n");
    ll_remove(l, 0);                                            // Remove the first occurrence of zero from the list using ll_remove.
    ll_print(l);                                                // Show the elements of the updated list using ll_print.
    printf("There are %d elements in the list.\n", ll_size(l)); // Print the number of elements in the list using ll_size.
    printf("------------\n\n");

    // Add and remove 1's
    printf("Adding ones and removing ones\n");
    for (int i = 0; i < 5; i++)
        ll_insert(l, 1); // Insert five occurrences of '1' into the list using ll_insert.
    ll_print(l);         // Show the elements of the updated list using ll_print.
    ll_remove_all(l, 1); // Remove all occurrences of '1' from the list using ll_remove_all.
    ll_print(l);         // Show the elements of the updated list using ll_print.
    printf("------------\n\n");

    // Checking whether 4 and 10 are in the list
    printf("Checking whether 4 and 10 are in the list\n");
    int values[5] = {-1, 0, 4, 5, 10}; // Array of values to check in the list.
    for (int i = 0; i < 5; i++)
        if (ll_is_in(l, values[i]))                    // Check if each value is in the list using ll_is_in.
            printf("%d is in the list.\n", values[i]); // Print if the value is in the list.
        else
            printf("%d is NOT in the list.\n", values[i]); // Print if the value is not in the list.

    printf("------------\n\n");

    // Keep a second list in ascending order
    printf("Inserting 7 3 9 1 5 in sorted order\n");
    LinkedList *sorted = ll_create();
    int unordered[5] = {7, 3, 9, 1, 5};
    for (int i = 0; i < 5; i++)
    {
        ll_insert_sorted(sorted, unordered[i]); // Each value goes straight to its place.
        ll_print(sorted);
    }

    // Free the memory used by the lists
    ll_free(l); // Free the memory allocated for the list and its nodes using ll_free.
    ll_free(sorted);

    return 0; // Return 0 to indicate successful program execution.
}

Como funciona o projeto

linkedlist.h declara os tipos opacos LinkedList e ListNode e as operações ll_*. Em linkedlist.c, a lista guarda só first, e cada nó guarda info e next. ll_insert insere no início, em tempo constante; por isso, inserir 0, 1, …, 9 produz a lista em ordem inversa.

ll_remove percorre a lista guardando o nó anterior (prev), refaz o encadeamento (atualizando first se o nó removido for o primeiro) e libera o nó; devolve 1 se encontrou o valor e 0 caso contrário. ll_remove_all repete ll_remove enquanto ela tiver sucesso. ll_insert_sorted procura o primeiro nó cujo valor não é menor que o novo, e insere o novo nó logo depois de prev — ou no início, se prev continuar NULL.

Protótipos sem implementação: o cabeçalho real também declara ll_append, ll_is_sorted, ll_reversed e ll_concatenate, que não têm corpo em linkedlist.c — ficam como exercício. O programa de teste não os chama, e por isso compila e liga sem erro.

void ll_insert_sorted(LinkedList *l, int v)
{
    ListNode *prev = NULL;  // Node that will precede the new one.
    ListNode *p = l->first; // Node used to walk the list.

    // Find the insertion point: first node whose value is not smaller than v.
    while (p != NULL && p->info < v)
    {
        prev = p;
        p = p->next;
    }

    ListNode *node = (ListNode *)malloc(sizeof(ListNode)); // Allocate memory for a new node.
    node->info = v;

    if (prev == NULL) // Insert at the beginning (empty list or v is the smallest).
    {
        node->next = l->first;
        l->first = node;
    }
    else // Insert in the middle or at the end, right after 'prev'.
    {
        node->next = prev->next;
        prev->next = node;
    }
}

    while (p != NULL)
    {
        // Check if the current node contains the element to be removed
        if (p->info == v)
        {
            // If the element to be removed is at the beginning of the list
            if (prev == NULL)
                l->first = p->next; // Update the 'first' pointer to skip the first node

        else
        {
            prev = p;    // Update the 'prev' pointer
            p = p->next; // Move to the next node
        }
    }

Como funciona o projeto

As estruturas são as mesmas do exemplo anterior, mas quase todas as operações são recursivas. Cada função pública (ll_size, ll_sum, ll_remove, ll_free, ll_print, ll_print_reversed, ll_equals) só repassa l->first para uma auxiliar static (_ll_size, _ll_sum, …) que trabalha sobre o encadeamento de nós: trata o caso base (p == NULL), o primeiro nó, e delega o subencadeamento p->next a si mesma.

#include "linkedlist.h"
#include <stdio.h>
#include <stdlib.h>

// Define a structure for the circular list.
struct list
{
    ListNode *first; // Any node of the cycle; NULL when the list is empty.
};

// Define a structure for a node in the list.
struct list_node
{
    int info;       // An integer value stored in the node.
    ListNode *next; // The next node; the last node points back to the first.
};

// Function to create an empty circular list and return a pointer to it.
LinkedList *ll_create()
{
    LinkedList *l = (LinkedList *)malloc(sizeof(LinkedList));
    l->first = NULL;
    return l;
}

// Function to check whether the list is empty.
int ll_is_empty(LinkedList *l)
{
    return l->first == NULL;
}

// Function to insert an element at the beginning of the list.
void ll_insert(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;

    if (l->first == NULL) // The only node points to itself.
    {
        node->next = node;
    }
    else
    {
        // Find the last node (the one whose next is the first) to close the cycle.
        ListNode *last = l->first;
        while (last->next != l->first)
            last = last->next;

        node->next = l->first;
        last->next = node;
    }
    l->first = node;
}

// Function to get the number of elements in the list.
int ll_size(LinkedList *l)
{
    int cnt = 0;
    ListNode *p = l->first;
    if (p != NULL)
        do
        {
            cnt++;
            p = p->next;
        } while (p != l->first); // Stop when we are back at the start.
    return cnt;
}

// Function to move the start of the list one node forward.
void ll_rotate(LinkedList *l)
{
    if (l->first != NULL)
        l->first = l->first->next;
}

// Function to free the memory used by the list.
void ll_free(LinkedList *l)
{
    if (l->first != NULL)
    {
        // Break the cycle, so the list ends in NULL like a regular one.
        ListNode *p = l->first->next;
        l->first->next = NULL;
        while (p != NULL)
        {
            ListNode *t = p->next; // Store a reference to the next node.
            free(p);
            p = t;
        }
    }
    free(l);
}

// Remove the first occurrence of a specific value from the linked list.
void ll_remove(LinkedList *l, int v)
{
    ListNode *p = _search(l, v);

    if (p == NULL)
        return; // If the node is not found, do nothing.

    if (p == l->first)
        l->first = p->next; // If it's the first element, update the 'first'.
    else
        p->prev->next = p->next; // Update the 'next' field of the previous element.

    if (p == l->last)
        l->last = p->prev; // If it's the last element, update the 'last'.
    else
        p->next->prev = p->prev; // Update the 'prev' field of the next element.

    free(p);    // Free the memory used by the removed node.
    l->count--; // Decrement the count.
}

Pergunta de checagem

Quando o programa remove o 0 — que é o último nó —, ll_remove não executa p->next->prev = p->prev. O que aconteceria se essa linha fosse executada mesmo assim, sem o teste if (p == l->last)?

  • AAcesso inválido: p->next vale NULL para o último nó, e NULL->prev não pode ser lido nem escrito; além disso, last continuaria apontando para o nó liberado.
  • BNada de diferente: como o último nó não tem seguinte, a atribuição seria simplesmente ignorada.
  • CO prev do primeiro nó passaria a apontar para o penúltimo, tornando a lista circular.
  • Dcount deixaria de ser decrementado, mas a lista continuaria correta.

Certo! As extremidades são as condições de contorno: no último nó, p->next é NULL, e desreferenciá-lo é comportamento indefinido (tipicamente, o programa é encerrado com falha de segmentação). Por isso, nesse caso, o código atualiza l->last = p->prev em vez de mexer no seguinte.

Não é isso. Para o último nó, p->next vale NULL; escrever em p->next->prev é desreferenciar NULL, comportamento indefinido. O teste if (p == l->last) desvia esse caso para l->last = p->prev.

// Define a structure for the linked list.
struct list
{
    int count;       // Number of elements in the linked list.
    ListNode *first; // A pointer to the first node in the linked list.
    ListNode *last;  // A pointer to the last node in the linked list.
};

// Define a structure for a node in the linked list.
struct list_node
{
    NodeType type;
    void *info;     // Data associated with the node (generic pointer).
    ListNode *prev; // A pointer to the previous node in the linked list.
    ListNode *next; // A pointer to the next node in the linked list.
};

// Create an empty linked list and return a pointer to it.
LinkedList *ll_create()
{
    LinkedList *l = (LinkedList *)malloc(sizeof(LinkedList));
    l->first = NULL;
    l->last = NULL;
    l->count = 0;
    return l;
}

// Get the number of elements in the linked list.
int ll_size(LinkedList *l)
{
    return l->count;
}

// Check whether the linked list is empty.
int ll_is_empty(LinkedList *l)
{
    return ll_size(l) == 0;
}

// Insert an element at the beginning of the linked list.
void ll_insert(LinkedList *l, void *info, NodeType type)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->type = type;
    node->info = info;
    node->next = l->first;
    node->prev = NULL;

    if (!ll_is_empty(l))
        l->first->prev = node;
    else
        l->last = node;

    l->first = node;
    l->count++;
}

// Display all elements of the linked list.
void ll_print(LinkedList *l)
{
    for (ListNode *p = l->first; p != NULL; p = p->next)
    {
        if (p->type == TYPE_STUDENT)
            st_print(p->info); // Print the information of each Student structure.
        else
            pr_print(p->info); // Print the information of each Professor structure.
    }
    printf("\n"); // Print a newline character to separate the output.
}

Pergunta de checagem

Suponha que, por engano, a linha 25 fosse ll_insert(l, p1, TYPE_STUDENT); — o professor Thiago marcado como aluno. O que aconteceria?

  • AO compilador acusaria um erro de tipo, porque p1 é um Professor * e não um Student *.
  • BO programa compilaria normalmente; na impressão, ll_print chamaria st_print sobre a memória de um Professor, interpretando-a com o formato de Student — um erro que o compilador não tem como detectar.
  • Cll_print perceberia a inconsistência e chamaria pr_print mesmo assim, porque o void * guarda o tipo original.
  • Dll_insert recusaria a inserção, porque um professor não pode ser guardado num nó de aluno.

Certo! ll_insert recebe void *, que aceita qualquer ponteiro, e o void * não carrega informação de tipo nenhuma: a única fonte de verdade é o campo type. Se ele estiver errado, st_print lê a memória de um Professor como se fosse um Student; as structs têm campos de tamanhos diferentes, e o resultado é comportamento indefinido.

Não é isso. Qualquer ponteiro de objeto é convertido para void * sem aviso, e o void * não guarda o tipo original — só o campo type do nó diz o que há lá. Com o tipo errado, ll_print chamaria st_print sobre um Professor, sem nenhum erro de compilação: comportamento indefinido.

Este programa não libera a memória que aloca: ll_free é um dos exercícios, e main termina logo depois de imprimir. Executado com valgrind --leak-check=full, ele acusa 432 bytes perdidos — 24 da estrutura da lista (definitely lost) e 408 dos quatro nós, dos dois alunos e dos dois professores alcançáveis a partir dela (indirectly lost). Uma ll_free heterogênea precisaria consultar type para saber como liberar cada objeto. O projeto compila sem nenhum aviso com -Wall.
Para lembrar. Uma lista encadeada aloca um nó por elemento e liga os nós por ponteiros: cresce e diminui sem realocar, mas perde o acesso direto por índice. Inserir no início custa sempre o mesmo; inserir em ordem, buscar e remover exigem percorrer a lista guardando o nó anterior. As variações trocam memória por conveniência — o ponteiro para o anterior e para o último na lista dupla, o ciclo na lista circular — e a informação guardada por ponteiro permite listas de qualquer tipo, inclusive heterogêneas, desde que cada nó saiba o tipo do que guarda.
