Listas encadeadas

Notas da aula sobre listas encadeadas: uma estrutura que aloca memória para cada elemento no momento em que ele é inserido e liga os elementos por ponteiros, em vez de guardá-los lado a lado. Partimos da lista simplesmente encadeada de inteiros e chegamos às variações — com ponteiro para o último, recursiva, circular, duplamente encadeada, de tipos estruturados e heterogênea. Cada operação vem com o código real, o custo e simulações passo a passo nos casos que mais confundem; cada estrutura, com suas vantagens, desvantagens e limitações.

Listas encadeadas

Até aqui, para guardar um conjunto de dados usamos vetores. Um vetor ocupa um espaço contíguo de memória, e é isso que permite o acesso direto a qualquer elemento por v[i]: o endereço do i-ésimo elemento é calculado com uma conta, sem visitar os anteriores. O preço é a rigidez. Um vetor estático precisa ser dimensionado antes de usar; o vetor dinâmico do módulo anterior cresce com realloc, mas cada realocação pode copiar todos os elementos para outro lugar da memória — o gargalo do vetor dinâmico.

A lista encadeada troca essas propriedades de lugar. Cada elemento é alocado sozinho, no momento em que é inserido, e liberado sozinho, quando é removido: a memória ocupada acompanha exatamente o número de elementos, e nenhuma inserção obriga a mover os demais. Como os elementos não ficam lado a lado, cada um precisa guardar onde está o próximo — e perde-se o acesso direto: para chegar ao i-ésimo, é preciso passar pelos anteriores. Quase tudo neste módulo é consequência dessa troca, e a seção Comparando as estruturas, no fim, reúne os custos lado a lado.

Como ler os custos. Dizemos que uma operação custa O(1) (constante) quando o trabalho não depende do tamanho n da lista, e O(n) (linear) quando, no pior caso, ela visita os n nós. Inserir no início de uma lista é O(1); procurar um valor é O(n).

Listas simplesmente encadeadas

Nós e a estrutura da lista

Uma lista encadeada é uma sequência de nós. Cada nó guarda a informação (info) e um ponteiro para o próximo nó (next); o último guarda NULL como próximo, marcando o fim. A lista em si só precisa conhecer o primeiro nó: a partir dele, segue-se next até chegar a NULL. Em C, isso são duas estruturas — o nó e a lista —, escondidas atrás de um TAD: o linkedlist.h só declara os tipos LinkedList e ListNode, e quem usa a lista nunca mexe em first ou next diretamente.

01_linkedlist/linkedlist.c

struct list
{
    ListNode *first; // NULL when the list is empty.
};

struct list_node
{
    int info;
    ListNode *next; // NULL in the last node.
};

Repare que ListNode é autorreferente: o nó contém um ponteiro para outro nó do mesmo tipo. Por isso o typedef vem antes, no .h, e a estrutura pode usar o nome ListNode dentro dela mesma.

Criar a lista é alocar a estrutura e fazer first = NULL: a lista vazia é a que não tem primeiro nó. Por isso testar se a lista está vazia também é uma comparação só. As duas operações são O(1).

01_linkedlist/linkedlist.c

LinkedList *ll_create()
{
    LinkedList *l = (LinkedList *)malloc(sizeof(LinkedList));
    l->first = NULL;
    return l;
}

int ll_is_empty(LinkedList *l)
{
    return l->first == NULL;
}

Adaptado de: Celes, W. Estrutura de Dados.

Por que malloc e não uma variável local? Se ll_create declarasse LinkedList l; e devolvesse &l, devolveria o endereço de uma variável que deixa de existir quando a função termina: quem chamou ficaria com um ponteiro pendente. Uma estrutura que precisa viver além da função que a criou tem de ser alocada dinamicamente.

Inserir no início

A inserção mais simples coloca o novo elemento no início. A função aloca um nó, guarda nele a informação, faz o nó novo apontar para o que era o primeiro e, por fim, faz first apontar para o nó novo. A ordem importa: se first fosse atualizado antes, o endereço do antigo primeiro se perderia. Nenhum nó existente é visitado, então o custo é O(1), qualquer que seja o tamanho da lista — e a lista vazia não é caso especial, porque o nó novo simplesmente aponta para o NULL que estava em first.

01_linkedlist/linkedlist.c

void ll_insert(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = l->first;
    l->first = node;
}

Adaptado de: Celes, W. Estrutura de Dados.

As simulações abaixo mostram a mesma função em três situações. Compare a lista vazia com o caso geral: as quatro linhas são as mesmas.

Uma consequência que costuma surpreender: inserir 1, 2 e 3, nessa ordem, produz a lista 3 2 1. Cada valor passa à frente dos anteriores.

Percorrer: imprimir e buscar

Percorrer a lista é o padrão mais usado do módulo: um ponteiro p começa em first e avança com p = p->next até virar NULL. Ele faz o papel do índice do vetor. Imprimir visita todos os nós (O(n)). Buscar pode parar antes, mas no pior caso (valor ausente ou no fim) também visita todos.

A busca fica numa auxiliar static, _search, que devolve o nó com o valor procurado, ou NULL se ele não está na lista. Por ser static, ela só existe dentro do linkedlist.c: quem usa a lista não a vê, mas as operações do TAD podem se apoiar nela.

01_linkedlist/linkedlist.c

// Returns the first node of l whose value is v, or NULL if there is none.
// Cost: O(n).
static ListNode *_search(LinkedList *l, int v)
{
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
        p = p->next;
    return p;
}

void ll_print(LinkedList *l)
{
    for (ListNode *p = l->first; p != NULL; p = p->next)
        printf("%d ", p->info);
    printf("\n");
}

Adaptado de: Celes, W. Estrutura de Dados.

Na lista vazia, p já começa NULL e o laço não executa nenhuma vez: a busca devolve NULL. Escrever o laço com a condição p != NULL antes de usar p é o que torna a lista vazia um caso que não precisa de tratamento à parte.

Exercício de aula. O linkedlist.h declara int ll_is_in(LinkedList *l, int v), que devolve 1 se v está na lista e 0 se não está. Como implementá-la a partir de _search?

Retirar um elemento

Retirar um elemento tem duas partes. A primeira é a busca: um laço avança p até o nó com o valor, guardando em prev o nó anterior, porque é o next dele que vai mudar. A segunda é o ajuste, a partir do resultado da busca: se p ficou NULL, o valor não está na lista e nada muda; senão, refaz-se o encadeamento para pular o nó e só então ele é liberado.

O ajuste tem dois casos. Se o nó é o primeiro (prev é NULL), quem muda é first; senão, quem muda é o next do anterior. Retirar o último não é caso especial: o anterior passa a apontar para o NULL que o último guardava. A função devolve 1 se achou o valor e 0 se não achou; o custo é O(n), pela busca.

01_linkedlist/linkedlist.c

int ll_remove(LinkedList *l, int v)
{
    // 1. Search: walk until p holds v, keeping in prev the node before it.
    ListNode *prev = NULL;
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
    {
        prev = p;
        p = p->next;
    }

    if (p == NULL) // v is not in the list.
        return 0;

    // 2. Unlink p and free it.
    if (prev == NULL)
        l->first = p->next; // p is the first node: the list now starts at the next one.
    else
        prev->next = p->next;
    free(p);
    return 1;
}

Adaptado de: Celes, W. Estrutura de Dados.

Os seis cenários abaixo são os que mais aparecem em erros: lista vazia, nó único, primeiro, meio, último e valor ausente. Repare que o único que mexe em first é o do primeiro nó, inclusive quando ele é o único.

Liberar a lista

Liberar a lista é liberar cada nó e, por fim, a estrutura. O cuidado é guardar o próximo antes do free: depois de liberado, o nó não pode mais ser lido, e p->next seria um acesso a memória que já não é do programa (o compilador não acusa; o erro aparece, quando aparece, na execução).

01_linkedlist/linkedlist.c

void ll_free(LinkedList *l)
{
    ListNode *p = l->first;
    while (p != NULL)
    {
        ListNode *t = p->next; // Saved before free(p): p->next cannot be read afterwards.
        free(p);
        p = t;
    }
    free(l);
}

Adaptado de: Celes, W. Estrutura de Dados.

Resumo: lista simplesmente encadeada

Vantagens
  • Cresce e diminui um nó por vez: ao contrário do vetor dinâmico, nunca realoca nem copia os demais.
  • Inserir e retirar no início custam O(1); no vetor dinâmico, inserir no início desloca todos, O(n).
  • Memória proporcional ao número de elementos, sem a capacidade ociosa que o vetor dinâmico reserva ao dobrar.
Desvantagens
  • Sem acesso direto: chegar ao i-ésimo elemento custa O(i), contra O(1) no vetor dinâmico.
  • Sem ponteiro para o último, anexar no fim custa O(n).
  • Só anda num sentido: o anterior de um nó tem de ser guardado durante o percurso.
  • Cada elemento gasta memória extra com o ponteiro next (8 bytes numa máquina de 64 bits), além do custo de uma alocação por nó.
Limitações impostas por C
  • Não há coleta de lixo: cada nó alocado precisa de um free, na ordem certa (guardar o próximo antes).
  • Um ponteiro para um nó já liberado (ponteiro pendente) continua compilando e "funcionando" às vezes — o erro só aparece na execução, e de forma imprevisível.
  • A lista é só de int: para outro tipo, o código tem de ser reescrito (ou recorrer a void *, como na lista heterogênea).

Lista com ponteiro para o último

Na lista simples, anexar no fim exige percorrer a lista até achar o último nó: O(n). Guardar, além de first, um ponteiro last para o último nó torna essa operação O(1). O nó é o mesmo da lista simples; só a estrutura da lista ganha um campo. Em troca, toda operação que pode mudar o último nó precisa manter last correto.

08_linkedlist-last/linkedlist.c

// The list keeps both ends: 'first' to start walking, 'last' to append without walking.
struct list
{
    ListNode *first; // NULL if the list is empty.
    ListNode *last;  // NULL if the list is empty.
};

struct list_node
{
    int info;
    ListNode *next;
};

Anexar não percorre nada: o nó novo é ligado depois de last. A lista vazia é o caso que exige atenção: sem último nó, o novo vira o primeiro e o último.

08_linkedlist-last/linkedlist.c

void ll_append(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = NULL;
    if (l->last == NULL) // Empty list: the new node is first AND last.
        l->first = node;
    else
        l->last->next = node; // Link after the current last node.
    l->last = node;
}

Retirar é a mesma função da lista simples com um cuidado a mais: se o nó retirado é o último, last recua para o anterior — que é NULL se a lista ficou vazia. Esquecer essa linha deixa last apontando para um nó liberado, e o próximo ll_append escreve em memória que já não pertence à lista.

08_linkedlist-last/linkedlist.c

int ll_remove(LinkedList *l, int v)
{
    // Same walk as in 01_linkedlist, plus one extra care: removing the last node moves 'last'.
    ListNode *prev = NULL;
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
    {
        prev = p;
        p = p->next;
    }
    if (p == NULL) // Not found.
        return 0;

    if (prev == NULL)
        l->first = p->next; // Removing the first node.
    else
        prev->next = p->next;

    if (p == l->last)
        l->last = prev; // The node before it becomes the last (NULL if the list emptied).

    free(p);
    return 1;
}

Resumo: lista com ponteiro para o último

Vantagens
  • Anexar no fim em O(1) em todo caso; no vetor dinâmico, é O(1) só em média, com cópia de tudo a cada realocação.
  • Base natural para uma fila (entra no fim, sai do início), que veremos adiante.
Desvantagens
  • Retirar o último continua O(n): é preciso achar o penúltimo, e só se anda para frente.
  • Toda operação nova que mexe nas pontas também precisa manter last correto: estender o TAD pede esse cuidado a mais.
Limitações impostas por C
  • Nada impede que last fique desatualizado: a consistência entre first, last e os nós é responsabilidade do programador do TAD.

Implementações recursivas

Uma lista encadeada tem uma definição recursiva natural: um encadeamento ou é vazio (NULL), ou é um nó seguido de outro encadeamento — o subencadeamento que começa em p->next. Quase toda operação pode seguir essa definição: resolve-se o caso vazio diretamente (o caso base) e, no caso não vazio, trata-se o nó atual e delega-se o resto à própria função.

Como a lista é um TAD, a recursão não acontece sobre LinkedList, mas sobre ListNode *. Cada operação pública chama uma função auxiliar static (visível só dentro de linkedlist.c) que recebe o primeiro nó. Imprimir segue a definição ao pé da letra: no vazio não há nada a fazer; senão, imprime-se o nó e delega-se o resto.

02_linkedlist-recursive/linkedlist.c

// Prints the chain starting at p, in order.
static void _ll_print(ListNode *p)
{
   if (p != NULL)
   {
      printf("%d ", p->info);
      _ll_print(p->next);
   }
}

void ll_print(LinkedList *l)
{
   _ll_print(l->first);
   printf("\n");
}

Adaptado de: Celes, W. Estrutura de Dados.

Nas operações que mudam o encadeamento, a auxiliar devolve o novo início do subencadeamento, e quem chama grava esse retorno: p->next = _ll_remove(p->next, val), e, em cima de tudo, l->first = _ll_remove(l->first, val). Assim, retirar o primeiro nó deixa de ser caso especial: a chamada mais externa simplesmente devolve o segundo nó, e é ele que vira first.

02_linkedlist-recursive/linkedlist.c

// Returns the chain starting at p without the first node whose value is val.
static ListNode *_ll_remove(ListNode *p, int val)
{
   ListNode *aux;
   if (p != NULL)
   {
      if (p->info == val) // Found: the chain now starts at the next node.
      {
         aux = p;
         p = p->next;
         free(aux);
      }
      else // Not here: remove from the subchain and relink.
         p->next = _ll_remove(p->next, val);
   }
   return p;
}

void ll_remove(LinkedList *l, int val)
{
   l->first = _ll_remove(l->first, val);
}

Adaptado de: Celes, W. Estrutura de Dados.

Às vezes a versão recursiva é bem mais simples que a iterativa. Imprimir de trás para frente é chamar a função para o resto antes de imprimir o nó atual: a impressão acontece na volta da recursão. Liberar segue a mesma ordem: primeiro o resto, depois o nó.

02_linkedlist-recursive/linkedlist.c

// Frees the chain starting at p, from the last node back to p.
static void _ll_free(ListNode *p)
{
   if (p != NULL)
   {
      _ll_free(p->next);
      free(p);
   }
}

// Prints the chain starting at p, from the last node to p.
static void _ll_print_reversed(ListNode *p)
{
   if (p != NULL)
   {
      _ll_print_reversed(p->next); // First print the rest of the list...
      printf("%d ", p->info);      // ...and only then this node.
   }
}

Adaptado de: Celes, W. Estrutura de Dados.

Resumo: implementações recursivas

Vantagens
  • O código segue a definição da estrutura: caso base e passo ficam explícitos.
  • Operações "de trás para frente" (imprimir ao contrário, decidir depois de ver o resto) ficam simples.
  • Devolver o novo início elimina o caso especial do primeiro nó.
Desvantagens
  • Cada chamada ocupa um quadro na pilha: uma operação sobre n nós chega a n chamadas simultâneas — memória O(n), contra O(1) da versão iterativa.
  • Chamadas de função custam mais que um passo de laço; percorrer um vetor dinâmico com índice é mais barato que as duas versões da lista.
Limitações impostas por C
  • A pilha tem tamanho limitado (alguns megabytes): uma lista com centenas de milhares de nós pode estourá-la, e o programa termina com falha de segmentação.
  • O compilador pode, mas não é obrigado a, transformar recursão de cauda em laço; não dá para contar com isso.

Listas circulares

Em algumas aplicações, os elementos formam um ciclo: depois do último vem de novo o primeiro, como jogadores numa mesa ou processos que se revezam no processador. Numa lista circular, o next do último nó, em vez de NULL, aponta para o primeiro. Não há mais fim: a estrutura só precisa de um ponteiro para algum nó, que serve de ponto de partida.

Sem NULL, o critério de parada muda: percorre-se até voltar ao ponto de partida. Como o primeiro nó é também o critério de parada, o laço precisa executar o corpo antes de testar — o do … while. Com um while comum, a condição p != l->first seria falsa logo de saída. A lista vazia (first == NULL) é testada antes.

03_circular-linkedlist/linkedlist.c

void ll_print(LinkedList *l)
{
    ListNode *p = l->first;
    if (p != NULL)
        do
        {
            printf("%d ", p->info);
            p = p->next;
        } while (p != l->first);
    printf("\n");
}

Adaptado de: Celes, W. Estrutura de Dados.

Inserir no início exige fechar o ciclo: o último nó precisa passar a apontar para o nó novo, e só se acha o último percorrendo a lista — O(n). Na lista vazia, o único nó aponta para si mesmo.

03_circular-linkedlist/linkedlist.c

void ll_insert(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;

    if (l->first == NULL) // The only node points to itself.
    {
        node->next = node;
    }
    else
    {
        // Find the last node (the one whose next is the first) to close the cycle.
        ListNode *last = l->first;
        while (last->next != l->first)
            last = last->next;

        node->next = l->first;
        last->next = node;
    }
    l->first = node;
}

Para liberar, quebra-se o ciclo (o nó de partida passa a apontar para NULL) e libera-se como numa lista comum. Sem isso, o laço de liberação nunca encontraria o fim.

03_circular-linkedlist/linkedlist.c

void ll_free(LinkedList *l)
{
    if (l->first != NULL)
    {
        // Break the cycle, so the list ends in NULL like a regular one.
        ListNode *p = l->first->next;
        l->first->next = NULL;
        while (p != NULL)
        {
            ListNode *t = p->next; // Saved before free(p): p->next cannot be read afterwards.
            free(p);
            p = t;
        }
    }
    free(l);
}

Resumo: lista circular

Vantagens
  • Qualquer nó serve de ponto de partida: seguindo next, alcançam-se todos os outros.
  • Modela naturalmente revezamento e rodízio; num vetor dinâmico, dar a volta exige calcular o índice com %.
Desvantagens
  • Inserir no início custa O(n), para fechar o ciclo (guardar um ponteiro para o último resolveria).
  • Todo laço precisa de outro critério de parada; esquecer o ponto de partida gera laço infinito.
Limitações impostas por C
  • Nada na linguagem distingue uma lista circular de uma comum: o mesmo tipo ListNode serve às duas, e uma função da lista comum aplicada a uma circular nunca encontra NULL.

Listas duplamente encadeadas

Na lista simples, cada nó só conhece o próximo: não dá para andar para trás, e retirar um nó exige ter guardado o anterior durante a busca. A lista duplamente encadeada resolve isso com um ponteiro a mais por nó, prev, para o anterior. A estrutura da lista guarda o primeiro e o último nós e, aqui, também o número de elementos (count), o que permite saber o tamanho em O(1), sem percorrer.

04_doubly-linkedlist/linkedlist.c

struct list
{
    int count;
    ListNode *first;
    ListNode *last;
};

struct list_node
{
    int info;
    ListNode *next;
    ListNode *prev;
};

Toda operação que liga um nó agora acerta dois sentidos. Inserir no início faz o nó novo apontar para o antigo primeiro e, se a lista não estava vazia, faz o antigo primeiro ganhar o nó novo como prev; se estava vazia, o nó novo é também o último. Anexar no fim é o simétrico, usando last — O(1).

04_doubly-linkedlist/linkedlist.c

void ll_insert(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = l->first;
    node->prev = NULL;

    if (!ll_is_empty(l))
        l->first->prev = node;
    else
        l->last = node; // If the list was empty, the new node is also the last node.

    l->first = node;
    l->count++;
}

void ll_append(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = NULL;    // The new node is the last one...
    node->prev = l->last; // ...and comes after the current last (NULL if the list is empty).

    if (l->last != NULL)
        l->last->next = node; // Link the old last node to the new one.
    else
        l->first = node; // Empty list: the new node is also the first one.

    l->last = node;
    l->count++;
}

Adaptado de: Celes, W. Estrutura de Dados.

Retirar fica mais simples de raciocinar: achado o nó p, ele mesmo sabe quem são seus vizinhos. O anterior pula p no sentido next (ou first muda, se p é o primeiro); o seguinte pula p no sentido prev (ou last muda, se p é o último). São quatro casos combinando "é o primeiro?" e "é o último?" — o nó único é os dois ao mesmo tempo.

// Returns the first node whose value is v (NULL if there is none).
static ListNode *_search(LinkedList *l, int v)
{
    ListNode *p = l->first;

    while ((p != NULL) && (p->info != v))
        p = p->next;

    return p;
}

void ll_remove(LinkedList *l, int v)
{
    ListNode *p = _search(l, v);

    if (p == NULL)
        return;

    if (p == l->first)
        l->first = p->next;
    else
        p->prev->next = p->next;

    if (p == l->last)
        l->last = p->prev;
    else
        p->next->prev = p->prev;

    free(p);
    l->count--;
}

Resumo: lista duplamente encadeada

Vantagens
  • Anda nos dois sentidos; o anterior de um nó está no próprio nó.
  • Inserir e anexar nas duas pontas em O(1) (no vetor dinâmico, inserir no início é O(n)); retirar um nó já encontrado em O(1).
  • Com count, o tamanho fica guardado na estrutura, sem percorrer a lista.
Desvantagens
  • Mais memória por elemento: dois ponteiros (16 bytes em 64 bits) em vez de um.
  • Toda operação acerta dois sentidos e mais campos da estrutura: mais pontos para errar.
  • Buscar continua O(n), e não há acesso direto.
Limitações impostas por C
  • A coerência entre next e prev não é verificada por ninguém: um prev esquecido passa despercebido até alguém percorrer a lista de trás para frente.

Listas de tipos estruturados

A informação de um nó pode ser qualquer coisa — por exemplo, um aluno, com nome e CPF. Em vez de copiar o registro inteiro para dentro do nó, o nó guarda um ponteiro para ele (Student *info). Assim o nó tem sempre o mesmo tamanho, qualquer que seja o registro, e o registro pode ser criado e manipulado pelo seu próprio TAD (student.h). Como Student também é opaco, a lista lê os campos por funções de acesso, st_name e st_cpf.

Listas heterogêneas

Que problema elas resolvem?

Todas as listas até aqui guardam um único tipo, fixado no código: int, ou Student *. Se o programa precisa de uma lista de alunos e de uma lista de professores, são dois TADs quase idênticos. E se a mesma coleção precisa conter alunos e professores — as pessoas de uma turma, por exemplo —, nenhuma das listas anteriores serve. A lista heterogênea resolve as duas coisas: uma única implementação de lista, cujos nós podem apontar para dados de tipos diferentes.

Relembrando: o ponteiro genérico void *

Antes da implementação, vale relembrar o recurso em que ela se apoia. Um void * guarda o endereço de qualquer coisa: o mesmo p recebe o endereço de um int, depois o de um double, depois o de uma struct, sem nenhuma conversão. O ponteiro guarda o endereço, mas não diz o que está do outro lado. Por isso, para usar o dado, é preciso dizer o tipo antes, com um cast: *(int *)p, *(double *)p, ((Point *)p)->y. 

#include <stdio.h>

typedef struct
{
    double x, y;
} Point;

int main(void)
{
    int x = 10;
    double y = 3.5;
    Point pt = {1.0, 2.0};

    void *p = &x;              // Any address fits in a void *.
    printf("%d\n", *(int *)p); // To read it, say the type first.

    p = &y; // The same pointer, now holding the address of a double.
    printf("%.1f\n", *(double *)p);

    p = &pt;                        // And now a struct.
    Point *q = (Point *)p;          // C accepts it without the cast; the course writes it.
    printf("(%.1f, %.1f)\n", q->x, ((Point *)p)->y);
    return 0;
}

Sem o cast, o compilador não sabe o tamanho nem o formato do dado, e recusa o acesso: desreferenciar um void * ou pedir um campo através dele são erros de compilação. 

int x = 10;
void *p = &x;
printf("%d\n", *p);   // error: invalid use of void expression

Point pt = {1.0, 2.0};
p = &pt;
printf("%.1f\n", p->x); // error: request for member 'x' in something not a structure or union

Em C, a conversão de void * para outro ponteiro também é aceita sem cast (Point *q = p; compila). Neste curso, escrevemos o cast sempre, por convenção: ele deixa visível o ponto exato em que a verificação de tipos passa a depender do programador. E ela depende mesmo: um cast errado compila sem nenhum aviso, mesmo com -Wall -Wextra, e o programa lê o dado com o formato errado — abaixo, um double que vale 3.5 lido como int imprime 0. 

#include <stdio.h>

int main(void)
{
    double y = 3.5;
    void *p = &y;
    printf("%d\n", *(int *)p); // Compiles without any warning; reads the double as an int.
    return 0;
}

A solução em C: void * e um identificador de tipo

C não tem tipos genéricos. O recurso disponível é o void *, um ponteiro que pode guardar o endereço de qualquer coisa. Mas, sozinho, um void * não diz o que está do outro lado — e não dá para usar o dado sem saber o tipo. Por isso cada nó guarda, junto do ponteiro, um identificador de tipo (NodeType), e toda operação que precisa ler o dado consulta esse identificador.

06_linkedlist-generic/linkedlist.c

struct list
{
    int count;
    ListNode *first;
    ListNode *last;
};

struct list_node
{
    NodeType type; // Says how to read info.
    void *info;    // The record: a Student * or a Professor *.
    ListNode *prev;
    ListNode *next;
};

Tudo o que depende do tipo fica em três auxiliares, e só nelas: _print imprime o registro, _cpf lê o CPF e _free_record libera o registro, cada uma com um teste sobre o tipo que decide se o void * é convertido em Student * ou em Professor *. A liberação passa pela função do próprio TAD (st_free, pr_free): a lista nunca presume como um registro é feito por dentro.

06_linkedlist-generic/linkedlist.c

// Prints the record of p according to its type.
static void _print(ListNode *p)
{
    if (p->type == TYPE_STUDENT)
        st_print((Student *)p->info);
    else
        pr_print((Professor *)p->info);
}

// Returns the CPF of the record of p: the type decides how to read the void *.
static const char *_cpf(ListNode *p)
{
    if (p->type == TYPE_STUDENT)
        return st_cpf((Student *)p->info);
    return pr_cpf((Professor *)p->info);
}

// Frees the record of p with the function of its own TAD.
static void _free_record(ListNode *p)
{
    if (p->type == TYPE_STUDENT)
        st_free((Student *)p->info);
    else
        pr_free((Professor *)p->info);
}

As operações da lista só chamam as auxiliares: imprimir é chamar _print em cada nó, e buscar por CPF é comparar o que _cpf devolve.

Quem libera o quê

Os registros são criados fora da lista (em main) e entregues a ela por ll_insert. A decisão deste TAD é que, ao recebê-los, a lista passa a ser dona deles: ll_remove e ll_free liberam também os registros, cada um pela função de liberação do seu próprio TAD, através de _free_record.

06_linkedlist-generic/linkedlist.c

// Unlinks node p from l and frees it together with the record it points to.
static void _unlink(LinkedList *l, ListNode *p)
{
    if (p == l->first)
        l->first = p->next;
    else
        p->prev->next = p->next;

    if (p == l->last)
        l->last = p->prev;
    else
        p->next->prev = p->prev;

    _free_record(p);
    free(p);
    l->count--;
}

void ll_free(LinkedList *l)
{
    while (l->first != NULL)
        _unlink(l, l->first);
    free(l);
}

Limitações

  • O compilador não confere o tipo. Inserir um professor marcado como aluno compila sem aviso; o erro aparece na execução, quando o registro é lido com o formato errado.
  • Cada tipo novo mexe na lista. Acrescentar, digamos, técnicos administrativos obriga a alterar o NodeType e as três auxiliares que testam o tipo (_print, _cpf, _free_record). Isolar esse conhecimento limita o estrago, mas a lista, que deveria ser genérica, continua conhecendo todos os tipos que guarda.
  • Posse e liberação ficam por conta de convenção. O void * não diz quem liberará o dado, nem como; a convenção tem de ser documentada e respeitada (aqui: a lista é dona dos registros que recebe e os libera).
  • Conversões em todo uso. Todo dado que sai da lista volta como void * e precisa de conversão explícita — e uma conversão errada não é detectada.

Uma alternativa, que veremos com mais calma adiante, é a lista não conhecer os tipos de jeito nenhum: quem cria a lista passa a ela as operações sobre os dados — imprimir, comparar, liberar — como ponteiros para funções. A lista chama essas funções sem saber o que elas fazem, e um tipo novo não exige mudar a lista. É o mesmo recurso do qsort da biblioteca padrão, que ordena qualquer vetor recebendo a função de comparação.

Resumo: lista heterogênea

Vantagens
  • Uma única implementação de lista para vários tipos.
  • Coleções com elementos de tipos diferentes. (Um vetor dinâmico de void * também poderia, mas precisaria do mesmo tipo guardado por elemento.)
Desvantagens
  • Um teste de tipo em toda operação que lê o dado.
  • A lista conhece todos os tipos que guarda e muda a cada tipo novo.
Limitações impostas por C
  • Sem tipos genéricos: void * desliga a verificação de tipos do compilador.
  • Sem coleta de lixo nem noção de posse: a liberação depende de convenção.

Pergunta de checagem

Em ll_remove, por que a busca guarda prev, o nó anterior a p?

  • APara poder liberar o nó anterior junto com p.
  • BPorque é o next do anterior que precisa mudar para pular p, e numa lista simples não há como voltar de p para ele.
  • CPara contar quantos nós a busca visitou.
  • DPorque free(p) exige o endereço do anterior.

Certo! Retirar p é fazer o anterior apontar para p->next. Na lista simples, cada nó só conhece o seguinte: se a busca não guardasse prev, seria preciso percorrer a lista de novo para achá-lo.

Não é isso. O anterior é guardado porque é ele que muda: prev->next passa a ser p->next. Na lista simples não há ponteiro para trás, então o anterior precisa ser lembrado durante a busca.

#include "linkedlist.h"
#include <stdio.h>
#include <stdlib.h>

struct list
{
    ListNode *first; // NULL when the list is empty.
};

struct list_node
{
    int info;
    ListNode *next; // NULL in the last node.
};

LinkedList *ll_create()
{
    LinkedList *l = (LinkedList *)malloc(sizeof(LinkedList));
    l->first = NULL;
    return l;
}

int ll_is_empty(LinkedList *l)
{
    return l->first == NULL;
}

void ll_insert(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = l->first;
    l->first = node;
}

// Returns the first node of l whose value is v, or NULL if there is none.
// Cost: O(n).
static ListNode *_search(LinkedList *l, int v)
{
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
        p = p->next;
    return p;
}

int ll_is_in(LinkedList *l, int v)
{
    return _search(l, v) != NULL;
}

int ll_remove(LinkedList *l, int v)
{
    // 1. Search: walk until p holds v, keeping in prev the node before it.
    ListNode *prev = NULL;
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
    {
        prev = p;
        p = p->next;
    }

    if (p == NULL) // v is not in the list.
        return 0;

    // 2. Unlink p and free it.
    if (prev == NULL)
        l->first = p->next; // p is the first node: the list now starts at the next one.
    else
        prev->next = p->next;
    free(p);
    return 1;
}

void ll_print(LinkedList *l)
{
    for (ListNode *p = l->first; p != NULL; p = p->next)
        printf("%d ", p->info);
    printf("\n");
}

void ll_free(LinkedList *l)
{
    ListNode *p = l->first;
    while (p != NULL)
    {
        ListNode *t = p->next; // Saved before free(p): p->next cannot be read afterwards.
        free(p);
        p = t;
    }
    free(l);
}

}

{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = l->first;
    if (l->first == NULL) // Empty list: the new node is also the last one.
        l->last = node;
    l->first = node;
}

{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = NULL;
    if (l->last == NULL) // Empty list: the new node is first AND last.
        l->first = node;
    else
        l->last->next = node; // Link after the current last node.
    l->last = node;
}

{
    // Same walk as in 01_linkedlist, plus one extra care: removing the last node moves 'last'.
    ListNode *prev = NULL;
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
    {
        prev = p;
        p = p->next;
    }
    if (p == NULL) // Not found.
        return 0;

    if (prev == NULL)
        l->first = p->next; // Removing the first node.
    else
        prev->next = p->next;

    if (p == l->last)
        l->last = prev; // The node before it becomes the last (NULL if the list emptied).

    free(p);
    return 1;
}

        p = t;

    free(l);
}

#include <stdio.h>
#include <stdlib.h>

struct list
{
    ListNode *first; // Any node of the cycle; NULL when the list is empty.
};

struct list_node
{
    int info;
    ListNode *next; // The next node; the last node points back to the first.
};

LinkedList *ll_create()
{
    LinkedList *l = (LinkedList *)malloc(sizeof(LinkedList));
    l->first = NULL;
    return l;
}

int ll_is_empty(LinkedList *l)
{
    return l->first == NULL;
}

void ll_insert(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;

    if (l->first == NULL) // The only node points to itself.
    {
        node->next = node;
    }
    else
    {
        // Find the last node (the one whose next is the first) to close the cycle.
        ListNode *last = l->first;
        while (last->next != l->first)
            last = last->next;

        node->next = l->first;
        last->next = node;
    }
    l->first = node;
}

void ll_free(LinkedList *l)
{
    if (l->first != NULL)
    {
        // Break the cycle, so the list ends in NULL like a regular one.
        ListNode *p = l->first->next;
        l->first->next = NULL;
        while (p != NULL)
        {
            ListNode *t = p->next; // Saved before free(p): p->next cannot be read afterwards.
            free(p);
            p = t;
        }
    }
    free(l);
}

void ll_print(LinkedList *l)
{
    ListNode *p = l->first;
    if (p != NULL)
        do
        {
            printf("%d ", p->info);
            p = p->next;
        } while (p != l->first);
    printf("\n");
}

        l->first = p->next;
    else
        p->prev->next = p->next;

    if (p == l->last)
        l->last = p->prev;
    else
        p->next->prev = p->prev;

    free(p);
    l->count--;
}

{

    node->info = v;
    node->next = NULL;    // The new node is the last one...
    node->prev = l->last; // ...and comes after the current last (NULL if the list is empty).

    if (l->last != NULL)
        l->last->next = node; // Link the old last node to the new one.
    else
        l->first = node; // Empty list: the new node is also the first one.

    l->last = node;
    l->count++;
}

{

    ListNode *t;
    while (p != NULL)
    {

        free(p);
        p = t;
    }
    free(l);
}
