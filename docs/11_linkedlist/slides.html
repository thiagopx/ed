Liberar: guardar o próximo antes do free

Depois de free(p), ler p->next seria acessar memória que não é mais do programa.

t = p->next1º: guarda o próximo
↓
free(p)2º: libera o atual
↓
p = t3º: avança
11_linkedlist/01_linkedlist/linkedlist.c
void ll_free(LinkedList *l)
{
    ListNode *p = l->first;
    while (p != NULL)
    {
        ListNode *t = p->next;
        free(p);
        p = t;
    }
    free(l);
}

Resumo: lista simples

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • Cresce e diminui um nó por vez: ao contrário do vetor dinâmico, nunca realoca nem copia os elementos que já estão lá.
  • Inserir e retirar no início custam O(1); no vetor dinâmico, inserir no início desloca todos os elementos, O(n).
  • Usa memória proporcional ao número de elementos, sem a capacidade ociosa que o vetor dinâmico reserva ao dobrar.

desvantagens

  • Cada elemento gasta um ponteiro next a mais: 8 bytes numa máquina de 64 bits.
  • Cada nó é uma alocação própria: um malloc por inserção, enquanto o vetor dinâmico aloca em blocos.
  • Acessar a posição i custa O(i); no vetor dinâmico, o acesso pelo índice é O(1).
  • Retirar exige guardar o anterior durante a busca, porque o nó não sabe quem vem antes dele.

Resumo: lista simples

Limitações: o que a estrutura não faz bem, e o que a linguagem C não confere por nós.

limitações da estrutura

  • Só se anda num sentido, do primeiro ao último: não há como voltar um nó.
  • Sem ponteiro para o último, anexar no fim percorre a lista inteira: custa O(n).
  • Buscar um valor visita os nós um a um: no pior caso, percorre os n nós.

limitações de C

  • Não há coleta de lixo: cada nó precisa do seu free, guardando antes o próximo.
  • Um ponteiro para um nó já liberado continua compilando; o erro só aparece na execução, de forma imprevisível.
  • ll_create usa malloc: devolver o endereço de uma variável local deixaria um ponteiro pendente.
  • A lista é só de int: outro tipo exige reescrever o código ou recorrer a void *.

void ll_append(LinkedList *l, int v)
{
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    node->next = NULL;
    if (l->last == NULL)
        l->first = node;
    else
        l->last->next = node;
    l->last = node;
}

Retirar o último move last

Esquecer essa linha deixa last apontando para um nó liberado.

p é o último→last = prev

11_linkedlist/08_linkedlist-last/linkedlist.c
int ll_remove(LinkedList *l, int v)
{
    ListNode *prev = NULL;
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
    {
        prev = p;
        p = p->next;
    }
    if (p == NULL)
        return 0;

    if (prev == NULL)
        l->first = p->next;
    else
        prev->next = p->next;

    if (p == l->last)
        l->last = prev;

    free(p);
    return 1;
}

Resumo: lista com last

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • Anexar no fim custa O(1), sem percorrer: o nó novo é ligado depois de last.
  • No vetor dinâmico, anexar é O(1) só em média: a cada realocação, todos os elementos são copiados.
  • É a base natural de uma fila, que entra pelo fim e sai pelo início, como veremos adiante.
  • O nó é o mesmo da lista simples: só a estrutura da lista ganha um campo, last.

desvantagens

  • Toda operação nova que mexe nas pontas também precisa manter last correto: estender o TAD pede esse cuidado a mais.
  • Na lista vazia, inserir ou anexar atualiza first e last ao mesmo tempo.
  • Como na lista simples, acessar a posição i custa O(i), contra O(1) no vetor dinâmico.

Resumo: lista com last

Limitações: o que a estrutura não faz bem, e o que a linguagem C não confere por nós.

limitações da estrutura

  • Retirar o último continua O(n): é preciso achar o penúltimo, e só se anda para frente.
  • Buscar um valor continua O(n), como na lista simples.
  • Como na lista simples, só se anda para frente: não há como voltar ao nó anterior.
  • Inserir mantendo a ordem continua O(n): a posição certa só se acha percorrendo a lista.

limitações de C

  • Nada impede que last fique desatualizado: a coerência entre first, last e os nós é do programador.
  • Se last apontar para um nó já liberado, nada avisa: o próximo ll_append escreve em memória liberada.
  • Sem coleta de lixo, ll_free libera nó a nó, guardando o próximo antes de cada free.

Remover e devolver o novo primeiro

Quem chama reatribui o retorno — é isso que refaz o encadeamento.

p == NULL→nada a remover: devolve p
p->info == val→libera o nó e devolve p->next
senão→p->next = _ll_remove(p->next, val)
11_linkedlist/02_linkedlist-recursive/linkedlist.c
static ListNode *_ll_remove(ListNode *p, int val)
{
   ListNode *aux;
   if (p != NULL)
   {
      if (p->info == val)
      {
         aux = p;
         p = p->next;
         free(aux);
      }
      else
         p->next = _ll_remove(p->next, val);
   }
   return p;
}

void ll_remove(LinkedList *l, int val)
{
   l->first = _ll_remove(l->first, val);
}

Resumo: recursão

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • O código segue a definição da estrutura: o caso base e o passo ficam explícitos na função.
  • Operações de trás para frente, como imprimir ao contrário, ficam simples: basta tratar o resto antes do nó.
  • Devolver o novo início elimina o caso especial do primeiro nó ao remover.

desvantagens

  • Cada chamada ocupa um quadro na pilha: n nós chegam a n chamadas simultâneas, memória O(n).
  • A versão iterativa faz o mesmo com memória O(1), porque reaproveita as mesmas variáveis a cada passo.
  • Percorrer um vetor dinâmico com um índice e um laço é mais barato que as duas versões da lista.
  • Cada operação vira duas funções: a pública e uma auxiliar static que recebe um ListNode *.

Resumo: recursão

Limitações: o que a estrutura não faz bem, e o que a linguagem C não confere por nós.

limitações da estrutura

  • A estrutura é a lista simples de sempre: a recursão muda o código, não o custo das operações.
  • Remover um valor ausente desce até o fim da lista: em [3, 7, 9], são 4 chamadas antes de voltar.
  • Acessar a posição i continua O(i), contra O(1) no vetor dinâmico.
  • Anexar no fim continua O(n), como na lista simples: a recursão desce nó a nó até o NULL.

limitações de C

  • A pilha tem tamanho limitado (alguns megabytes): centenas de milhares de nós podem estourá-la.
  • Quando a pilha estoura, o programa termina com falha de segmentação, sem nenhum aviso do compilador.
  • O compilador pode transformar recursão de cauda em laço, mas não é obrigado: não dá para contar com isso.

Resumo: lista circular

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • Qualquer nó serve de ponto de partida: seguindo next a partir dele, alcançam-se todos os outros.
  • Modela naturalmente revezamento e rodízio, como jogadores numa mesa ou processos no processador.
  • Dar a volta num vetor dinâmico exige calcular o índice com %; na circular, o ciclo está nas próprias ligações.

desvantagens

  • Inserir no início custa O(n): é preciso achar o último para ele apontar para o nó novo.
  • Todo laço precisa de outro critério de parada; esquecer o ponto de partida gera laço infinito.
  • O laço vira do … while: com while comum, p != l->first seria falso logo na entrada.
  • Inserir na lista vazia é um caso à parte: o único nó precisa apontar para si mesmo.

limitações da estrutura

void ll_remove(LinkedList *l, int v)
{
    ListNode *p = _search(l, v);

    if (p == NULL)
        return;

    if (p == l->first)
        l->first = p->next;
    else
        p->prev->next = p->next;

    if (p == l->last)
        l->last = p->prev;
    else
        p->next->prev = p->prev;

    free(p);
    l->count--;
}

como funciona

  • Quem cria a lista passa a ela as operações sobre os dados: imprimir, comparar e liberar.
  • As operações chegam como ponteiros para funções, e a lista as chama sem saber o que elas fazem.
  • Imprimir a lista, por exemplo, vira chamar a função de impressão recebida para cada nó.
  • Comparar, para buscar ou ordenar, também vira chamar a função de comparação recebida.

o que se ganha

  • Um tipo novo não exige mudar a lista: basta passar as funções que tratam dele.
  • A lista deixa de conhecer os tipos que guarda, que é a limitação apontada no resumo.
  • É o mesmo recurso do qsort, que ordena qualquer vetor recebendo a função de comparação.
