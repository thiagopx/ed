void ll_append(LinkedList *l, int v)
{

    node->info = v;
    node->next = NULL;

    if (l->first == NULL)
    {

        return;

void ll_insert_sorted(LinkedList *l, int v)
{
    ListNode *prev = NULL;
    ListNode *p = l->first;
    while (p != NULL && p->info < v)
    {
        prev = p;
        p = p->next;
    }
    ListNode *node = (ListNode *)malloc(sizeof(ListNode));
    node->info = v;
    if (prev == NULL)
    {
        node->next = l->first;
        l->first = node;
    }
    else
    {
        node->next = prev->next;
        prev->next = node;
    }
}

Refazer o encadeamento, depois free

ll_remove retira a primeira ocorrência e devolve 1 se achou, 0 se não.

prev == NULL→l->first = p->next
senão→prev->next = p->next
nos dois casos→só então free(p)
11_linkedlist/01_linkedlist/linkedlist.c
int ll_remove(LinkedList *l, int v)
{
    ListNode *p = l->first;
    ListNode *prev = NULL;
    while (p != NULL)
    {
        if (p->info == v)
        {
            if (prev == NULL)
                l->first = p->next;
            else
                prev->next = p->next;
            free(p);
            return 1;
        }
        else
        {
            prev = p;
            p = p->next;
        }
    }
    return 0;
}

Liberar: guardar o próximo antes do free

Depois de free(p), ler p->next seria acessar memória que não é mais do programa.

↓

↓
p = t3º: avança
11_linkedlist/01_linkedlist/linkedlist.c
void ll_free(LinkedList *l)
{
    ListNode *p = l->first;
    while (p != NULL)
    {
        ListNode *t = p->next;
        free(p);
        p = t;
    }
    free(l);
}

Uma lista a partir de um vetor

Guardar o último nó criado evita percorrer a lista a cada valor: O(n) no total, não O(n²).

ll_append a cada valor→O(n²)
guardando o último→O(1) por valor
exercício→ll_reversed e ll_concatenate
11_linkedlist/01_linkedlist/linkedlist.c
LinkedList *ll_from_array(int v[], int n)
{
    LinkedList *l = ll_create();
    ListNode *last = NULL;
    for (int i = 0; i < n; i++)
    {
        ListNode *node = (ListNode *)malloc(sizeof(ListNode));
        node->info = v[i];
        node->next = NULL;
        if (last == NULL)
            l->first = node;
        else
            last->next = node;
        last = node;
    }
    return l;
}

Ficha: lista simples

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • Cresce e diminui um nó por vez, sem realocar nem copiar os elementos que já estão na lista.
  • Inserir e retirar no início custam O(1): só o nó novo e first mudam, qualquer que seja n.
  • Usa memória proporcional ao número de elementos, sem a reserva ociosa de um vetor.

desvantagens

  • Cada elemento gasta um ponteiro next a mais: 8 bytes numa máquina de 64 bits.
  • Cada nó é uma alocação própria: um malloc a cada inserção e um free a cada remoção.
  • Sem ponteiro para o último, anexar no fim percorre a lista inteira: custa O(n).
  • Retirar exige guardar o anterior durante o percurso, porque o nó não sabe quem vem antes dele.

Limitações: o que a estrutura não faz bem, e o que a linguagem C não confere por nós.

limitações da estrutura

  • Não há acesso direto: chegar ao i-ésimo elemento exige seguir i ponteiros, custo O(i).
  • Só se anda num sentido, do primeiro ao último: não há como voltar um nó.
  • Buscar um valor visita os nós um a um: no pior caso, percorre os n nós.

limitações de C

  • Não há coleta de lixo: cada nó precisa do seu free, guardando antes o próximo.
  • Um ponteiro para um nó já liberado continua compilando; o erro só aparece na execução, de forma imprevisível.
  • ll_create usa malloc: devolver o endereço de uma variável local deixaria um ponteiro pendente.
  • A lista é só de int: outro tipo exige reescrever o código ou recorrer a void *.

11_linkedlist/08_linkedlist-last/linkedlist.c
int ll_remove(LinkedList *l, int v)
{
    ListNode *prev = NULL;
    ListNode *p = l->first;
    while (p != NULL && p->info != v)
    {
        prev = p;
        p = p->next;
    }
    if (p == NULL)
        return 0;

    if (prev == NULL)
        l->first = p->next;
    else
        prev->next = p->next;

    if (p == l->last)
        l->last = prev;

    free(p);
    return 1;
}

void ll_join(LinkedList *l1, LinkedList *l2)
{
    if (l2->first == NULL)
        return;

    if (l1->first == NULL)
        l1->first = l2->first;
    else
        l1->last->next = l2->first;
    l1->last = l2->last;

    l2->first = l2->last = NULL;
}

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • Anexar no fim custa O(1): o nó novo é ligado depois de last, sem percorrer a lista.
  • Juntar duas listas custa O(1): o último de l1 passa a apontar para o primeiro de l2.
  • É a base natural de uma fila, que entra pelo fim e sai pelo início, como veremos adiante.
  • O nó é o mesmo da lista simples: só a estrutura da lista ganha um campo, last.

desvantagens

  • Toda operação que pode mudar o último nó precisa manter last correto, e é aí que moram os erros.
  • Na lista vazia, anexar precisa atualizar first e last; atualizar só um deles corrompe a lista.
  • A estrutura da lista ganha mais um campo, que toda inserção e remoção tem de conferir.

Limitações: o que a estrutura não faz bem, e o que a linguagem C não confere por nós.

limitações da estrutura

  • Retirar o último continua O(n): é preciso achar o penúltimo, e só se anda para frente.
  • Acessar a posição i continua O(i), e buscar um valor continua O(n), como na lista simples.
  • Inserir em ordem continua O(n): a posição certa só se acha percorrendo a lista.
  • Como na lista simples, só se anda para frente: não há como voltar ao nó anterior.

limitações de C

  • Nada impede que last fique desatualizado: a coerência entre first, last e os nós é do programador.
  • Se last apontar para um nó já liberado, nada avisa: o próximo ll_append escreve em memória liberada.
  • Sem coleta de lixo, ll_free libera nó a nó, guardando o próximo antes de cada free.

Remover e devolver o novo primeiro

Quem chama reatribui o retorno — é isso que refaz o encadeamento.

p == NULL→nada a remover: devolve p
p->info == val→libera o nó e devolve p->next
senão→p->next = _ll_remove(p->next, val)
11_linkedlist/02_linkedlist-recursive/linkedlist.c
static ListNode *_ll_remove(ListNode *p, int val)
{
   ListNode *aux;
   if (p != NULL)
   {
      if (p->info == val)
      {
         aux = p;
         p = p->next;
         free(aux);
      }
      else

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • O código segue a definição da estrutura: o caso base e o passo ficam explícitos na função.

Limitações: o que a estrutura não faz bem, e o que a linguagem C não confere por nós.

limitações da estrutura

  • A estrutura é a lista simples de sempre: a recursão muda o código, não o custo das operações.

  • O compilador pode transformar recursão de cauda em laço, mas não é obrigado: não dá para contar com isso.

void ll_remove(LinkedList *l, int v)
{
    ListNode *p = _search(l, v);

    if (p == NULL)
        return;

    if (p == l->first)
        l->first = p->next;
    else
        p->prev->next = p->next;

    if (p == l->last)
        l->last = p->prev;
    else
        p->next->prev = p->prev;

    l->count--;
}

  • Posse de memória não faz parte do tipo: nada no código diz se a lista é dona do registro.
  • Liberar um registro duas vezes, ou nenhuma, compila sem aviso; o erro só aparece na execução.
  • Strings são vetores de char: == compararia os endereços, por isso a busca usa strcmp.
  • Copiar o nome para o registro exige strcpy: vetores de char não se copiam com =.

static ListNode *_first_by_name(LinkedList *l)
{

        return NULL;

    return best;
}

Qual é o tipo na posição i?

Quem chama pergunta o tipo antes de converter o ponteiro; chegar à posição i custa O(i).

11_linkedlist/06_linkedlist-generic/linkedlist.c
static ListNode *_at(LinkedList *l, int pos)
{
    if (pos < 0 || pos >= l->count)
        return NULL;
    ListNode *p = l->first;
    for (int i = 0; i < pos; i++)
        p = p->next;
    return p;
}

NodeType ll_type_at(LinkedList *l, int pos)
{
    return _at(l, pos)->type;
}

Ficha: lista heterogênea

Vantagens e desvantagens: o que se ganha e o que se paga com esta implementação.

vantagens

  • Uma única implementação de lista serve para vários tipos, sem duplicar o TAD.
  • A mesma coleção guarda elementos de tipos diferentes, como os alunos e professores de uma turma.
  • Outra lista pode apontar para os mesmos registros sem copiá-los, como faz ll_professors.
  • Buscar e retirar por CPF valem para os dois tipos, com uma auxiliar que lê o CPF conforme o tipo.

desvantagens

  • Ler o dado exige testar o tipo do nó antes de converter o void *; aqui, esse teste fica em três auxiliares.
  • Todo dado que sai da lista volta como void * e precisa de cast explícito.
  • Há duas formas de liberar (ll_free e ll_free_nodes), e escolher a errada vaza ou libera demais.

Ficha: lista heterogênea

Limitações: o que a estrutura não faz bem, e o que a linguagem C não confere por nós.

limitações da estrutura

  • Cada tipo novo mexe na lista: técnicos administrativos exigiriam alterar NodeType e as três auxiliares.
  • A lista, que deveria ser genérica, conhece todos os tipos que guarda.
  • Chegar à posição i custa O(i): na lista não há índice, como em toda lista encadeada.

limitações de C

  • Sem tipos genéricos, o void * desliga a verificação de tipos do compilador.
  • Inserir um professor marcado como aluno compila sem aviso; o erro só aparece na execução.
  • Uma conversão errada do void * não é detectada: o registro é lido com o formato errado.
  • Sem coleta de lixo nem noção de posse, quem libera cada registro depende de convenção.

Alternativa: passar as operações

Uma ideia que veremos com mais calma adiante: a lista não conhecer tipo nenhum.

como funciona

  • Quem cria a lista passa a ela as operações sobre os dados: imprimir, comparar e liberar.
  • As operações chegam como ponteiros para funções, e a lista as chama sem saber o que elas fazem.
  • Imprimir a lista, por exemplo, vira chamar a função de impressão recebida para cada nó.
  • Comparar, para buscar ou ordenar, também vira chamar a função de comparação recebida.

o que se ganha

  • Um tipo novo não exige mudar a lista: basta passar as funções que tratam dele.
  • A lista deixa de conhecer os tipos que guarda, que é a limitação apontada na ficha.
  • É o mesmo recurso do qsort, que ordena qualquer vetor recebendo a função de comparação.
