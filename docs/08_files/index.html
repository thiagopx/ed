Arquivos

Manipulação de arquivos em C

Estas são as notas da décima aula: como abrir, ler, escrever e fechar arquivos em disco a partir de um programa C, as diferenças entre tratar um arquivo em modo texto ou em modo binário, e três formas comuns de organizar dados dentro de um arquivo texto — caractere a caractere, linha a linha e por palavras-chave. Os seis exemplos interativos logo abaixo colocam parte dessa teoria em prática, passo a passo.

Arquivos

Até aqui, todo dado que um programa manipulava existia só enquanto o programa estava rodando — guardado em variáveis, vetores ou structs na memória principal (RAM), que se perdem assim que o programa termina. Um arquivo resolve essa limitação: é uma unidade de informação gravada em memória secundária (o disco), que continua existindo depois que o programa que a criou já encerrou, e que pode ser lida de volta por outro programa, ou pela mesma pessoa, tempo depois. A troca não é de graça — acessar o disco é, em geral, muito mais lento do que acessar a RAM diretamente, por isso o sistema operacional usa buffers (áreas da memória principal que funcionam como zona de trânsito entre o programa e o disco): ele lê e escreve em blocos de alguns Kbytes de cada vez, em vez de um byte por vez, para reduzir o número de acessos físicos ao dispositivo.

Cada arquivo é identificado por um nome (geralmente com uma extensão, como .txt ou .c) dentro de um diretório. Ele pode ser tratado de duas formas: em modo texto, como uma sequência de caracteres legível por um editor comum, ou em modo binário, como uma sequência de bytes que só faz sentido para o programa que sabe interpretá-la.

Arquivos texto são mais fáceis de inspecionar e editar à mão; arquivos binários costumam ser mais compactos e eficientes para grandes volumes de dados, por dispensar qualquer conversão entre a representação em memória e a representação salva. Um conceito importante em ambos os casos é o cursor: uma posição de trabalho, mantida pelo sistema operacional, que indica de onde a próxima leitura ou escrita vai acontecer. Ele avança automaticamente a cada operação bem-sucedida, e também pode ser reposicionado manualmente — como veremos na seção sobre arquivos binários.

Funções para abrir e fechar arquivos

Antes de ler ou escrever qualquer coisa, é preciso abrir o arquivo com fopen, que devolve um ponteiro do tipo FILE (um tipo opaco definido pela biblioteca padrão, que representa a abstração do arquivo aberto) ou NULL, caso a abertura falhe: 

FILE *fopen(char *nome_arquivo, char *modo);

O segundo parâmetro, modo, é uma string que combina alguns caracteres com significado próprio: r abre para leitura (o arquivo precisa já existir, senão a função falha), w abre para escrita (cria um arquivo novo vazio, destruindo qualquer conteúdo anterior com o mesmo nome) e a abre para escrita no final de um arquivo já existente, preservando o conteúdo anterior (se o arquivo não existir, um novo é criado). Um + acrescentado a qualquer um desses (r+, w+) habilita leitura e escrita no mesmo arquivo. Os caracteres t (texto) e b (binário) indicam o modo de tratamento — por convenção em C, omitir os dois costuma equivaler a modo texto. Toda abertura de arquivo deve ser seguida de uma verificação, antes de qualquer outra operação: 

FILE *fp = fopen("entrada.txt", "rt");
if (fp == NULL)
{
    printf("Erro na abertura do arquivo!\n");
    exit(1);
}

Depois de terminar de usar um arquivo, é obrigatório fechá-lo com fclose(fp): essa chamada garante que qualquer dado ainda pendente no buffer seja de fato gravado em disco (no caso de um arquivo aberto para escrita) e libera a área de memória reservada para esse buffer. A função devolve 0 em caso de sucesso, ou a constante EOF se algo der errado. Todos os seis exemplos deste módulo seguem esse par fopen/fclose — sempre verificando o retorno de fopen antes de prosseguir.

Verdadeiro ou Falso

Chamar fclose(fp) sobre um arquivo que foi aberto só para leitura (modo "r") não tem nenhum efeito, já que não há dado pendente de gravação para proteger.

  • VVerdadeiro
  • FFalso

Certo, é falso. Mesmo sem dado pendente de escrita, fclose ainda libera a área de memória reservada para o buffer e o recurso do sistema operacional associado ao arquivo — por isso vale chamá-lo mesmo depois de só ler um arquivo.

Não é isso. Independentemente do modo de abertura, fclose sempre libera a memória do buffer e o recurso do sistema operacional associado ao arquivo — só a garantia de "gravação pendente" é exclusiva de arquivos abertos para escrita.

Arquivos em modo texto

Em modo texto, o conteúdo do arquivo é interpretado como uma sequência de caracteres — os mesmos caracteres que apareceriam se o arquivo fosse aberto num editor comum. A linguagem C oferece funções específicas para ler e escrever nesse modo, próximas das já conhecidas scanf e printf, mas operando sobre um arquivo em vez da entrada e saída padrão.

Verdadeiro ou Falso

Em modo texto, o conteúdo gravado é sempre uma cópia byte a byte da representação que os dados tinham na memória do programa.

  • VVerdadeiro
  • FFalso

Certo, é falso. Essa é a característica do modo binário, não do texto. Em modo texto os dados passam por conversão/formatação (um número vira uma sequência de dígitos legíveis, por exemplo); a cópia byte a byte é exclusividade do modo binário, que vem mais adiante nesta página.

Não é isso. O modo texto formata os dados como caracteres legíveis (um número vira dígitos, por exemplo); é o modo binário que copia os bytes da memória diretamente, sem tradução.

Funções para ler dados

fscanf é a versão de scanf que lê de um arquivo em vez do teclado: recebe o ponteiro do arquivo como primeiro parâmetro, seguido da mesma string de formato e da mesma lista de endereços já usados em scanf. Seu valor de retorno é o número de itens lidos com sucesso — informação útil para detectar o fim do arquivo ou um erro de formato. 

int fscanf(FILE *fp, char *formato, ...);

Outra função de leitura muito usada é fgetc, que captura um único caractere do arquivo por vez, avançando o cursor uma posição a cada chamada. Seu tipo de retorno é int (não char) justamente para poder representar, além de qualquer código de caractere válido, a constante EOF (end of file), devolvida quando o fim do arquivo é alcançado. Já fgets lê uma linha inteira de uma vez: recebe a cadeia de caracteres que vai armazenar o resultado, o número máximo de caracteres a ler (importante para não estourar o espaço reservado) e o ponteiro do arquivo — lê até encontrar um '\n' ou atingir esse máximo, e devolve NULL quando não há mais nada para ler. 

int fgetc(FILE *fp);
char *fgets(char *s, int n, FILE *fp);

Como sempre acontece na leitura de um arquivo, o cursor avança automaticamente a cada chamada bem-sucedida — uma leitura subsequente sempre captura o trecho que vem depois do que já foi lido, nunca o mesmo trecho duas vezes.

Verdadeiro ou Falso

Se a linha do arquivo for mais longa que o limite passado para fgets, os caracteres que não couberam são descartados — a próxima chamada de fgets continua a partir da linha seguinte, ignorando o restante daquela linha.

  • VVerdadeiro
  • FFalso

Certo, é falso. fgets simplesmente para de ler ao atingir o limite, sem descartar nada — o cursor do arquivo fica exatamente onde a leitura parou, então a próxima chamada continua a partir do restante daquela mesma linha, não da linha seguinte.

Não é isso. Nada é descartado: fgets só para de ler ao atingir o limite, deixando o cursor no meio da linha — a próxima chamada continua exatamente dali, capturando o restante daquela mesma linha, não pulando para a linha seguinte.

Funções para escrever dados

As funções de escrita em modo texto espelham as de leitura. fprintf é a versão de printf que escreve num arquivo em vez da tela, recebendo o ponteiro do arquivo como primeiro parâmetro; seu retorno é o número de bytes escritos.

fputc escreve um único caractere no arquivo, devolvendo o próprio caractere escrito (ou EOF, se a escrita falhar). O exemplo Três arquivos abertos ao mesmo tempo, mais adiante, usa fprintf para gravar o resultado da soma. 

int fprintf(FILE *fp, char *formato, ...);
int fputc(int c, FILE *fp);
Verdadeiro ou Falso

O retorno de fputc é do tipo int (não char) pelo mesmo motivo do retorno de fgetc: para conseguir representar também a constante EOF em caso de falha.

  • VVerdadeiro
  • FFalso

Certo! Assim como fgetc, fputc devolve int para poder representar, além dos códigos de caractere possíveis, a constante EOF quando a escrita falha — daí a assinatura int fputc(int c, FILE *fp), com c também int, não char.

Não é isso. É exatamente o mesmo motivo do retorno int de fgetc: como EOF não é um valor de caractere válido, fputc precisa de um tipo que caiba tanto os códigos de caractere quanto essa constante extra — por isso sua assinatura usa int, não char.

Estruturação de dados em arquivos textos

Um arquivo texto não impõe nenhuma estrutura por si só — cabe a quem escreve o programa decidir como organizar os dados dentro dele, de um jeito que depois possa ser lido de volta sem ambiguidade. Três estratégias aparecem com frequência:

Caractere a caractere

fgetc num laço até EOF — ideal para contar ou classificar caracteres individuais.

Linha a linha

fgets até NULL — cada linha vira uma unidade, útil combinada com sscanf.

03_count_lines
Palavras-chave

fscanf com %s captura um token por vez — a base para despachar por tipo de registro.

02_count_words
Verdadeiro ou Falso

Um programa que lê um arquivo linha a linha com fgets só funciona corretamente se o arquivo tiver sido gravado com uma linha por registro — essa correspondência não é garantida automaticamente pelo formato texto.

  • VVerdadeiro
  • FFalso

Certo! Como o arquivo texto não impõe nenhuma estrutura por si só, cabe a quem grava os dados garantir esse alinhamento — se a escrita não seguir "uma linha por registro", a leitura por fgets não vai corresponder aos registros esperados.

Não é isso. A correspondência entre "uma linha" e "um registro" não vem de graça: é o programa que grava o arquivo que precisa seguir essa convenção para que a leitura linha a linha, com fgets, funcione como esperado.

Acesso caractere a caractere

A estratégia mais granular é varrer o arquivo um caractere por vez com fgetc, dentro de um laço que só para quando encontra EOF. É a abordagem certa quando o que importa é contar ou classificar caracteres individuais — por exemplo, contar ocorrências de '\n', ou converter cada letra minúscula para maiúscula com toupper (ctype.h), lendo de um arquivo de entrada e escrevendo, caractere a caractere, num arquivo de saída. 

int c;
while ((c = fgetc(fp)) != EOF)
{
    /* processa c */
}

O exemplo Contagem de caracteres deste módulo aplica exatamente essa técnica, aproveitando o fato de a atribuição em C também ser uma expressão: c = fgetc(fp) já vale como o próprio valor comparado com EOF na mesma condição. Vale registrar também ungetc, que "devolve" o último caractere lido para ser capturado de novo na próxima chamada — útil quando o programa precisa "espiar" o próximo caractere sem avançar o cursor de fato.

Verdadeiro ou Falso

Um laço que conta caracteres com fgetc, e usa ungetc para "devolver" um caractere logo depois de inspecioná-lo, contaria esse caractere duas vezes se o contador for incrementado antes da decisão de usar ungetc.

  • VVerdadeiro
  • FFalso

Certo! Como a chamada de fgetc seguinte a um ungetc devolve de novo o mesmo caractere, incrementar o contador antes de decidir usar ungetc conta esse caractere duas vezes — uma na primeira leitura, outra quando ele é lido de novo depois do ungetc.

Não é isso. Acontece sim: a chamada de fgetc seguinte a um ungetc devolve de novo o mesmo caractere — se o contador já tiver sido incrementado antes dessa decisão, ele seria contado duas vezes.

Acesso linha a linha

Muitas aplicações fazem mais sentido processando o arquivo uma linha inteira de cada vez, com fgets dentro de um laço que termina quando a função devolve NULL. É o caso, por exemplo, de um programa que busca a primeira linha contendo uma certa subcadeia (usando strstr) — o análogo em C do utilitário grep. O exemplo Contagem de linhas deste módulo usa essa técnica para contar e imprimir cada linha conforme é lida.

A leitura linha a linha também combina bem com sscanf, uma função irmã de fscanf que lê valores formatados de dentro de uma cadeia de caracteres já em memória, em vez de ler de um arquivo: 

int sscanf(char *s, char *formato, ...);
int sprintf(char *s, char *formato, ...); /* caminho inverso */

O padrão típico é ler uma linha inteira com fgets e, em seguida, usar sscanf para extrair os campos daquela linha — por exemplo, um caractere de tipo (r para retângulo, c para círculo) seguido dos parâmetros numéricos da figura. O retorno de sscanf (quantos itens foram lidos com sucesso) ainda permite detectar linhas vazias ou mal formatadas sem interromper a leitura do restante do arquivo. O exemplo Parser com sscanf deste módulo isola esse mecanismo: extrai nome, idade e altura de dentro de uma string já lida — o passo que viria depois de um fgets num cenário real de arquivo.

Verdadeiro ou Falso

O exemplo Parser com sscanf deste módulo usa sscanf para gravar valores formatados dentro de uma string, do mesmo jeito que sprintf faria.

  • VVerdadeiro
  • FFalso

Certo, é falso. O exemplo Parser com sscanf usa sscanf para extrair (ler) nome, idade e altura de dentro de uma string já lida — quem faria o caminho inverso, escrevendo valores formatados numa string, seria sprintf, não usado nesse exemplo.

Não é isso. sscanf lê (extrai) valores de dentro de uma string — é isso que o exemplo Parser com sscanf faz com nome, idade e altura. Gravar valores formatados numa string é papel de sprintf, o caminho inverso.

Acesso via palavras-chave

Quando os registros de um arquivo têm tamanhos variáveis — um polígono pode ter qualquer número de vértices, por exemplo — é comum precedê-los de uma palavra-chave que identifica o tipo (RETANGULO, CIRCULO, POLIGONO). 

char palavra[50];
fscanf(fp, "%s", palavra); /* ignora espaços/quebras antes */
if (strcmp(palavra, "RETANGULO") == 0) { /* ... */ }

A leitura gira em torno de capturar uma palavra por vez com fscanf(fp, "%s", palavra) e decidir, a partir do conteúdo lido (comparado com strcmp), como interpretar o que vem a seguir. O exemplo Contagem de palavras deste módulo isola justamente esse mecanismo de leitura — a mesma primitiva usada para reconhecer palavras-chave num arquivo real, mesmo sem o strcmp de despacho por tipo.

Verdadeiro ou Falso

fscanf(fp, "%s", palavra) captura a palavra inteira mesmo que ela contenha um espaço no meio, como em "RIO DE JANEIRO".

  • VVerdadeiro
  • FFalso

Certo, é falso. fscanf com %s para de capturar assim que encontra o primeiro espaço — em "RIO DE JANEIRO", a variável palavra receberia só "RIO"; capturar o nome inteiro exigiria uma abordagem diferente (como fgets seguido de outro processamento).

Não é isso. %s para no primeiro espaço que encontrar — em "RIO DE JANEIRO", palavra ficaria só com "RIO", não a cadeia inteira; espaços no meio quebram a captura de uma palavra-chave só de uma peça.

Arquivos em modo binário

Um arquivo binário guarda o conteúdo da memória diretamente, byte a byte, sem nenhuma conversão para texto — o mesmo bloco de bytes que representa uma struct em RAM é copiado, tal como está, para o disco. Isso torna a gravação e a recuperação de grandes volumes de dados bem mais eficientes do que passar por formatação de texto, ao custo de o arquivo deixar de ser legível por um editor comum.

Verdadeiro ou Falso

Se alguém abrir, num editor de texto comum, um arquivo binário que contém o float 12.5 gravado com fwrite, o editor mostraria exatamente os caracteres "1", "2", ".", "5", só que sem formatação bonita.

  • VVerdadeiro
  • FFalso

Certo, é falso. Um editor de texto tentaria interpretar os bytes brutos (41 48 00 00, no exemplo do float 12.5 visto no início da página) como caracteres — o resultado seria algo ilegível ou cheio de símbolos estranhos, nada parecido com o texto "12.5" que aparece no modo texto.

Não é isso. Os bytes brutos do float (41 48 00 00, no exemplo visto no início da página) não correspondem aos caracteres "1", "2", ".", "5" — um editor de texto exibiria algo ilegível, não os dígitos formatados que aparecem no modo texto.

Funções para salvar e recuperar

As duas funções centrais são análogas entre si: fwrite copia um bloco de memória para o arquivo, e fread faz o caminho inverso, copiando bytes do arquivo de volta para a memória. 

int fwrite(void *p, int tam, int nelem, FILE *fp);
int fread(void *p, int tam, int nelem, FILE *fp);

p é o endereço do bloco de memória, tam é o tamanho em bytes de cada elemento (tipicamente sizeof) e nelem é a quantidade de elementos — permitindo gravar ou recuperar um vetor inteiro de uma só vez. O exemplo Registros binários aplica esse par a um vetor de structs Produto: 

fwrite(produtos, sizeof(Produto), n, fp); /* grava os n de uma vez */

Uma vantagem exclusiva do modo binário é acessar diretamente um registro específico, sem ler tudo o que vem antes dele — algo que não é natural em modo texto, onde o tamanho de cada linha pode variar. Isso é possível porque, em modo binário, cada registro ocupa sempre o mesmo número de bytes, e o programador pode reposicionar o cursor com fseek: 

int fseek(FILE *fp, long offset, int origem);
Produto[0]offset 0
Produto[1]offset sizeof(Produto)
Produto[2]offset 2×sizeof(Produto)
fseek(fp, 1 × sizeof(Produto), SEEK_SET) → salta direto para Produto[1], sem ler Produto[0]

O parâmetro offset indica quantos bytes avançar, e origem indica a referência: SEEK_SET (início do arquivo), SEEK_CUR (posição atual) ou SEEK_END (final do arquivo). O exemplo Registros binários usa fseek(fp, i * sizeof(Produto), SEEK_SET) para recuperar só o segundo produto do arquivo, sem ler o primeiro.

Verdadeiro ou Falso

Trocar fwrite(produtos, sizeof(Produto), n, fp) por fwrite(produtos, sizeof(Produto), 1, fp) dentro de um laço que repete n vezes produziria, no arquivo final, o mesmo conjunto de bytes gravado pela chamada original com nelem = n.

  • VVerdadeiro
  • FFalso

Certo! O resultado final no arquivo é o mesmo — nelem só controla quantos elementos são copiados por chamada; gravar n vezes com nelem = 1 dentro de um laço produz a mesma sequência de bytes que uma única chamada com nelem = n, só que com mais chamadas (menos eficiente).

Não é isso. Os bytes gravados são idênticos nos dois casos — nelem = n numa chamada só ou nelem = 1 repetido n vezes num laço escrevem exatamente a mesma sequência de bytes; a diferença é só o número de chamadas feitas, não o conteúdo do arquivo.

#include <stdio.h>

int main()
{
    FILE *file = fopen("main.c", "r");
    // FILE *file = fopen(__FILE__, "r");

    if (file == NULL)
    {
        printf("Error opening file\n");
        return 1;
    }

    int char_count = 0;
    char ch;

    while ((ch = fgetc(file)) != EOF) // EOF is typically -1
    {
        if (ch != ' ' && ch != '\n' && ch != '\t')
        {
            char_count++;
        }
    }

    printf("Total characters (excluding spaces, tabs, and newlines): %d\n", char_count);

    fclose(file);
    return 0;
}

fgetc num laço, até EOF

O arquivo é aberto pelo próprio nome literal, "main.c" — a linha comentada logo abaixo mostra a alternativa usada pelos dois próximos exemplos, a macro __FILE__, que o pré-processador substitui pelo nome do arquivo-fonte atual. ch é declarada como int, não char: é esse detalhe que permite comparar com EOF (um valor fora da faixa normal de um char) sem ambiguidade. A atribuição dentro da condição do while — (ch = fgetc(file)) != EOF — lê e testa o caractere na mesma expressão, um padrão comum em C.

Pergunta de checagem

O código declara ch como int, não como char, mesmo cada caractere lido ocupando só um byte. O que poderia acontecer se ch fosse declarado como char neste laço, num sistema em que char é sinalizado (signed)?

  • AO programa não compilaria, pois fgetc exige uma variável int por assinatura.
  • BO laço poderia terminar antes do fim real do arquivo: um byte lido como 0xFF seria interpretado como -1, o mesmo valor de EOF.
  • CNada mudaria — char e int se comportam de forma idêntica nesta comparação.
  • DO laço passaria a contar cada caractere duas vezes.

Certo! Com char assinado, um byte de valor alto (como 0xFF) pode ser promovido para o int negativo -1 — exatamente o valor de EOF — encerrando a leitura antes do fim verdadeiro do arquivo. É por isso que fgetc devolve int, e o código segue essa convenção ao declarar ch.

Não é isso. O risco real é outro: com char assinado, um byte de valor alto (como 0xFF) pode virar o int negativo -1 ao ser comparado com EOF, terminando o laço cedo demais — mesmo sem ter chegado ao fim do arquivo.

#include <stdio.h>

int main()
{
    FILE *file = fopen(__FILE__, "r");

    if (file == NULL)
    {
        printf("Error opening file\n");
        return 1;
    }

    int word_count = 0;
    char word[100]; // sequence of non-blank characters

    while (fscanf(file, "%s", word) != EOF)
    {
        word_count++;
        printf("%s\n", word);
    }

    printf("\nTotal words in the source code: %d\n", word_count);

    fclose(file);
    return 0;
}

fscanf com %s: uma palavra por chamada

fscanf(file, "%s", word) captura a próxima sequência de caracteres não separada por espaço, tab ou quebra de linha — pulando automaticamente qualquer espaço em branco antes dela. É a mesma primitiva de leitura usada, na prática, para reconhecer palavras-chave num arquivo real (comparando o texto lido com strcmp), só que aqui sem nenhum despacho por tipo: cada "palavra" (inclusive pontuação colada a ela, como "1;" ou "(file") é só impressa e contada.

Soma de vetores em arquivo

#include <stdio.h>
#include <stdlib.h>

int main()
{
    FILE *input_file_1 = fopen("vector_1.txt", "r");
    FILE *input_file_2 = fopen("vector_2.txt", "r");
    FILE *output_file = fopen("sum_vector.txt", "w"); // w means writting

    if (input_file_1 == NULL || input_file_2 == NULL || output_file == NULL)
    {
        printf("Error opening files.\n");
        return 1;
    }

    int n1, n2;
    fscanf(input_file_1, "%d", &n1); // Read the size of the vectors
    fscanf(input_file_2, "%d", &n2);

    if (n1 != n2)
    {
        printf("Error: n1 and n2 should be equal.");
        return 1;
    }

    // Dynamically allocate memory for the vectors
    int *vector_1 = (int *)malloc(n1 * sizeof(int));
    int *vector_2 = (int *)malloc(n1 * sizeof(int));
    int *sum_vector = (int *)malloc(n1 * sizeof(int));

    if (vector_1 == NULL || vector_2 == NULL || sum_vector == NULL)
    {
        printf("Memory allocation failed.\n");
        return 1;
    }

    // Read the elements of the first vector
    for (int i = 0; i < n1; i++)
    {
        fscanf(input_file_1, "%d", &vector_1[i]);
    }

    // Read the elements of the second vector
    for (int i = 0; i < n2; i++)
    {
        fscanf(input_file_2, "%d", &vector_2[i]);
    }

    // Calculate the sum of the vectors
    for (int i = 0; i < n1; i++)
    {
        sum_vector[i] = vector_1[i] + vector_2[i];
    }

    // Write the sum_vector to the output file
    fprintf(output_file, "%d\n", n1); // Write the size of the sum vector
    for (int i = 0; i < n1; i++)
    {
        fprintf(output_file, "%d ", sum_vector[i]);
    }

    // Free dynamically allocated memory
    free(vector_1);
    free(vector_2);
    free(sum_vector);

    // Close the files
    fclose(input_file_1);
    fclose(input_file_2);
    fclose(output_file);

    printf("Sum of vectors has been written to sum_vector.txt.\n");

    return 0;
}

Três arquivos abertos ao mesmo tempo

Este exemplo combina leitura e escrita: dois arquivos (vector_1.txt, vector_2.txt) abertos para leitura e um terceiro (sum_vector.txt) aberto para escrita, todos simultaneamente — cada um com seu próprio ponteiro FILE* e seu próprio cursor independente. A leitura usa fscanf com %d, que, assim como %s, ignora espaços e quebras de linha entre um número e outro — por isso o formato do arquivo de entrada (tamanho numa linha, valores na seguinte) não precisa ser lido "linha a linha" propriamente, os números são lidos um a um independentemente de onde as quebras de linha caem. Os três vetores são alocados dinamicamente, unindo a técnica do módulo de alocação dinâmica ao conteúdo vindo de arquivo.

A leitura usa fscanf(input_file_1, "%d", &n1), que funciona independentemente de os números do arquivo estarem todos numa linha ou espalhados em várias. Por que isso não seria garantido se a leitura fosse feita com fgets (uma linha inteira por chamada, como no exemplo anterior) sem um sscanf depois para separar os valores?

  • Afgets devolveria a linha crua como texto — sem separar os números, o programa teria que interpretá-los manualmente, e uma linha com mais de um número, ou um número quebrado entre duas linhas, quebraria essa suposição.
  • Bfgets converte automaticamente cada linha lida em um número inteiro, então o resultado seria o mesmo.
  • Cfgets não pode ser usado em arquivos abertos para leitura de números, apenas texto.
  • DNão haveria diferença nenhuma — as duas funções leem exatamente o mesmo tipo de dado.

Certo! fscanf com %d ignora espaços e quebras de linha entre um número e outro, tratando o arquivo como uma sequência de tokens — por isso não importa como os números estão distribuídos entre linhas. fgets, ao contrário, devolve o texto bruto de uma linha por vez; sem um sscanf para reinterpretar esse texto, o programa dependeria de uma correspondência exata entre "linha" e "número", que este formato de arquivo não garante.

Não é isso. fscanf com %d lê o arquivo como uma sequência de tokens numéricos, ignorando onde caem as quebras de linha. fgets devolveria só o texto bruto da linha; sem sscanf para reinterpretá-lo, o programa dependeria de uma correspondência exata entre linha e número que este arquivo não garante.

A família fscanf/fprintf, aplicada a strings

Este exemplo não abre nenhum arquivo — ele isola o par sscanf/sprintf, que fazem para uma string em memória exatamente o que fscanf/fprintf fazem para um arquivo. Não é isso. A diferença central é a fonte/destino dos dados: sscanf/sprintf operam sobre uma cadeia de caracteres já em memória, sem buffer de disco nem cursor de arquivo — por isso dispensam fopen.

#include <stdio.h>
#include <stdlib.h>

typedef struct
{
    int id;
    char nome[30];
    float preco;
} Produto;

void salvar_produtos(const char *arquivo, Produto *produtos, int n)
{
    FILE *fp = fopen(arquivo, "wb");
    if (fp == NULL)
    {
        printf("Erro ao abrir arquivo para escrita.\n");
        exit(1);
    }
    fwrite(produtos, sizeof(Produto), n, fp);
    fclose(fp);
}

int carregar_produtos(const char *arquivo, Produto *produtos, int n)
{
    FILE *fp = fopen(arquivo, "rb");
    if (fp == NULL)
    {
        printf("Erro ao abrir arquivo para leitura.\n");
        return 0;
    }
    int lidos = fread(produtos, sizeof(Produto), n, fp);
    fclose(fp);
    return lidos;
}

Produto carregar_produto_por_indice(const char *arquivo, int indice)
{
    Produto p;
    FILE *fp = fopen(arquivo, "rb");
    fseek(fp, indice * sizeof(Produto), SEEK_SET);
    fread(&p, sizeof(Produto), 1, fp);
    fclose(fp);
    return p;
}

int main()
{
    Produto catalogo[3] = {
        {1, "Caderno", 12.50},
        {2, "Caneta", 3.20},
        {3, "Mochila", 89.90}
    };

    salvar_produtos("produtos.bin", catalogo, 3);
    printf("3 produtos salvos em produtos.bin (modo binario).\n\n");

    Produto lidos[3];
    int n = carregar_produtos("produtos.bin", lidos, 3);
    printf("Produtos recuperados do arquivo binario:\n");
    for (int i = 0; i < n; i++)
    {
        printf("  #%d %-10s R$ %.2f\n", lidos[i].id, lidos[i].nome, lidos[i].preco);
    }

    printf("\nAcesso direto ao produto de indice 1 (sem ler os demais):\n");
    Produto p = carregar_produto_por_indice("produtos.bin", 1);
    printf("  #%d %-10s R$ %.2f\n", p.id, p.nome, p.preco);

    return 0;
}

fwrite/fread para o vetor inteiro, fseek para um registro só

salvar_produtos grava o vetor catalogo inteiro de uma vez com fwrite(produtos, sizeof(Produto), n, fp) — os n × sizeof(Produto) bytes de memória são copiados para o arquivo tal como estão, sem nenhuma formatação de texto. carregar_produtos faz o caminho inverso com fread. Já carregar_produto_por_indice mostra a vantagem exclusiva do modo binário: como cada Produto ocupa sempre o mesmo número de bytes, fseek(fp, indice * sizeof(Produto), SEEK_SET) posiciona o cursor direto no início do registro desejado, e um único fread de sizeof(Produto) bytes recupera só aquele produto — sem precisar ler (nem alocar espaço para) os que vêm antes dele.
