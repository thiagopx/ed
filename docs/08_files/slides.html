O que é um arquivo

Um arquivo vive fora da memória do programa

Memória secundária (disco): a informação persiste depois que o programa termina — mas acessá-la é muito mais lento do que acessar a RAM.

memória principal (RAM)

rápida · variáveis, vetores, structs · some quando o programa termina

disco (arquivo)

lenta · identificada por nome + diretório (ex.: dados.txt) · persiste — outro programa, ou outra pessoa, lê depois

O cursor marca onde a próxima leitura ou escrita acontece

O arquivo é uma memória sequencial: cada leitura ou escrita avança o cursor — ao abrir para leitura, ele começa no início do arquivo.

dado 0já lido
dado 1já lido
dado 2◀ cursor: próximo
dado 3ainda não lido
…fim do arquivo
a cada leitura, o cursor avança para o dado seguinte — nunca lê o mesmo trecho duas vezes por conta própria

FILE: a abstração do arquivo aberto

Um tipo da biblioteca padrão (stdio.h) que representa o arquivo aberto — toda função de arquivo recebe um FILE*. Você já usa dois sem saber: stdin e stdout, por baixo de scanf e printf.

Abrir e fechar arquivos

fopen localiza o arquivo, prepara o buffer e devolve um FILE*

Se não conseguir — arquivo inexistente, diretório sem permissão — devolve NULL: por isso todo código testa o retorno antes de qualquer outra operação.

sucesso → FILE*

arquivo encontrado, buffer preparado, cursor no início

falha → NULL

não existe (leitura) ou sem permissão de escrita no diretório

01_count_chars/main.c
FILE *file = fopen("main.c", "r");

if (file == NULL)
{
    printf("Error opening file\n");
    return 1;
}

O modo diz o que você vai fazer com o arquivo

Segundo parâmetro de fopen: leitura, escrita ou acréscimo — e texto ou binário (omitir t/b vale como texto).

"r"

leitura — o arquivo precisa já existir

"w"

escrita — cria vazio, destrói o que já existia

"a"

escrita no final — preserva o conteúdo anterior

"+"

combinado a r/w — leitura e escrita no mesmo arquivo

"t"

modo texto — sequência de caracteres

"b"

modo binário — bytes brutos

fclose descarrega o buffer e libera o arquivo

Escrita pendente vai para o disco, a memória do buffer é liberada, e a função devolve 0 (ou EOF se algo deu errado) — obrigatório mesmo para um arquivo que só foi lido.

Chamar fclose(fp) sobre um arquivo que foi aberto só para leitura (modo "r") não tem nenhum efeito, já que não há dado pendente de gravação para proteger.

Falso

Três funções para ler: um caractere, uma linha ou um valor

Mesma família de scanf, agora lendo de um FILE* — a cada leitura, o cursor avança.

fgetc(fp)

um caractere por chamada — o grão mais fino

fgets(s, n, fp)

uma linha inteira, até '\n' ou n-1 caracteres

fscanf(fp, fmt, ...)

valores formatados, como um scanf que lê de arquivo

while (fgets(line, 200, file) != NULL)

fgets: uma linha inteira por chamada

fscanf: valores formatados, como no teclado

Mesma sintaxe de scanf, só que lendo de um FILE*; devolve quantos itens leu com sucesso — aqui, Contagem de palavras lê uma palavra por volta até EOF.

Modo binário

fwrite grava um bloco de memória; fread traz de volta

p = endereço, tam = bytes por elemento (sizeof), nelem = quantos — um vetor inteiro numa chamada só; aqui, Registros binários salva n Produtos de uma vez.

fwrite(p, tam, nelem, fp)

copia nelem × tam bytes da memória para o arquivo

fread(p, tam, nelem, fp)

o caminho inverso: do arquivo para a memória

06_binary_records/main.c
void salvar_produtos(
    const char *arquivo, Produto *produtos, int n)
{
    FILE *fp = fopen(arquivo, "wb");
    fwrite(produtos, sizeof(Produto), n, fp);
    fclose(fp);
}

Modo binário

fseek: acesso direto a um registro

Como cada registro ocupa sempre sizeof(Produto) bytes, dá para posicionar o cursor em indice × sizeof(Produto) e ler só aquele — sem passar pelos anteriores.

Produto[0]offset 0
Produto[1]offset sizeof(Produto)
Produto[2]offset 2×sizeof(Produto)
fseek(fp, 1 × sizeof(Produto), SEEK_SET) → salta direto para Produto[1], sem ler Produto[0]
06_binary_records/main.c
Produto carregar_produto_por_indice(
    const char *arquivo, int indice)
{
    Produto p;
    FILE *fp = fopen(arquivo, "rb");
    fseek(fp, indice * sizeof(Produto), SEEK_SET);
    fread(&p, sizeof(Produto), 1, fp);
    fclose(fp);
    return p;
}

Verdadeiro ou Falso

Uma única chamada fwrite(produtos, sizeof(Produto), n, fp) e n chamadas fwrite(&produtos[i], sizeof(Produto), 1, fp), uma por volta de um laço, gravam exatamente a mesma sequência de bytes no arquivo.

Verdadeiro
Falso

Verdadeiro

O resultado final no arquivo é o mesmo — nelem só controla quantos elementos são copiados por chamada: uma chamada com nelem = n copia os n de uma vez; n chamadas com nelem = 1 copiam um por vez, na mesma ordem. Mudam o número de chamadas (e a eficiência), não os bytes gravados.
