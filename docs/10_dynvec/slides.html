realloc: dois destinos possíveis

vet = realloc(vet, m * sizeof(float)); preserva os elementos já existentes — mas o endereço de retorno pode mudar.

espaço livre depois do bloco

o sistema estende o bloco no próprio lugar, sem copiar nada.

retorno == endereço antigo

sem espaço livre

aloca um novo bloco, copia o conteúdo e libera o antigo.

retorno != endereço antigo — reatribua o ponteiro!

A estratégia: dobrar a capacidade

Sempre que a capacidade se esgota, n_max dobra — poucas realocações no total.

n_max = 4capacidade esgotada
↓
realloc × 2
↓
n_max = 8nova capacidade
10_dynvec/01_dynvec/dynvec.c
static void reallocate(DynVec *dv)
{
   dv->n_max *= 2;
   dv->v = (float *)realloc(dv->v,
      dv->n_max * sizeof(float));
}

Realocação de memória

Por que não crescer de 1 em 1

Uma realocação a cada inserção pode somar um custo da ordem de n² ao inserir n elementos.

+1 por inserção

cada nova realocação pode copiar todos os elementos já inseridos.

custo total ~ n²

dobrar a capacidade

poucas realocações no total, ao preço de, por um tempo, até metade do vetor ficar alocada e vazia.

custo total ~ log n realocações

dv_insert decide antes de gravar

Só realoca quando o vetor já está cheio — n igual a n_max.

n == n_max
chama reallocate(dv)
n_max dobra antes de gravar
n < n_max
grava direto
v[n++] = x, sem realocação
10_dynvec/01_dynvec/dynvec.c
void dv_insert(DynVec *dv, float x)
{
   if (dv->n == dv->n_max)
      reallocate(dv);

   dv->v[dv->n++] = x;
}

Sem saber quantos valores tem o arquivo

dv_create_from_file insere um a um até fscanf falhar — sem ler o arquivo duas vezes.

$ make run ./test_dynvec size=1 capacity=4 10.000000 34.320000 4.300000 23.559999 9.330000 2.100000 9.810000 size=6 capacity=8 1.000000 3.000000 6.000000 10.000000 20.000000
10_dynvec/01_dynvec/dynvec.c
DynVec *dv_create_from_file(const char *filename)
{
   FILE *f = fopen(filename, "rt");
   if (f == NULL)
      return NULL;

   DynVec *dv = dv_create();
   float x;
   while (fscanf(f, "%f", &x) == 1)
      dv_insert(dv, x);

   fclose(f);
   return dv;
}

Um único campo, sempre do tamanho exato

reallocate(ds, n) reserva n + 1 bytes — sempre espaço para o terminador '\0'.

ds_assign substitui; ds_concat anexa

Os dois só diferem no tamanho pedido a reallocate.

10_dynvec/02_strdin/dynstr.c
void ds_assign(DynStr *ds, const char *s) {
    reallocate(ds, strlen(s));
    strcpy(ds->v, s);
}

void ds_concat(DynStr *ds, const char *s) {
    reallocate(ds, strlen(ds->v) + strlen(s));
    strcat(ds->v, s);
}

read_text cresce em pedaços

fgets lê até 64 bytes por vez; ds_concat anexa cada pedaço, sem saber o tamanho do arquivo.

fgets(buffer, 64, f)lê um pedaço
↓
ds_concat(s, buffer)anexa à cadeia
↻ repete até fgets devolver NULL
10_dynvec/02_strdin/main.c
DynStr* read_text(const char *filename) {
    FILE *f = fopen(filename, "rt");
    if (f == NULL)
        return NULL;

    DynStr *s = ds_create_empty();
    char buffer[64];
    while (fgets(buffer, sizeof(buffer), f) != NULL)
        ds_concat(s, buffer);

    fclose(f);
    return s;
}
