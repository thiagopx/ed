Memória dinâmica e crescimento

Vetores dinâmicos

Estas são as notas da aula sobre realocação de memória e vetores dinâmicos: como um vetor alocado com malloc pode crescer em tempo de execução com realloc, e como essa ideia vira dois TADs — um vetor dinâmico de números e uma cadeia de caracteres dinâmica. Os dois exemplos abaixo são projetos com vários arquivos e Makefile.

Vetores dinâmicos

Um vetor em C é a forma mais primitiva de representar vários elementos agrupados. Para declará-lo estaticamente é preciso escolher, antes de compilar, um número máximo de elementos: float vet[1000];. Como o vetor ocupa um espaço contíguo de memória, o símbolo vet é o endereço do primeiro elemento, e qualquer elemento é acessado diretamente por vet[i] — é esse acesso aleatório, sem precisar percorrer os elementos anteriores, que distingue o vetor de estruturas como as listas, que veremos mais adiante.

A alocação dinâmica (módulo anterior) adia essa escolha para o tempo de execução: float *vet = malloc(n * sizeof(float)); permite que n venha, por exemplo, de um valor lido em tempo de execução. Mas a necessidade de escolher um tamanho continua — só que agora em tempo de execução, não em tempo de compilação. Em muitas aplicações nem isso é possível: para ler e armazenar um conjunto de valores de um arquivo sem saber de antemão quantos valores existem, processar o arquivo duas vezes (uma para contar, outra para ler) é ineficiente, e em outros casos nem existe um valor máximo razoável para estimar. A solução, sem abrir mão das vantagens do vetor, é a realocação de memória.

Realocação de memória

A função realloc da biblioteca padrão redimensiona um bloco já alocado, preservando os elementos existentes: vet = realloc(vet, m * sizeof(float)); redimensiona vet para caber m valores, e os elementos que já estavam lá continuam lá, inalterados. Conceitualmente, realloc é equivalente a alocar um novo bloco, copiar o menor entre o tamanho antigo e o novo, e liberar o bloco antigo — mas a implementação real pode ser mais eficiente: se houver espaço livre logo depois do bloco atual, o sistema simplesmente estende o bloco no lugar, sem copiar nada, e o endereço retornado é o mesmo que foi passado. Quando não há esse espaço livre, a cópia e a liberação ocorrem de fato, e o endereço muda. É por isso que todo código que chama realloc precisa reatribuir o ponteiro ao valor de retorno — nunca supor que o endereço antigo continua válido.

Mesmo sendo útil, uma realocação tem custo computacional (na pior hipótese, a cópia de todos os elementos). Por isso, a estratégia de chamar realloc para crescer de um elemento por vez — sempre que um novo elemento é inserido — é ruim: ao inserir n elementos um a um, o custo total das cópias pode chegar à ordem de n². A estratégia mais usada na prática é dobrar a capacidade sempre que ela se esgota, o que mantém o número de realocações baixo (logarítmico em n) ao preço de, em algum momento, até metade do vetor estar alocada e ainda vazia. Outras estratégias são possíveis — aumentar em 25%, ou em um incremento fixo — e também é possível reduzir a capacidade quando a ocupação cai muito, embora isso seja raro na prática: remover elementos do meio de um vetor já exige deslocar os demais, e reduzir sua capacidade a cada remoção só aumentaria esse custo.

Vetor dinâmico

Um vetor dinâmico é um TAD — na linha do que vimos no módulo anterior sobre tipos abstratos de dados — cujo vetor interno cresce conforme elementos são inseridos, sem que o cliente precise escolher uma capacidade máxima. As operações típicas são cria (vetor vazio), insere (no final, com realocação automática quando necessário), tam (número de elementos armazenados), acessa e libera.

O projeto 01_dynvec implementa esse TAD para valores float. A struct, visível só em dynvec.c, guarda três campos: n (elementos armazenados), n_max (capacidade atual) e v (o vetor de dados). dv_create começa pequeno, com n_max = 4 — o cliente não precisa estimar nada. A inserção verifica a capacidade antes de gravar, e delega o crescimento a uma função auxiliar interna (static, portanto invisível fora do arquivo), que dobra a capacidade: 

static void reallocate(DynVec *dv)
{
   dv->n_max *= 2;
   dv->v = (float *)realloc(dv->v, dv->n_max * sizeof(float));
}

dv_insert só chama essa função quando n == n_max, isto é, quando o vetor está cheio. Com isso, o projeto resolve exatamente o problema que abriu esta aula: dv_create_from_file lê valores de um arquivo até o fim, chamando dv_insert um de cada vez, sem nunca precisar saber quantos valores o arquivo tem. O cliente (em main.c) nunca acessa os campos n, n_max ou v diretamente — só chama as funções exportadas por dynvec.h, inclusive para compor operações novas a partir das já existentes, como dv_concatenate, que cria um terceiro vetor e insere nele os elementos dos dois primeiros, usando apenas dv_size, dv_get e dv_insert.

Cadeia de caracteres dinâmica

A mesma ideia de realocação se aplica a cadeias de caracteres. O mau uso de memória em cadeias — copiar ou concatenar mais caracteres do que o vetor alocado comporta — é uma das fontes de erro mais comuns em programas C. Um TAD que gerencia esse espaço internamente, sempre com exatamente a memória necessária para o valor atual, evita esse tipo de erro: o cliente só atribui e concatena, e nunca escreve diretamente no vetor de caracteres.

O projeto 02_strdin implementa esse TAD. A struct guarda um único campo, char *v, e uma função auxiliar interna, também chamada reallocate, cuida de sempre reservar espaço para o terminador '\0': ds->v = realloc(ds->v, n + 1). ds_assign realoca para strlen(s) e copia com strcpy; ds_concat realoca para o tamanho atual mais o de s, e concatena com strcat. Como ds_get devolve um const char *, o cliente lê o valor armazenado, mas não pode alterá-lo diretamente — só através de ds_assign ou ds_concat, que são as únicas operações que sabem redimensionar o buffer.

Isso permite tratar uma cadeia dinâmica quase como um valor comum: ds_assign(city, "Recife") reatribui o conteúdo de city de forma análoga a uma atribuição numérica, mesmo que o novo texto tenha um tamanho diferente do anterior — o redimensionamento do buffer fica escondido dentro do TAD. O mesmo vetor interno que cresce elemento a elemento no vetor dinâmico, aqui cresce um pedaço de cada vez: a função read_text do projeto lê um arquivo de texto inteiro para dentro de uma DynStr, concatenando, a cada iteração, o conteúdo de um buffer fixo de leitura (fgets) — sem que o chamador precise saber o tamanho do arquivo de antemão, exatamente como dv_create_from_file fazia para números.

Como funciona o projeto

dynvec.h declara o tipo opaco DynVec e as operações exportadas. A struct, definida só em dynvec.c, guarda n (elementos armazenados), n_max (capacidade) e v (vetor de float). dv_create começa com n_max = 4.

dv_insert verifica, antes de gravar, se n == n_max; se sim, chama a função auxiliar static reallocate, que dobra n_max e chama realloc. Depois disso (ou se não houver necessidade), grava o valor em v[n] e incrementa n.

dv_create_from_file cria um vetor vazio e insere, um a um, os valores lidos de um arquivo texto com fscanf, até o fim do arquivo — sem nunca precisar saber quantos valores existem. O programa também mostra dv_concatenate, que cria um novo vetor e o preenche com os elementos de dois outros, usando apenas dv_size, dv_get e dv_insert.

01_dynvec/dynvec.c

#include "dynvec.h"
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>

// Define the structure for the dynamic vector
struct dynvec
{
   int n;     // number of elements
   int n_max; // vector capacity
   float *v;  // vector data
};

// Function to create a new dynamic vector
DynVec *dv_create()
{
   DynVec *dv = (DynVec *)malloc(sizeof(DynVec)); // Allocate memory for the DynVec structure

   dv->n = 0;                                          // Initialize the number of elements to 0
   dv->n_max = 4;                                      // Allocate initially space for 4 elements
   dv->v = (float *)malloc(dv->n_max * sizeof(float)); // Allocate memory for the vector data

   return dv; // Return a pointer to the created dynamic vector
}

// Function to create a new dynamic vector from a file
DynVec *dv_create_from_file(const char *filename)
{
   FILE *f = fopen(filename, "rt"); // Open the file for reading
   if (f == NULL)
      return NULL; // Return NULL if the file cannot be opened

   // Create a new dynamic vector
   DynVec *dv = dv_create();
   float x;
   while (fscanf(f, "%f", &x) == 1) // Read and insert values from the file into the dynamic vector
      dv_insert(dv, x);

   fclose(f); // Close the file
   return dv; // Return a pointer to the created dynamic vector
}

// Helper function to reallocate memory for the dynamic vector
static void reallocate(DynVec *dv)
{
   dv->n_max *= 2;                                             // Double the capacity
   dv->v = (float *)realloc(dv->v, dv->n_max * sizeof(float)); // Reallocate memory for the vector data
}

// Function to insert a float value into the dynamic vector
void dv_insert(DynVec *dv, float x)
{
   // Check if the capacity is enough, and if not, reallocate memory
   if (dv->n == dv->n_max)
      reallocate(dv);

   dv->v[dv->n++] = x; // Insert the value and increment the size
}

// Function to get the current size (number of elements) of the dynamic vector
int dv_size(DynVec *dv)
{
   return dv->n;
}

// Function to get the current capacity (maximum number of elements without resizing) of the dynamic vector
int dv_capacity(DynVec *dv)
{
   return dv->n_max;
}

// Function to get the value at a specific index 'i' in the dynamic vector
float dv_get(DynVec *dv, int i)
{
   assert(i >= 0 && i < dv->n); // Runtime assertion to ensure 'i' is within valid bounds

   return dv->v[i];
}

// Function to free the memory associated with the dynamic vector
void dv_free(DynVec *dv)
{
   free(dv->v); // Free the data vector
   free(dv);    // Free the ADT
}

// Function to print the values of the dynamic vector
void dv_print_values(DynVec *dv)
{
   for (int i = 0; i < dv_size(dv); i++) // Iterate through the elements of the dynamic vector
      printf("%f ", dv_get(dv, i));
   printf("\n");
}

DynVec *dv_concatenate(DynVec *dv1, DynVec *dv2)
{
   DynVec *dv = dv_create();

   for (int i = 0; i < dv_size(dv1); i++)
   {
      float v = dv_get(dv1, i);
      dv_insert(dv, v);
   }

   for (int i = 0; i < dv_size(dv2); i++)
   {
      float v = dv_get(dv2, i);
      dv_insert(dv, v);
   }

   return dv;
}
Pergunta de checagem

Depois de ler data.txt, o vetor termina com n = 6 e n_max = 8. O que aconteceria se o programa chamasse dv_insert mais duas vezes seguidas, inserindo um 7º e um 8º valor?

  • ANenhuma realocação ocorreria: n ficaria em 7 e depois 8, e só na inserção seguinte (a 9ª) n se igualaria a n_max.
  • BUma realocação ocorreria já na 7ª inserção, porque n seria igual a n_max antes de inserir.
  • CO programa travaria, porque um vetor só pode ser realocado uma única vez.
  • Ddv_insert chamaria reallocate a cada inserção, independentemente do valor de n.

Certo! dv_insert só chama reallocate quando dv->n == dv->n_max. Com n_max = 8, isso só volta a acontecer quando n chegar a 8, ou seja, na 9ª inserção a partir do estado lido do arquivo.

Não é isso. A condição de dv_insert é if (dv->n == dv->n_max) reallocate(dv);. Com n = 6 e n_max = 8, as inserções 7 e 8 não disparam essa condição; ela só voltaria a valer na 9ª inserção.

O valor 23.559999 na saída não é um erro: é o 4.3 original de data.txt impresso com seis casas decimais por %f, depois de passar por float — a representação binária de ponto flutuante não guarda 23,56 de forma exata. O exemplo compila sem nenhum aviso com -Wall.

Cadeia de caracteres dinâmica (DynStr)

ver no GitHub ↗ 
#include "dynstr.h"
#include <stdio.h>

// Reads an entire text file into a dynamic string, growing it one buffer
// at a time via ds_concat -- the caller never needs to know the file size
// in advance.
DynStr* read_text(const char *filename) {
    FILE *f = fopen(filename, "rt");
    if (f == NULL)
        return NULL;

    DynStr *s = ds_create_empty();
    char buffer[64];
    while (fgets(buffer, sizeof(buffer), f) != NULL)
        ds_concat(s, buffer);

    fclose(f);
    return s;
}

int main() {
    // A dynamic string can be reassigned like a value, growing or
    // shrinking its internal buffer as needed.
    DynStr *city = ds_create_copy("Rio de Janeiro");
    printf("city = %s\n", ds_get(city));

    ds_assign(city, "Recife");
    printf("city = %s\n", ds_get(city));
    ds_free(city);

    // Reading a whole file without knowing its size ahead of time.
    DynStr *text = read_text("poem.txt");
    printf("poem =\n%s", ds_get(text));
    ds_free(text);

    return 0;
}

Como funciona o projeto

dynstr.h declara o tipo opaco DynStr. A struct, definida só em dynstr.c, guarda um único campo, char *v. Uma função auxiliar static reallocate(ds, n) concentra a regra de tamanho: realloc(ds->v, n + 1), sempre reservando espaço extra para o '\0'.

ds_assign realoca para strlen(s) e copia com strcpy, substituindo o valor anterior; ds_concat realoca para o tamanho atual mais o de s, e concatena com strcat. ds_create_copy reaproveita ds_assign (o ponteiro interno começa em NULL, que é um primeiro argumento válido para realloc). ds_get devolve const char *: o cliente lê o valor, mas não escreve diretamente nele.

read_text ilustra a cadeia dinâmica crescendo em pedaços: a cada volta do laço, fgets lê uma linha para um buffer fixo de 64 bytes, e ds_concat anexa esse pedaço à cadeia acumulada — sem que a função conheça o tamanho do arquivo antes de terminar de lê-lo.

02_strdin/dynstr.c

#include "dynstr.h"
#include <stdlib.h>
#include <string.h>

// Implementation of the type: the dynamic string only ever keeps a buffer
// exactly as large as it needs to hold the current value plus '\0'.
struct dynstr {
    char *v;
};

// Resizes the internal buffer to hold n characters plus the terminator.
static void reallocate(DynStr *ds, int n) {
    ds->v = (char *)realloc(ds->v, n + 1);
}

// Create a new dynamic string initialized with a copy of s.
DynStr* ds_create_copy(const char *s) {
    DynStr *ds = (DynStr *)malloc(sizeof(DynStr));

    ds->v = NULL;
    ds_assign(ds, s);

    return ds;
}

// Create a new dynamic string, initially empty.
DynStr* ds_create_empty(void) {
    return ds_create_copy("");
}

// Reassign the value of an existing dynamic string to a copy of s.
void ds_assign(DynStr *ds, const char *s) {
    reallocate(ds, strlen(s));
    strcpy(ds->v, s);
}

// Append s to the end of the current value of ds.
void ds_concat(DynStr *ds, const char *s) {
    reallocate(ds, strlen(ds->v) + strlen(s));
    strcat(ds->v, s);
}

// Return the string currently stored.
const char* ds_get(DynStr *ds) {
    return ds->v;
}

// Free the memory associated with the dynamic string.
void ds_free(DynStr *ds) {
    free(ds->v);
    free(ds);
}
Pergunta de checagem

Se, em vez de trocar a cidade, o programa chamasse ds_assign(city, "Rio de Janeiro") de novo — reatribuindo o mesmo texto já armazenado — o que a função reallocate faria?

  • AChamaria realloc do mesmo jeito, com o mesmo tamanho de antes; ds_assign não verifica se o tamanho mudou, só se o valor precisa ser escrito de novo.
  • BPerceberia que o tamanho é igual ao anterior e não chamaria realloc nessa segunda vez.
  • CCausaria um vazamento de memória, porque o buffer antigo não seria liberado antes do novo malloc.
  • Dds_assign ignoraria a chamada, porque comparar o novo valor com o antigo é parte do TAD.

Certo! ds_assign sempre chama reallocate(ds, strlen(s)), e esta sempre chama realloc, independentemente de o novo tamanho coincidir com o anterior. Não há verificação de "mesmo valor" nem de "mesmo tamanho" no TAD.

Não é isso. O código de ds_assign não compara tamanhos: ele sempre chama reallocate, que sempre chama realloc(ds->v, n + 1), mesmo quando n é igual ao tamanho já alocado.

ds_get devolve const char *: o compilador recusa qualquer tentativa de escrever através desse ponteiro (por exemplo, ds_get(city)[0] = 'X'; não compila). Só ds_assign e ds_concat, dentro do próprio módulo, têm acesso de escrita ao buffer. O exemplo compila sem nenhum aviso com -Wall.
Para lembrar. realloc redimensiona um bloco preservando seu conteúdo, mas tem custo; dobrar a capacidade a cada esgotamento é a estratégia mais comum para manter esse custo baixo. Um vetor dinâmico e uma cadeia dinâmica são o mesmo TAD por trás de dois tipos diferentes: uma função auxiliar interna concentra a regra de crescimento, e o cliente só vê as operações exportadas.
