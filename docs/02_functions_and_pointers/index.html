Funções e ponteiros

Dividindo o programa em funções

Estas são as notas da aula sobre funções e ponteiros: como dividir um programa em blocos reutilizáveis, o que acontece na memória a cada chamada, e como uma função pode alterar as variáveis de quem a chamou. Os exemplos interativos logo abaixo colocam parte dessa teoria em prática, passo a passo.

Funções e ponteiros

Duas ferramentas centrais para organizar um programa maior: dividir o código em funções reutilizáveis, e usar ponteiros para que uma função consiga alterar dados de quem a chamou.

Criação de novas funções

Uma função é um bloco de código nomeado que pode ser chamado (invocado) de várias partes do programa, evitando repetir a mesma lógica. Toda função tem uma assinatura — tipo de retorno, nome e lista de parâmetros entre parênteses — seguida do corpo entre chaves. O exemplo Cilindro define cylinder_volume(double radius, double height), chamada a partir de main() sempre que o volume precisa ser calculado.

Verdadeiro ou Falso

Chamar a mesma função em cinco pontos diferentes do programa faz o compilador copiar o corpo dela cinco vezes no código-fonte — é por isso que funções economizam digitação, mas não organização.

  • VVerdadeiro
  • FFalso

Certo, é falso. O corpo da função é escrito uma única vez; cada chamada apenas desvia a execução para esse mesmo bloco e volta depois. É justamente essa ausência de duplicação que faz uma correção feita na função valer imediatamente para todos os pontos que a chamam.

Não é isso. O corpo da função aparece uma vez só; as chamadas desviam a execução para ele e retornam. Não há cópia do código a cada chamada — por isso corrigir a função conserta de uma vez todos os lugares que a usam.

Parâmetros e valor de retorno

Parâmetros são as variáveis que a função declara para receber os dados de que precisa (radius e height, no exemplo Cilindro); os valores passados na chamada — os argumentos — são copiados para esses parâmetros. O comando return devolve um valor ao ponto onde a função foi chamada e encerra a execução da função imediatamente; o tipo declarado antes do nome da função (double, no caso) precisa bater com o tipo do valor retornado. Uma função também pode ser declarada void quando não retorna valor algum — é o caso de calculate_sum_and_difference no exemplo Soma e diferença, que devolve os resultados por outro caminho: parâmetros que são ponteiros, como veremos adiante.

Verdadeiro ou Falso

Se um return for executado no meio do corpo de uma função, os comandos escritos abaixo dele naquela função não chegam a ser executados naquela chamada.

  • VVerdadeiro
  • FFalso

Certo! O return faz duas coisas ao mesmo tempo: define o valor devolvido e encerra a função ali mesmo. O que vem depois dele no corpo só rodaria se um caminho diferente da execução (por exemplo, outro ramo de um if) chegasse até lá.

É verdadeiro, sim. O return encerra a função imediatamente, além de devolver o valor: nenhum comando depois dele é executado naquela chamada.

Escopo de variáveis

Cada variável só existe — só é visível — dentro de uma região do código, chamada seu escopo. Uma variável declarada dentro de uma função (variável local) só existe enquanto essa função está em execução, e é invisível para outras funções, mesmo que tenham o mesmo nome. Isso permite que main() e cylinder_volume(), por exemplo, usem nomes de variáveis parecidos sem qualquer conflito entre si.

Verdadeiro ou Falso

Duas funções diferentes podem declarar variáveis locais com o mesmo nome sem que uma interfira no valor da outra.

  • VVerdadeiro
  • FFalso

Certo! Cada variável local pertence ao escopo da função onde foi declarada. Mesmo nome, variáveis distintas: nada em uma delas afeta a outra, e nenhuma das duas é visível de fora da sua função.

É verdadeiro, sim. O nome de uma variável local só tem significado dentro do escopo em que foi declarada; duas funções podem usar i, total ou radius sem qualquer conflito entre si.

Modelo de pilha

Cada chamada de função empilha uma nova moldura (frame) de memória, que guarda seus parâmetros e variáveis locais; quando a função retorna, a moldura é desempilhada e toda a memória que ela ocupava é liberada — é por isso que variáveis locais "somem" quando a função termina. O exemplo Cilindro deixa esse ciclo bem visível: radius e height vivem na moldura de main(); radius e height são copiados para a nova moldura de cylinder_volume(), e assim que a função retorna essa moldura desaparece, restando só o valor devolvido, agora guardado em volume, na moldura de main().

Verdadeiro ou Falso

Depois que uma função retorna, suas variáveis locais continuam existindo na pilha, então o chamador pode voltar a lê-las mais tarde sem problema.

  • VVerdadeiro
  • FFalso

Certo, é falso. Ao retornar, a moldura da função é desempilhada e o espaço que ela ocupava passa a estar livre para a próxima chamada reutilizar. As variáveis locais deixam de existir — contar com o valor delas depois do retorno é apostar em memória que já não é mais sua.

Não é isso. A moldura é desempilhada no retorno e sua memória fica livre para ser reaproveitada pela próxima chamada. Quem precisa de um valor produzido pela função tem que recebê-lo pelo return (ou por um endereço que o chamador forneceu) — não "olhando" para a moldura que já foi embora.

Ponteiro de variáveis

Um ponteiro é uma variável cujo valor não é um dado comum, mas o endereço de memória de outra variável.

Verdadeiro ou Falso

Um ponteiro é uma variável comum sob todos os aspectos — ocupa memória e tem seu próprio endereço; o que muda é o tipo de valor que ele guarda.

  • VVerdadeiro
  • FFalso

Certo! Ponteiro não é uma criatura de outra natureza: é uma variável que existe na memória como qualquer outra. A diferença está no que ela armazena — um endereço de memória, em vez de um número, um caractere ou um valor real.

É verdadeiro, sim. Um ponteiro é uma variável como outra qualquer: ocupa espaço na memória e tem endereço próprio. A particularidade é apenas o conteúdo que ele guarda — o endereço de outra variável.

Variáveis do tipo ponteiro

Um ponteiro é declarado com um asterisco antes do nome (int *ptr;), e guarda o endereço de uma variável do tipo indicado. O operador & obtém o endereço de uma variável (ptr = &num;), e o mesmo símbolo *, quando aplicado a um ponteiro já existente, dereferencia — acessa o valor guardado naquele endereço (printf("%d", *ptr);). Alterar *ptr também altera num, porque os dois nomes se referem à mesma posição de memória: é exatamente o que o exemplo Ponteiro faz ao executar *ptr = 100;.

Verdadeiro ou Falso

O asterisco de int *ptr; e o asterisco de *ptr = 100; fazem a mesma coisa: os dois dereferenciam o ponteiro.

  • VVerdadeiro
  • FFalso

Certo, é falso. O mesmo símbolo tem dois papéis distintos: na declaração, o * faz parte do tipo — anuncia que ptr guarda o endereço de um int; num comando, aplicado a um ponteiro já existente, ele dereferencia, isto é, acessa o valor que está no endereço apontado.

Não é isso. Na declaração, o * faz parte do tipo ("ponteiro para int") e não dereferencia nada — nem existe ainda um endereço para acessar. Só em um comando posterior, aplicado a um ponteiro que já aponta para algo, o * passa a significar "o conteúdo apontado".

Passando ponteiros para funções

Como os parâmetros de uma função são cópias (passagem por valor), uma função normalmente não consegue alterar as variáveis de quem a chamou — só pode devolver um resultado através do return, e só um. Passar um ponteiro como parâmetro contorna essa limitação: a função recebe o endereço da variável do chamador, e pode escrever nela diretamente através do operador *, mesmo depois de retornar. É assim que o exemplo Soma e diferença "retorna" dois valores de uma vez — calculate_sum_and_difference(num1, num2, &sum, &difference) recebe os endereços de sum e difference e escreve os resultados diretamente ali.

Verdadeiro ou Falso

Passar &sum para uma função continua sendo passagem por valor: o que é copiado para o parâmetro é o endereço de sum.

  • VVerdadeiro
  • FFalso

Certo! C só tem passagem por valor — o que muda é qual valor se copia. Copiando o endereço, a função passa a saber onde a variável do chamador mora e pode escrever lá com *; a variável em si nunca foi copiada. (Como o ponteiro recebido é uma cópia, a função pode alterar o que ele aponta, mas não pode fazer o ponteiro do chamador apontar para outro lugar.)

É verdadeiro, sim. Não existe outra forma de passagem em C: o argumento é sempre copiado. Passar &sum copia o endereço de sum para o parâmetro, e é por meio desse endereço que a função escreve na variável do chamador.

Variáveis globais e estáticas

Uma variável global é declarada fora de qualquer função e existe durante todo o programa, visível (e alterável) por qualquer função — útil às vezes, mas também uma fonte comum de bugs difíceis de rastrear, por isso deve ser usada com moderação. Uma variável local declarada como static, por outro lado, continua local a uma única função, mas seu valor é preservado entre chamadas, em vez de ser recriado do zero a cada vez: é o que o exemplo Contador de chamadas faz com static int counter = 0;, para lembrar quantas vezes a função já foi chamada.

Verdadeiro ou Falso

Uma variável global pode ser lida e alterada por qualquer função do programa — e é justamente isso que a torna uma fonte comum de bugs difíceis de rastrear.

  • VVerdadeiro
  • FFalso

Certo! Como qualquer função pode escrever numa global, descobrir quem deixou nela um valor errado exige inspecionar o programa todo. Por isso a recomendação é preferir parâmetros e retorno (ou uma local static, quando só uma função precisa lembrar algo) e reservar globais para casos realmente justificados.

É verdadeiro, sim. A global é visível e alterável por todas as funções; essa é ao mesmo tempo sua conveniência e seu risco — qualquer ponto do programa pode ser o culpado por um valor inesperado nela.

Recursão

Uma função recursiva é uma função que chama a si mesma, geralmente para resolver um problema dividindo-o em uma versão menor do mesmo problema, até alcançar um caso-base que interrompe as chamadas. Se uma função A chama a própria A, a recursão é direta; se A chama B, que por sua vez chama A de volta, a recursão é indireta — os exemplos deste módulo usam sempre a forma direta, mais comum. Cada chamada recursiva empilha sua própria moldura na pilha de execução — a mesma pilha do modelo visto acima, com parâmetros e variáveis locais independentes a cada chamada — por isso uma recursão sem caso-base, ou com um caso-base que nunca é alcançado, esgota a memória disponível e trava o programa com um erro de estouro de pilha (stack overflow).

O exemplo Fatorial recursivo aplica essa ideia ao cálculo de n!, definido recursivamente como n! = n × (n-1)!, com caso-base 0! = 1! = 1 — a tradução quase direta dessa definição para C já é a função inteira. Já vimos o mesmo cálculo de forma iterativa, com um for multiplicando os números de 1 até n (módulo de repetições, exemplo Fatorial); aqui, em vez de acumular o resultado num laço, cada chamada delega quase todo o trabalho a uma chamada menor de si mesma, até a mais simples de todas (n <= 1) resolver sozinha.

Verdadeiro ou Falso

Uma função recursiva cujo caso-base nunca é alcançado compila normalmente; o problema só aparece durante a execução.

  • VVerdadeiro
  • FFalso

Certo! Sintaticamente não há nada de errado em uma função que chama a si mesma, e o compilador não tem como decidir se o caso-base será alcançado. O programa compila, roda, empilha molduras até esgotar a memória da pilha e trava com estouro de pilha (stack overflow).

É verdadeiro, sim. O compilador só verifica a sintaxe — e chamar a si mesma é sintaticamente válido. A falta de um caso-base alcançável se manifesta em tempo de execução, como estouro de pilha.

Pré-processador e macros

Antes mesmo da compilação começar, o pré-processador do C resolve as diretivas que começam com #, como #include e #define. Uma macro criada com #define funciona como uma substituição textual: onde quer que SQUARE(x) apareça no código, o pré-processador troca pelo texto ((x) * (x)) antes de compilar — é o que o exemplo Macro quadrado faz. Por isso os parênteses em volta de cada parâmetro da macro são importantes: sem eles, uma chamada como SQUARE(a + b) se expandiria para a + b * a + b, um resultado bem diferente do esperado.

Verdadeiro ou Falso

Chamar SQUARE(num) é chamar uma função: em tempo de execução, uma moldura é empilhada com o parâmetro x, como em qualquer outra chamada.

  • VVerdadeiro
  • FFalso

Certo, é falso. Não há chamada nem moldura: o pré-processador substitui o texto SQUARE(num) por ((num) * (num)) antes de a compilação começar, e o compilador só vê a expressão já expandida. É exatamente por ser substituição textual que os parênteses ao redor de cada parâmetro importam tanto.

Não é isso. Macro não é função: a expansão acontece antes da compilação, por substituição de texto, e não existe chamada nem moldura na pilha em tempo de execução — o compilador enxerga apenas ((num) * (num)) no lugar de SQUARE(num).

Volume do cilindro

#include <stdio.h>
#include <math.h>

// Function to calculate volume of a cylinder
double cylinder_volume(double radius, double height)
{
    return M_PI * pow(radius, 2) * height;
    // return M_PI * radius * radius * height;
}

int main()
{
    double radius, height;

    printf("Enter the radius of the cylinder: ");
    scanf("%lf", &radius);

    printf("Enter the height of the cylinder: ");
    scanf("%lf", &height);

    double volume = cylinder_volume(radius, height);

    printf("\nCylinder Parameters:\n");
    printf("Radius: %.2lf\n", radius);
    printf("Height: %.2lf\n", height);
    printf("Volume: %.2lf\n", volume);

    return 0;
}

Como funciona a função

cylinder_volume é definida antes de main, com dois parâmetros (radius, height) e retorno double. Ao ser chamada em cylinder_volume(radius, height), a execução salta para dentro da função: os valores de radius e height de main são copiados para os parâmetros locais da função. O return calcula o volume e devolve esse valor para quem chamou — a expressão cylinder_volume(radius, height) "vira" esse valor, que é atribuído a volume.

Pergunta de checagem

cylinder_volume é declarada com retorno double. O que aconteceria se ela fosse declarada com retorno int, mantendo o resto do código (inclusive volume, ainda double) igual?

  • ANão mudaria nada — C converte automaticamente o tipo de retorno para bater com o tipo do double que recebe o resultado.
  • BO programa passaria a calcular a área em vez do volume.
  • CO valor calculado dentro da função (double) seria truncado para inteiro no return, perdendo a parte decimal antes mesmo de chegar a volume.
  • DO programa não compilaria, pois C não permite funções int com corpo contendo cálculos double.

Certo! O valor é convertido para o tipo de retorno declarado da função (int) antes mesmo de ser devolvido — a parte decimal do cálculo (M_PI × radius² × height) seria descartada ali, não depois, quando o double volume recebesse o resultado já truncado.

Não é essa. O tipo de retorno declarado da função é o que vale: o resultado seria truncado para int — perdendo a parte decimal — antes mesmo de ser devolvido para volume, mesmo que volume continue sendo double.

Ponteiros básicos

ver no GitHub ↗ 
#include <stdio.h>

int main()
{
    // Declare an integer variable
    int num = 42;

    // Declare a pointer to an integer
    int *ptr;

    // Assign the address of 'num' to the pointer
    ptr = &num;

    // Display the original value of 'num', the address stored in 'ptr',
    // and the value pointed to by 'ptr'
    printf("Original num value: %d\n", num);
    printf("Address stored in ptr: %p\n", (void *)ptr); // Note the typecast
    printf("Value pointed to by ptr: %d\n", *ptr);

    // Modify the value of 'num' through the pointer
    *ptr = 100;

    // Display the updated value of 'num', the address stored in 'ptr',
    // and the value pointed to by 'ptr'
    printf("Updated num value: %d\n", num);
    printf("Address stored in ptr: %p\n", (void *)ptr); // Note the typecast
    printf("Value pointed to by ptr: %d\n", *ptr);

    return 0;
}

Como funcionam & e *

&num ("endereço de") devolve a posição de memória onde num está guardado; ptr armazena esse endereço. *ptr ("conteúdo de") acessa o valor guardado naquele endereço — por isso *ptr e num sempre têm o mesmo valor: são o mesmo espaço de memória visto de dois jeitos diferentes. Alterar *ptr altera num, mesmo sem escrever num diretamente.

Pergunta de checagem

O programa altera num executando *ptr = 100;. O que aconteceria se, em vez disso, o código tentasse ptr = 100; (sem o *)?

  • AO mesmo resultado: num passaria a valer 100.
  • BErro de compilação obrigatório, pois ponteiros não podem receber valores literais.
  • Cnum seria automaticamente definida como ponteiro também.
  • Dptr deixaria de apontar para num e passaria a guardar o valor 100 como se fosse um endereço de memória — quase certamente inválido, que não deve ser dereferenciado.

Certo! Sem o *, a atribuição é sobre o próprio ptr, não sobre o que ele aponta: ptr passaria a guardar o valor 100 como se fosse um endereço de memória — quase certamente inválido — e num continuaria com seu valor original (42). É o * que redireciona a atribuição para o conteúdo apontado, não para o ponteiro em si.

Não é essa. Sem o *, você estaria alterando o próprio ponteiro, não a variável apontada: ptr passaria a guardar o valor 100 como endereço (quase certamente inválido), e num continuaria com seu valor original.

Soma e diferença

#include <stdio.h>

// Function to calculate sum and difference of two double values
void calculate_sum_and_difference(
    double a, double b, double *sum, double *difference)
{
    *sum = a + b;
    *difference = a - b;
}

int main()
{
    double num1, num2, sum, difference;

    printf("Enter the first number: ");
    scanf("%lf", &num1);

    printf("Enter the second number: ");
    scanf("%lf", &num2);

    calculate_sum_and_difference(num1, num2, &sum, &difference);

    printf("Sum: %.2lf\n", sum);
    printf("Difference: %.2lf\n", difference);

    return 0;
}

Por que ponteiros aqui

Uma função só consegue return um único valor — mas aqui precisamos de dois resultados (soma e diferença). A saída é passar os endereços de sum e difference (com &sum, &difference): a função recebe esses endereços em double *sum, double *difference e escreve diretamente neles com *sum = ... e *difference = .... Por isso a função nem precisa de return — é declarada void.

Pergunta de checagem

A função recebe double *sum, double *difference e escreve com *sum = ..., *difference = .... O que aconteceria se, em vez de ponteiros, ela recebesse os parâmetros por valor — double sum, double difference — trocando *sum = por sum = dentro da função?

  • AA função alteraria apenas suas próprias cópias locais de sum e difference; as variáveis de mesmo nome em main continuariam com valor indefinido (lixo) depois da chamada.
  • BFuncionaria exatamente igual — o compilador otimiza automaticamente a passagem para usar os endereços quando necessário.
  • CO programa não compilaria, pois uma função void não pode alterar variável nenhuma.
  • Dsum e difference em main receberiam os valores calculados, só que arredondados.

Certo! Por valor, sum e difference dentro da função seriam apenas cópias locais — alterá-las não afeta as variáveis de mesmo nome em main, que nunca chegariam a ser inicializadas de verdade. O printf imprimiria lixo de memória. É exatamente esse problema que passar os endereços (ponteiros) resolve.

Não é essa. Por valor, a função só alteraria cópias locais de sum e difference — as variáveis de main, nunca escritas, ficariam com valor indefinido (lixo). É o problema que os ponteiros resolvem neste exemplo.

Contador de chamadas

ver no GitHub ↗ 
#include <stdio.h>

// Function with a local static variable
int count_calls()
{
    static int counter = 0; // Local static variable

    counter++; // Increment the counter
    return counter;
}

int main()
{
    printf("Function has been called %d times.\n", count_calls());
    printf("Function has been called %d times.\n", count_calls());
    printf("Function has been called %d times.\n", count_calls());
    printf("Function has been called %d times.\n", count_calls());
    printf("Function has been called %d times.\n", count_calls());

    return 0;
}

Como funciona static aqui

Uma variável local comum nasce e morre a cada chamada da função. static int counter = 0; é diferente: a inicialização com 0 só acontece uma única vez, na primeira chamada — nas chamadas seguintes, counter já existe e mantém o valor que tinha ao final da chamada anterior. É assim que a função "lembra" quantas vezes já foi chamada.

Pergunta de checagem

O que aconteceria se static fosse removido de static int counter = 0;, mantendo as mesmas 5 chamadas de count_calls()?

  • AO comportamento seria idêntico, pois toda variável local em C já preserva seu valor entre chamadas por padrão.
  • Bcounter passaria a ser compartilhada entre todas as funções do programa, como se fosse global.
  • Ccounter seria recriada e reinicializada em 0 a cada chamada; a função imprimiria "1 times" nas 5 vezes, em vez de 1, 2, 3, 4, 5.
  • DO programa não compilaria, pois toda variável usada com ++ precisa ser static.

Certo! Sem static, counter volta a ser uma variável local comum: nasce e é reinicializada em 0 a cada chamada, sempre incrementada para 1 antes do retorno. As 5 chamadas imprimiriam "...1 times." cinco vezes, em vez de 1, 2, 3, 4, 5 — a função "esqueceria" quantas vezes já foi chamada.

Não é essa. Sem static, counter volta a ser uma variável local comum, sempre recriada com valor 0 a cada chamada: as 5 chamadas imprimiriam "...1 times." em todas elas, nunca avançando.

#include <stdio.h>

// Define a macro to calculate the square of a number
#define SQUARE(x) ((x) * (x))

int main()
{
    int num = 5;
    int squared = SQUARE(num);

    printf("The square of %d is %d\n", num, squared);

    return 0;
}

Macro não é função

#define é uma diretiva de pré-processador: antes mesmo da compilação, todo texto SQUARE(num) é substituído, literalmente, por ((num) * (num)). Não existe chamada de função, parâmetro ou retorno — é apenas troca de texto. Os parênteses em ((x) * (x)) não são um capricho: protegem a expressão contra problemas de precedência quando o argumento não é um nome simples (ex.: SQUARE(1 + 2) vira ((1 + 2) * (1 + 2)) = 9, e não 1 + 2 * 1 + 2 = 5, se faltassem os parênteses).

Pergunta de checagem

A macro é definida como #define SQUARE(x) ((x) * (x)). O que aconteceria se ela fosse definida sem os parênteses internos — #define SQUARE(x) (x * x) — e chamada como SQUARE(2 + 3)?

  • AA expansão viraria (2 + 3 * 2 + 3), que por precedência de operadores avalia para 11, não 25.
  • BO resultado seria o mesmo, 25 — os parênteses externos já protegem toda a expressão.
  • CO pré-processador detectaria a ausência de parênteses no parâmetro e os adicionaria automaticamente.
  • DO programa não compilaria, pois macros exigem parênteses ao redor de cada parâmetro.

Certo! Sem parênteses ao redor de x, a substituição é literal: (x * x) vira (2 + 3 * 2 + 3). Por precedência de operadores, a multiplicação (3 × 2 = 6) acontece antes das somas, dando 2 + 6 + 3 = 11 — bem diferente do 25 esperado (5²). É por isso que a macro real do exemplo envolve cada parâmetro com seus próprios parênteses.

Não é essa. A resposta certa é 11: sem parênteses ao redor de x, (x * x) vira, literalmente, (2 + 3 * 2 + 3) — a multiplicação (3 × 2) acontece antes das somas, dando 2 + 6 + 3 = 11, não 25.

Fatorial recursivo

#include <stdio.h>

long long factorial(int n)
{
    if (n <= 1)
    {
        return 1;
    }
    return n * factorial(n - 1);
}

int main()
{
    int n;
    printf("Digite um numero: ");
    scanf("%d", &n);

    printf("%d! = %lld\n", n, factorial(n));

    return 0;
}

Recursão: chamando a própria função

factorial é definida chamando a si mesma: dentro do próprio corpo, a linha return n * factorial(n - 1); invoca factorial de novo, agora com um valor menor (n - 1). if (n <= 1) return 1; é o caso-base — sem ele, a recursão nunca pararia, e o programa travaria com estouro de pilha assim que a memória disponível para molduras se esgotasse. Já vimos a versão iterativa do mesmo cálculo no módulo de repetições (03_repetition_and_rand/01_factorial, com um for); aqui, a mesma ideia — multiplicar os números de 1 até n — é resolvida de forma recursiva: cada chamada delega quase todo o trabalho a uma chamada menor de si mesma, até a mais simples de todas (n <= 1) resolver sozinha.

O tipo de retorno é long long, não int: fatoriais crescem muito rápido (13! já ultrapassa a faixa de um int de 32 bits) — por isso o especificador usado no printf é %lld, não %d. O caso-base n <= 1 (em vez de só n == 0) também cobre corretamente n = 1, sem precisar de uma chamada recursiva a mais.
Pergunta de checagem

O que aconteceria se o caso-base if (n <= 1) return 1; fosse removido de factorial, deixando só return n * factorial(n - 1);?

  • AO compilador recusaria compilar, pois toda função recursiva precisa de um caso-base explícito.
  • BA função retornaria sempre 1, independente do valor de n.
  • CO programa entraria em loop infinito, mas sem consumir memória adicional, rodando para sempre sem travar.
  • DA recursão nunca pararia: cada chamada geraria outra, com n cada vez mais negativo, até a pilha de execução se esgotar (stack overflow) e o programa travar.

Certo! Sem uma condição de parada, cada chamada de factorial(n) dispararia outra, com n cada vez menor — passando por 0, depois valores negativos — sem nunca satisfazer nenhuma condição de parada, que nem existe mais. Cada chamada empilha uma nova moldura; como a pilha de execução tem tamanho limitado, o programa eventualmente trava com um erro de estouro de pilha (stack overflow).

Não é essa. Sem o caso-base, a recursão nunca pararia: cada chamada gera outra chamada (com n cada vez mais negativo), empilhando uma nova moldura a cada vez, até a pilha de execução se esgotar (stack overflow) e o programa travar.

Para lembrar. Funções recebem parâmetros por cópia e podem devolver um único valor por return; para alterar variáveis de quem chamou — ou "retornar" mais de um valor — passe endereços (ponteiros) como parâmetro. static preserva o valor de uma variável local entre chamadas, mas continua visível só dentro da função. Uma macro (#define) não é uma função: é texto substituído antes da compilação.
