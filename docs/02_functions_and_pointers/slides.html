Criação de novas funções

Um programa bom é feito de funções pequenas

Cada função implementa uma funcionalidade específica — e o programa principal só a chama.

Uma função precisa ser conhecida antes de ser usada

Ou ela vem escrita antes de quem a chama, ou seu protótipo é declarado no topo do arquivo.

definição antes

A função inteira aparece acima de main — é o que os exemplos deste módulo fazem.

double cylinder_volume(...) { ... } int main() { ... }

protótipo antes

Só o cabeçalho, com ponto-e-vírgula: o compilador já sabe os tipos e a definição pode vir depois.

double cylinder_volume(double, double); int main() { ... }

Nomes iguais em funções diferentes são variáveis distintas, em áreas de memória distintas.

Ponteiro de variáveis

E quando a função precisa devolver dois valores?

Alterar os parâmetros não resolve: eles são cópias, e quem chamou não vê a mudança.

um resultado

A soma de dois números sai pelo return, sem dificuldade nenhuma.

return a + b;

dois resultados

Soma e diferença: escrever nos parâmetros não funciona — quem chamou continua com lixo.

sum = a + b; difference = a - b;

Ponteiro de variáveis · Variáveis do tipo ponteiro

Um ponteiro guarda um endereço

& obtém o endereço de uma variável; * acessa — ou altera — o valor guardado nele.

Ponteiro de variáveis · Variáveis do tipo ponteiro

Dois operadores, e nada mais

Para cada tipo existe um tipo ponteiro: int *, double *, char *...

&num

"endereço de" — resulta no endereço da variável

*ptr

"conteúdo de" — acessa o valor guardado naquele endereço

02_pointer/pointer.c
int num = 42;
int *ptr;

ptr = &num;      // ptr guarda o endereço de num
printf("Value pointed to by ptr: %d\n", *ptr);

*ptr = 100;      // altera num pelo ponteiro

Value pointed to by ptr: 42
Updated num value: 100
(as linhas de endereço mudam a cada execução)

Ponteiro de variáveis · Variáveis do tipo ponteiro

"p aponta para a" — daí o nome ponteiro

Em vez de escrever o endereço fictício, desenha-se uma seta: acessar a é o mesmo que acessar *p.

Ponteiro de variáveis · Variáveis do tipo ponteiro

Ponteiro não inicializado guarda um endereço-lixo

O ponteiro é uma variável como outra qualquer: sem atribuição, seu conteúdo é indefinido.

erro típico

Escrever pelo ponteiro antes de apontá-lo para algum espaço válido grava num endereço desconhecido — e o programa pode "voar".

int *p; *p = 3;

correto

Primeiro o ponteiro passa a apontar para um espaço que já existe; só então se escreve no conteúdo.

int a; int *p; p = &a; *p = 3;

Passando ponteiros para funções

Por cópia, ou pelo endereço?

Uma função só altera o que recebeu por endereço — nunca uma cópia.

func(num)

Recebe uma cópia de num — alterar essa cópia não muda o original.

num continua 10

func(&num)

Recebe o endereço de num — escreve através de *ptr na variável original.

num passa a valer 100

A porta dos fundos para retornar mais de um valor

Recebendo os endereços das variáveis de main, a função escreve os dois resultados diretamente nelas.

Passando ponteiros para funções

Dois resultados, sem nenhum return

A função é void: os resultados saem pelos endereços que ela recebeu.

Variáveis globais e estáticas

Onde cada variável mora — e por quanto tempo

local

Nasce e morre a cada chamada da função — vive na pilha e some quando ela retorna.

vida: 1 chamada

static (local)

Fora da pilha, inicializada uma única vez; preserva o valor entre chamadas, mas continua visível só ali.

vida: todo o programa

global

Declarada fora de qualquer função: existe do início ao fim do programa, visível a todas as funções seguintes.

vida: todo o programa

Variáveis globais e estáticas

static: a memória que lembra da última chamada

Sem inicialização explícita, uma variável estática começa em zero — e o valor sobrevive ao retorno da função.

int count_calls()

Variáveis globais e estáticas

Global resolve — e cria dependência

Duas funções podem se comunicar por uma variável global, mas o preço é alto.

global

Visível — e alterável — por qualquer função seguinte, e por qualquer arquivo do programa. Alto grau de interdependência entre as funções.

int s, p;

static global

Visível apenas dentro do arquivo que a declara: o nome não é exportado. Ameniza o problema, mas ainda pede critério.

static int s, p;

Variáveis globais e estáticas
Falso

O static local muda o tempo de vida (passa a durar todo o programa), não o escopo: a variável continua visível só dentro da função que a declara. Quem quer visibilidade geral usa variável global — com critério.

Recursão

Cada chamada recursiva tem o seu próprio n

As variáveis locais de cada chamada são independentes — como se fossem funções diferentes.

Recursão

Sem condição de contorno, a pilha estoura

A chamada recursiva precisa caminhar para um caso em que ela não acontece mais.

sem caso-base

A função chama a si mesma com o mesmo valor: o programa nunca termina e é interrompido quando a pilha chega ao limite.

func(n); // sempre

com caso-base

O argumento diminui a cada chamada e existe um valor em que a recursão para — a execução tem fim.

if (n <= 1) return 1;

Pré-processador e macros

Duas diretivas já usadas em todo exemplo

#include <stdio.h>

o pré-processador substitui a linha pelo corpo do arquivo — entre < > não procura no diretório local; entre " ", procura

#define SQUARE(x) ((x) * (x))

definição com parâmetros — uma macro: toda ocorrência de SQUARE(...) é trocada pelo texto correspondente

Pré-processador e macrosEstruturas de Dados
Pré-processador e macros

Uma macro no exemplo do módulo

Não há chamada de função em tempo de execução: o compilador só vê ((num) * (num)).

05_square_macro/square_macro.c
// Define a macro to calculate the square of a number
#define SQUARE(x) ((x) * (x))

int num = 5;
int squared = SQUARE(num);
execução
The square of 5 is 25

Pré-processador e macros

Cada parâmetro entre parênteses — e a macro toda também

Substituição é texto puro: sem parênteses, a precedência dos operadores muda o resultado.

#define SQUARE(x) x * x

Com SQUARE(2 + 3), o compilador vê o texto trocado cru:

2 + 3 * 2 + 3 resultado 11

#define SQUARE(x) ((x) * (x))

Com os parênteses, a expressão passada é avaliada antes da multiplicação:

((2 + 3) * (2 + 3)) resultado 25
