Pilhas e filas

Notas da aula sobre pilhas, filas e filas duplas: estruturas em que a própria regra de acesso decide quem sai, o último que entrou (pilha), o primeiro (fila) ou o de qualquer das pontas (fila dupla). Cada uma aparece em duas implementações atrás da mesma interface, uma sobre o vetor dinâmico e outra sobre a lista encadeada. Cada operação vem com o código real, o custo e simulações passo a passo nos casos que mais confundem. Cada implementação vem com suas vantagens, desvantagens e limitações, e a pilha ganha uma aplicação completa, a calculadora pós-fixada.

Pilhas e filas

No módulo anterior, a lista encadeada podia receber e perder elementos em qualquer lugar: no início, no fim, no meio, em ordem. Muitos problemas não precisam dessa liberdade toda. Eles só precisam guardar valores e devolvê-los numa ordem fixa, decidida pela própria estrutura. Neste módulo estudamos as duas estruturas mais usadas desse tipo. Na pilha, o último elemento a entrar é o primeiro a sair (regra LIFO, last in, first out). Na fila, o primeiro a entrar é o primeiro a sair (regra FIFO, first in, first out). Fechamos com a fila dupla, que aceita entrar e sair pelas duas pontas.

Restringir as operações tem uma vantagem: toda operação passa a atuar só numa ponta da estrutura, e por isso pode ser feita sem percorrer nada. Cada estrutura aparece aqui em duas implementações, uma sobre o vetor dinâmico do módulo 10 e outra sobre a lista encadeada do módulo 11, atrás da mesma interface. Quem usa a pilha não sabe qual das duas está usando, e esse é o ponto central de um TAD (módulo 9). A seção Comparando as estruturas, no fim, reúne os custos lado a lado.

Como ler os custos. Uma operação custa O(1) (constante) quando o trabalho não depende do número n de elementos, e O(n) (linear) quando cresce com n. Nas implementações com vetor, inserir costuma ser O(1), mas a inserção que encontra o vetor cheio realoca e copia os n elementos: O(n) nessa vez. Como a capacidade dobra a cada realocação, essas cópias são raras, e o custo médio por inserção continua constante.

Pilhas

Na pilha, todo acesso acontece por uma ponta só, o topo. Um elemento novo é colocado no topo e passa a ser o único acessível. Só o elemento do topo pode ser retirado. Pense numa pilha de pratos: o prato novo vai em cima, e para pegar o de baixo é preciso tirar antes os que estão sobre ele. Por isso os elementos saem na ordem inversa da chegada. As duas operações básicas têm nomes em inglês consagrados: push (empilhar) e pop (desempilhar).

A pilha mais próxima de quem programa em C é a pilha de execução. Cada chamada de função empilha as variáveis locais dela, e quando a função termina elas são desempilhadas. A função em execução só enxerga as variáveis do topo. É por isso que devolver o endereço de uma variável local é um erro: quando a função retorna, a variável sai da pilha. Esse erro já apareceu nos módulos 5 e 11.

Interface do tipo pilha

Uma pilha pode ser implementada de várias formas, mas a interface não muda. O stack.h do módulo declara um tipo opaco Stack de valores float e as operações: criar, empilhar (s_push), desempilhar (s_pop), consultar o topo sem retirá-lo (s_top), verificar se está vazia, liberar e imprimir. Este mesmo arquivo serve para as duas implementações. Só muda o comentário da primeira linha.

01_stack-array/stack.h

typedef struct stack Stack;

// Returns a new empty stack.
Stack *s_create();

// Removes and returns the top element of s.
// Requires: s is not empty.
float s_pop(Stack *s);

// Returns the top element of s without removing it.
// Requires: s is not empty.
float s_top(Stack *s);

// Pushes v onto s, doubling the capacity first if s is full (amortized O(1)).
void s_push(Stack *s, float v);

// Checks whether s is empty; returns 1 if it is, 0 otherwise.
int s_is_empty(Stack *s);

// Frees s.
void s_free(Stack *s);

// Prints the size, the capacity, the elements of s (from the top) and the whole vector.
// Cost: O(n_max).
void s_print(Stack *s);

Adaptado de: Celes, W. Estrutura de Dados.

s_pop e s_top só fazem sentido com a pilha não vazia. Nas duas implementações, a pilha vazia é tratada como erro de quem chamou, e não como um valor especial de retorno. As funções começam com assert(!s_is_empty(s)) (de assert.h), que interrompe o programa com uma mensagem quando a condição é falsa. O cliente que não tem certeza de que a pilha tem elementos deve perguntar antes, com s_is_empty.

Implementação de pilha com vetor

Estrutura e função de criação

A pilha com vetor é um vetor dinâmico, como o do módulo 10: v guarda os elementos, n_max é a capacidade atual e n é quantos elementos há. Os elementos ocupam v[0] a v[n-1], na ordem em que entraram. A base fica em v[0] e o topo em v[n-1]. Não é preciso um campo para o topo, porque n já diz onde ele está. Criar a pilha é alocar a estrutura e um vetor inicial de 4 posições, com n = 0. Custo O(1).

01_stack-array/stack.c

struct stack
{
    int n_max; // Capacity of v.
    int n;     // Number of elements; the top is v[n-1].
    float *v;
};

Stack *s_create()
{
    Stack *s = (Stack *)malloc(sizeof(Stack));
    s->n = 0;
    s->n_max = 4;
    s->v = (float *)malloc(s->n_max * sizeof(float));
    return s;
}

Adaptado de: Celes, W. Estrutura de Dados.

O comentário da linha s->n = 0 fala em "índice inválido": com n = 0, o topo seria v[-1], que não existe. É assim que a pilha vazia é representada.

Funções de inserção (push) e remoção (pop)

Empilhar é gravar na primeira posição livre, v[n], e incrementar n. Se o vetor está cheio (n == n_max), a função auxiliar reallocate dobra a capacidade com realloc antes de gravar. Ela é declarada static: só existe dentro de stack.c e não faz parte da interface. O custo é O(1) quando há espaço e O(n) na inserção que realoca, porque o realloc pode copiar os n elementos para outro lugar.

01_stack-array/stack.c

// Doubles the capacity of s.
// Cost: O(n): realloc may copy the elements to a new block.
static void reallocate(Stack *s)
{
    s->n_max *= 2;
    s->v = (float *)realloc(s->v, s->n_max * sizeof(float));
}

void s_push(Stack *s, float v)
{
    if (s->n == s->n_max)
        reallocate(s);

    s->v[s->n++] = v;
}

Adaptado de: Celes, W. Estrutura de Dados.

Repare no s->v[s->n++] = v. O operador pós-fixado usa o valor de n como índice e só depois o incrementa. O valor vai para a posição n antiga, e o novo n conta o elemento a mais. As simulações mostram a pilha vazia, a pilha com um elemento e o caso que realoca. As posições com ? nunca foram escritas: o conteúdo delas é indeterminado.

Desempilhar é o inverso. O s->v[--s->n] usa o operador prefixado: primeiro decrementa n, depois lê v[n], que era o topo. Nada é apagado. O valor continua no vetor, só que fora da parte ocupada, e o próximo push grava por cima. s_top faz a mesma conta sem alterar n: devolve v[n-1]. As duas são O(1).

01_stack-array/stack.c

float s_top(Stack *s)
{
    assert(!s_is_empty(s));
    return s->v[s->n - 1];
}

float s_pop(Stack *s)
{
    assert(!s_is_empty(s));
    return s->v[--s->n];
}

Adaptado de: Celes, W. Estrutura de Dados.

O cenário da pilha vazia foi executado de verdade, e o programa aborta com stack.c:50: s_pop: Assertion `!s_is_empty(s)' failed. Sem o assert, o --s->n deixaria n = -1 e a função leria v[-1], fora do vetor. O erro passaria em silêncio e estragaria a pilha.

Funções para verificar se vazia e para liberar

A pilha está vazia quando n == 0. Liberar é devolver os dois blocos alocados, o vetor e a estrutura, nessa ordem: depois de free(s), s->v não poderia mais ser lido. As duas são O(1).

01_stack-array/stack.c

int s_is_empty(Stack *s)
{
    return (s->n == 0);
}

void s_free(Stack *s)
{
    free(s->v);
    free(s);
}

Adaptado de: Celes, W. Estrutura de Dados.

Ficha: pilha com vetor
Vantagens
  • Push, pop e top em O(1), com acesso direto a v[n-1].
  • Elementos contíguos: nenhum ponteiro extra por elemento, e o percurso aproveita bem a memória cache.
  • Duas alocações no total (estrutura e vetor), em vez de uma por elemento.
Desvantagens
  • O push que encontra o vetor cheio custa O(n), pela realocação.
  • Reserva espaço ocioso: logo depois de dobrar, até metade do vetor fica sem uso.
  • O vetor nunca encolhe. Depois de um pico de elementos, a memória continua reservada até o s_free.
Limitações da estrutura
  • Só o topo é acessível. Para ver o terceiro elemento, é preciso desempilhar os dois de cima.
  • Retirar da pilha vazia é erro (o assert aborta), e o cliente deve testar antes com s_is_empty.
Limitações impostas por C
  • A pilha é só de float. Para outro tipo, é preciso outro TAD ou void *, com os cuidados da lista heterogênea.
  • O realloc pode mudar o vetor de lugar. Um ponteiro guardado para &v[i] antes de um push pode ficar pendente. A interface não expõe v justamente para evitar isso.
  • Não há coleta de lixo: quem cria a pilha deve chamar s_free.

Implementação de pilha com lista

Estrutura e função de criação

Na lista encadeada, inserir e retirar no início custam O(1) (módulo 11). Então o topo da pilha é o primeiro nó. A estrutura guarda só o ponteiro top, e cada nó guarda info e next, que aponta para o elemento logo abaixo. Criar é alocar a estrutura com top = NULL.

02_stack/stack.c


struct stack
{
    StackNode *top; // NULL when the stack is empty.
};

struct stacknode
{
    float info;
    StackNode *next;
};

Stack *s_create()
{
    Stack *s = (Stack *)malloc(sizeof(Stack));
    s->top = NULL;
    return s;
}

Adaptado de: Celes, W. Estrutura de Dados.

Funções de inserção (push) e remoção (pop)

s_push é o ll_insert do módulo 11: aloca um nó, faz ele apontar para o antigo topo e atualiza top. A pilha vazia não é caso especial, porque o nó novo simplesmente aponta para o NULL que estava em top. O custo é O(1), e não existe a inserção cara: cada push faz uma alocação pequena, de um nó.

02_stack/stack.c


void s_push(Stack *s, float v)
{
    StackNode *node = (StackNode *)malloc(sizeof(StackNode));
    node->info = v;
    node->next = s->top;
    s->top = node;
}

Adaptado de: Celes, W. Estrutura de Dados.

s_pop guarda o valor e o endereço do topo, avança top para o próximo e só então libera o nó antigo. A ordem importa. Se o free viesse antes, s->top->next leria memória já liberada. Retirar o único elemento também não é caso especial: top recebe o NULL que o nó guardava. s_top só lê top->info. As duas são O(1).

02_stack/stack.c

float s_top(Stack *s)
{
    assert(!s_is_empty(s));
    return s->top->info;
}

float s_pop(Stack *s)
{
    assert(!s_is_empty(s));

    float v = s->top->info;
    StackNode *p = s->top; // Saved to be freed after top moves on.
    s->top = s->top->next;
    free(p);
    return v;
}

Adaptado de: Celes, W. Estrutura de Dados.

Funções para verificar se vazia e para liberar

A pilha está vazia quando top == NULL. Liberar é o ll_free do módulo 11: percorre os nós guardando o próximo antes de cada free e, por fim, libera a estrutura. O custo é O(n), porque cada nó foi uma alocação separada e precisa do seu próprio free.

02_stack/stack.c

int s_is_empty(Stack *s)
{
    return s->top == NULL;
}

Adaptado de: Celes, W. Estrutura de Dados.

02_stack/stack.c

void s_free(Stack *s)
{
    StackNode *p = s->top;
    while (p != NULL)
    {
        StackNode *t = p->next; // Saved before free(p): p->next cannot be read afterwards.
        free(p);
        p = t;
    }
    free(s);
}

Adaptado de: Celes, W. Estrutura de Dados.

Função de impressão (versões com vetor e com lista)

Pela definição da pilha, só o topo deveria ser acessível. Para testar o código, porém, é útil ver tudo o que está guardado, e por isso as duas versões têm s_print. A versão com lista percorre do topo para a base. A versão com vetor mostra mais coisas: o tamanho, a capacidade, o índice do topo, os dados do topo para a base e a linha Memory, com as n_max posições do vetor, inclusive as que estão fora da pilha. As duas são O(n). A versão com vetor é O(n_max), por causa da linha Memory.

01_stack-array/stack.c


void s_print(Stack *s)
{
    printf("Size: %d\n", s->n);
    printf("Capacity: %d\n", s->n_max);
    printf("Top: %d\n", s->n - 1);
    printf("Data: (top) ");
    for (int i = s->n - 1; i >= 0; i--)
    {
        printf("%.2f ", s->v[i]);
    }
    printf("\nMemory: ");
    for (int i = 0; i < s->n_max; i++)
    {
        printf("%.2f ", s->v[i]);
    }
    printf("\n");
}

Adaptado de: Celes, W. Estrutura de Dados.

02_stack/stack.c

void s_print(Stack *s)
{
    for (StackNode *p = s->top; p != NULL; p = p->next)
        printf("%.2f ", p->info);

    printf("\n");
}

Adaptado de: Celes, W. Estrutura de Dados.

Atenção à linha Memory. Ela lê posições que podem nunca ter sido escritas. O malloc e a parte nova do realloc não inicializam a memória, e o valor dessas posições é indeterminado. Na execução mostrada nos exemplos, elas saíram como 0.00, mas isso não é garantido: compilado com o AddressSanitizer, por exemplo, o mesmo programa mostra outros valores. Não trate esses zeros como resultado esperado.
Ficha: pilha com lista
Vantagens
  • Push, pop e top em O(1) sempre, sem a inserção cara da realocação.
  • Memória proporcional ao número de elementos: a pilha cresce e encolhe um nó por vez.
  • Nenhum elemento muda de endereço enquanto está na pilha.
Desvantagens
  • Cada elemento gasta um ponteiro next (8 bytes numa máquina de 64 bits) além do float (4 bytes), mais o custo de uma alocação por push.
  • Liberar a pilha custa O(n): um free por nó.
  • Os nós ficam espalhados pela memória, o que torna o percurso mais lento que o de um vetor.
Limitações da estrutura
  • As mesmas da pilha com vetor: só o topo é acessível, e retirar da pilha vazia aborta.
Limitações impostas por C
  • Cada nó retirado precisa de free, depois de lido o que se precisa dele. O ponteiro p que sobra fica pendente.
  • Só float, como na versão com vetor.
  • O typedef de StackNode aparece no .h, mas a struct só no .c. O cliente conhece o nome do tipo do nó, mas não consegue mexer nos campos.
Problema resolvido: escrever um número em binário

Problema. Imprimir um inteiro não negativo em base 2: 13 deve sair como 1101.

Estratégia. As divisões sucessivas por 2 dão os bits do número, mas do menos significativo para o mais significativo: os restos de 13 são 1, 0, 1, 1, e a resposta é essa sequência ao contrário. Inverter uma sequência é o que a pilha faz. A função empilha cada resto e, no fim, desempilha até esvaziar. O laço é um do-while para que o 0 ainda produza um dígito. A função usa só a interface (s_create, s_push, s_is_empty, s_pop, s_free), então funciona sem mudança com as duas implementações. Ela foi compilada e executada com cada uma, e as duas saídas são idênticas: 1101, 110 e 0 para 13, 6 e 0. O custo é proporcional ao número de bits, cerca de log₂ x.

código cliente: binary.c

// Prints x (x >= 0) in base 2. The remainders of the divisions by 2 come out
// from the least significant bit to the most significant: the stack reverses them.
void print_binary(int x)
{
    Stack *s = s_create();
    do
    {
        s_push(s, x % 2); // Least significant bit first...
        x = x / 2;
    } while (x > 0);

    while (!s_is_empty(s))
        printf("%d", (int)s_pop(s)); // ...printed last.
    printf("\n");
    s_free(s);
}
Problema resolvido: cancelar vizinhos iguais

Problema. Numa sequência de valores, dois valores iguais que ficam vizinhos se cancelam e somem. Com isso, os vizinhos deles passam a ser vizinhos entre si e também podem se cancelar. Queremos saber o que sobra: 5 3 3 5 7 vira 7, porque os dois 3 se cancelam e depois os dois 5; 1 2 2 1 some inteira; e 1 2 1 2 não muda.

Estratégia. Lendo da esquerda para a direita, o único valor que pode cancelar o valor novo é o último que sobrou até agora, e esse é o topo de uma pilha. A cada valor, a função compara com o topo antes de decidir: se for igual, desempilha (os dois somem); senão, empilha. É aqui que s_top aparece, junto com dois cuidados. O primeiro é a ordem do teste: !s_is_empty(s) && s_top(s) == v[i] só chama s_top se a pilha não estiver vazia, porque o && de C para na primeira condição falsa, e s_top com a pilha vazia abortaria. O segundo é o fim: a pilha vazia significa que tudo se cancelou, e o que sobra nela é a resposta, impressa do topo para a base. Cada valor entra e sai no máximo uma vez, então o custo é O(n). A função foi compilada e executada com as duas implementações de pilha, e as duas imprimem 7 (1 left), (0 left) e 2 1 2 1 (4 left).

código cliente: cancel.c

// Cancels equal neighbors: reading v from left to right, a value equal to the one on the
// top of the stack cancels it (both disappear); otherwise it waits on the top. Prints what
// is left (top first) and returns how many values were left.
int cancel_pairs(float v[], int n)
{
    Stack *s = s_create();
    for (int i = 0; i < n; i++)
    {
        if (!s_is_empty(s) && s_top(s) == v[i]) // test empty first: s_top asserts
            s_pop(s);                           // v[i] cancels the top
        else
            s_push(s, v[i]); // nothing to cancel: v[i] waits on the top
    }
    int left = 0;
    while (!s_is_empty(s))
    {
        printf("%.0f ", s_pop(s));
        left++;
    }
    printf("(%d left)\n", left);
    s_free(s);
    return left;
}

Exemplo de uso: calculadora pós-fixada

Notação pós-fixada

Na notação usual, chamada infixa, o operador fica entre os operandos, e para avaliar (1 - 2) * (4 + 5) é preciso de parênteses e de regras de precedência. Na notação pós-fixada (ou notação polonesa reversa, RPN), o operador vem depois dos operandos, e a mesma expressão fica 1 2 - 4 5 + *, sem parênteses. As calculadoras RPN avaliam essa notação com uma pilha. Cada operando é empilhado. Cada operador binário desempilha dois valores, calcula e empilha o resultado.

Em 1 2 - 4 5 + *: empilham-se 1 e 2; o - desempilha 2 e 1 e empilha 1 - 2 = -1; empilham-se 4 e 5; o + desempilha 5 e 4 e empilha 9. Nesse momento, a pilha tem os dois resultados parciais, −1 na base e 9 no topo. O * desempilha os dois e empilha −9. Repare na ordem: o primeiro valor desempilhado é o operando da direita. Em 1 2 -, sai primeiro o 2, e a conta é 1 − 2, não 2 − 1.

Interface da calculadora

A calculadora é outro TAD, construído sobre o TAD pilha. Ela é criada com um formato de impressão (um formato de printf, como "%.2f\n"), recebe operandos e operadores um de cada vez e, a cada passo, imprime o novo topo. O projeto 05_postfix-calc usa a pilha com vetor, mas calc.c só chama funções do stack.h. Trocar stack.c pela versão com lista não muda uma linha da calculadora.

05_postfix-calc/calc.h

typedef struct calc Calc;

// Returns a new calculator; fmt is the printf format used to show the top (e.g. "%.2f\n").
Calc *calc_create(const char *fmt);

// Pushes the operand v onto c and prints the new top.
void calc_operand(Calc *c, float v);

// Pops two operands of c, applies op (+, -, * or /), pushes the result and prints the new top;
//   a missing operand counts as zero.
void calc_operator(Calc *c, char op);

// Frees c and its stack.
void calc_free(Calc *c);

Adaptado de: Celes, W. Estrutura de Dados.

Estrutura e função de criação

A estrutura guarda o formato numa cadeia de até 20 caracteres e um ponteiro para a pilha de operandos. A cópia usa strncpy com limite de 20 e grava o '\0' na última posição explicitamente, porque o strncpy não termina a cadeia quando a origem é longa demais (módulo 6). Um strcpy, como no livro, escreveria além de fmt[20] se recebesse um formato maior.

05_postfix-calc/calc.c

struct calc
{
    char fmt[21]; // Format used to print the top of the stack
    Stack *s;     // Stack of operands (any Stack implementation works)
};

Calc *calc_create(const char *fmt)
{
    Calc *c = (Calc *)malloc(sizeof(Calc));
    strncpy(c->fmt, fmt, 20);
    c->fmt[20] = '\0';
    c->s = s_create();
    return c;
}

Adaptado de: Celes, W. Estrutura de Dados.

Funções operando e operador

calc_operand empilha e imprime o valor. calc_operator desempilha o segundo operando (v2, o topo) e depois o primeiro (v1), aplica o operador na ordem v1 op v2, empilha o resultado e o imprime. Se faltar operando, ele vale zero. É para isso que serve o teste s_is_empty(c->s) ? 0.0f : s_pop(c->s), que evita o assert de s_pop. O v começa em 0.0f para que um operador desconhecido não empilhe lixo. Cada chamada é O(1) (a menos de uma realocação).

05_postfix-calc/calc.c

void calc_operand(Calc *c, float v)
{
    s_push(c->s, v);
    printf(c->fmt, v);
}

void calc_operator(Calc *c, char op)
{
    float v2 = s_is_empty(c->s) ? 0.0f : s_pop(c->s); // Second operand (top).
    float v1 = s_is_empty(c->s) ? 0.0f : s_pop(c->s);
    float v = 0.0f;

    switch (op)
    {
    case '+': v = v1 + v2; break;
    case '-': v = v1 - v2; break;
    case '*': v = v1 * v2; break;
    case '/': v = v1 / v2; break;
    }

    s_push(c->s, v);
    printf(c->fmt, v);
}

Adaptado de: Celes, W. Estrutura de Dados.

Função para liberar

Filas

A fila é a fila do dia a dia: quem chega entra no fim, quem é atendido sai do início. O primeiro a entrar é o primeiro a sair (FIFO). Um uso clássico em computação é a fila de impressão de uma impressora compartilhada, em que os documentos são impressos na ordem em que chegaram. A fila atua nas duas pontas: insere numa e retira da outra. É isso que a torna mais delicada de implementar que a pilha.

Interface do tipo fila

O queue.h declara o tipo opaco Queue de float e as operações: criar, inserir no fim (q_enqueue, "enfileirar"), retirar do início (q_dequeue, "desenfileirar"), verificar se está vazia, liberar e imprimir. Como na pilha, as duas implementações têm a mesma interface, e retirar de fila vazia é erro de quem chamou.

Implementação de fila com vetor

Incremento circular

Uma ideia simples seria guardar a fila em v[0..n-1], inserir em v[n] e, ao retirar v[0], deslocar todos os outros uma posição para a esquerda. Funciona, mas cada retirada custaria O(n). Para evitar o deslocamento, a fila guarda o índice do seu primeiro elemento, head. Inserir grava depois do último. Retirar só avança head. Assim a fila "anda" pelo vetor: depois de inserir 1.4, 2.2, 3.5 e 4.0 e retirar dois, o início está na posição 2.

Andando assim, a fila chega ao fim do vetor, enquanto as posições antes de head ficaram livres. A solução é tratar o vetor como circular: depois da última posição vem a posição 0. O incremento de um índice i passa a ser i = (i + 1) % n_max. O resto da divisão faz n_max - 1 voltar para 0. Com isso, a fila pode ocupar o fim e o começo do vetor ao mesmo tempo.

As convenções, as mesmas do livro de Cormen et al. (CLRS), são duas. head é a posição do próximo elemento a sair, e tail é a posição livre onde entra o próximo. A estrutura não guarda tail, que é calculado a partir de head e do número de elementos: tail = (head + n) % n_max. Guardar n resolve uma ambiguidade. Com a fila vazia e com a fila cheia, tail e head coincidem, e é n que diferencia os dois casos.

Estrutura e função de criação

A estrutura tem o vetor dinâmico (v, n_max), o número de elementos n e o índice head. Criar é alocar a estrutura e um vetor de 4 posições, com n = 0 e head = 0. Custo O(1).

Função de inserção (com realocação)

Inserir é gravar em tail = (head + n) % n_max e incrementar n. O caso difícil é o vetor cheio. O realloc dobra o vetor e mantém cada valor no mesmo índice, o que só serve se a fila não der a volta, isto é, se head == 0. Se head != 0, a fila ocupa o trecho de head até o fim do vetor antigo e depois o trecho do começo. Depois de dobrar, entre esses dois trechos ficam as posições novas, ainda vazias, e a ordem circular se quebra. A correção é mover o primeiro trecho, de head até o fim antigo, para o fim do vetor novo, e atualizar head.

03_queue-array/queue.c

// Doubles the capacity of q.
// Cost: O(n): realloc may copy the elements to a new block.
static void reallocate(Queue *q)
{
    q->n_max *= 2;
    q->v = (float *)realloc(q->v, q->n_max * sizeof(float));
}

void q_enqueue(Queue *q, float v)
{
    if (q->n == q->n_max)
    {
        reallocate(q);

        // If the queue wraps around the end of the old vector, the block from head to
        // the old end must move to the end of the new vector. memmove (string.h) copies
        // a block of bytes, like a loop copying element by element.
        if (q->head != 0)
        {
            memmove(
                &q->v[q->n_max - q->n + q->head], // destination
                &q->v[q->head],                   // source
                (q->n - q->head) * sizeof(float)  // bytes to shift
            );
            q->head = q->n_max - q->n + q->head;
        }
    }
    int tail = (q->head + q->n) % q->n_max;
    q->v[tail] = v;
    q->n++;
}

Adaptado de: Celes, W. Estrutura de Dados.

O deslocamento usa uma função nova, memmove, de string.h: memmove(destino, origem, nbytes) copia um bloco de nbytes bytes de um endereço para outro. Aqui ela equivale a um laço que copia elemento a elemento. Com k = n - head elementos a mover e d = n_max - n + head, o novo início, a chamada faz o mesmo que 

for (int i = k - 1; i >= 0; i--)  // same effect as the memmove call
    q->v[d + i] = q->v[q->head + i];

A contagem é em bytes, e não em elementos: daí o * sizeof(float). E por que memmove, e não a parecida memcpy? A memcpy só tem comportamento definido quando os dois blocos não se sobrepõem. A memmove funciona mesmo com sobreposição, como se copiasse primeiro para um lugar temporário. Neste código, o trecho movido tem k elementos e anda n_max - n posições (o tamanho antigo). Como k < n, origem e destino nunca se encontram, e memcpy funcionaria. Mas provar isso exige uma conta, e uma mudança na política de crescimento (crescer 50% em vez de dobrar, por exemplo) poderia criar a sobreposição. A memmove é a escolha que continua certa sem depender dessa conta. O laço do exemplo acima também tem um detalhe: ele copia de trás para a frente, que é a ordem segura quando o destino fica à direita da origem.

O custo é O(1) quando há espaço e O(n) quando realoca. A simulação "cheia e dando a volta" é exatamente o estado do exemplo interativo na linha 27 do main.c.

Funções de retirada, para verificar se vazia e para liberar

Retirar é ler v[head], avançar head circularmente e decrementar n. Nada é deslocado: O(1). Uma consequência é que a fila vazia nem sempre tem head = 0. Depois de inserir e retirar um elemento, head = 1 e n = 0, e isso é uma fila vazia válida. A próxima inserção vai para a posição 1. Verificar se está vazia é testar n == 0, e liberar é devolver o vetor e a estrutura. As duas são O(1).

float q_dequeue(Queue *q)
{
    assert(!q_is_empty(q));
    float v = q->v[q->head];
    q->head = (q->head + 1) % q->n_max;
    q->n--;
    return v;
}

int q_is_empty(Queue *q)
{
    return (q->n == 0);
}

void q_free(Queue *q)
{
    free(q->v);
    free(q);
}

Implementação de fila com lista

Estrutura e função de criação

Numa lista simplesmente encadeada, retirar do início é O(1), mas retirar do fim não. Para achar o novo último, seria preciso percorrer a lista, porque o nó não sabe quem vem antes dele. Então o início da fila é o primeiro nó, de onde se retira, e o fim é o último, onde se insere. Para inserir no fim sem percorrer, a estrutura guarda dois ponteiros: head (primeiro nó) e tail (último nó). É a lista com ponteiro para o último do módulo 11. Note que aqui tail aponta para o último elemento, enquanto no vetor ele indicava a próxima posição livre. Os dois significados são os do CLRS para cada representação.

Funções de inserção e retirada

q_enqueue aloca um nó com next = NULL e o liga depois de tail. Se a fila está vazia, não há último a ligar, e o nó novo passa a ser também o primeiro. Esse é o caso em que head muda numa inserção. Em todos os casos, tail passa a apontar para o nó novo. Custo O(1).

{

   node->info = v;
   node->next = NULL;

      q->head = node;
   else
      q->tail->next = node;

   q->tail = node;
}

q_dequeue guarda o valor e o nó do início e avança head. O cuidado está na fila com um nó só (head == tail): depois da retirada, os dois ponteiros precisam virar NULL. Se só head mudasse, tail continuaria apontando para o nó liberado, um ponteiro pendente. Custo O(1).

float q_dequeue(Queue *q)
{
   assert(!q_is_empty(q));

   float v = q->head->info;
   QueueNode *p = q->head; // Saved to be freed after head moves on.

   if (q->head != q->tail)
      q->head = q->head->next;
   else
      q->head = q->tail = NULL;

   free(p);
   return v;
}

Problema resolvido: média móvel

Problema. Ler uma sequência de medidas e, depois de cada uma, imprimir a média das k últimas (ou de todas, enquanto houver menos de k). Para 4, 8, 6, 2, 10 e k = 3, a saída é 4.00 6.00 6.00 5.33 6.00.

Estratégia. A janela das k últimas medidas é uma fila. Cada medida nova entra no fim e, quando a janela passa de k, a mais antiga sai do início. Em vez de somar a janela inteira a cada passo, a função mantém a soma, acrescentando o valor que entra e subtraindo o que q_dequeue devolve. Como a interface não tem função de tamanho, o cliente conta os elementos ele mesmo. Cada medida custa O(1), e o total é O(n). A função foi compilada e executada com as duas implementações de fila, com a mesma saída.

código cliente: average.c

// Prints, after each of the n values of v, the average of the last k values read.
// The queue holds exactly the window: when it grows past k, the oldest value leaves.
void moving_average(float v[], int n, int k)
{
    Queue *q = q_create();
    float sum = 0;
    int count = 0; // The queue has no size function: the client keeps its own count.
    for (int i = 0; i < n; i++)
    {
        q_enqueue(q, v[i]);
        sum += v[i];
        count++;
        if (count > k)
        {
            sum -= q_dequeue(q); // The oldest value leaves the window.
            count--;
        }
        printf("%.2f ", sum / count);
    }
    printf("\n");
    q_free(q);
}
Problema resolvido: inverter os k primeiros de uma fila

Problema. Inverter a ordem dos k primeiros elementos de uma fila de n, mantendo os demais na ordem original: com k = 3, a fila 1 2 3 4 5 6 vira 3 2 1 4 5 6.

Estratégia. Junta os dois TADs do módulo, cada um usado pela sua regra de saída. Os k primeiros saem da fila (FIFO, na ordem) e entram numa pilha. Ao voltarem da pilha para o fim da fila (LIFO), chegam invertidos. Nesse ponto, a fila é 4 5 6 3 2 1: os n - k elementos que não foram mexidos estão na frente. Para levá-los para trás, cada um sai pelo início e entra pelo fim uma vez. Acompanhar onde está cada ponta a cada passo (o topo da pilha, o início e o fim da fila) é o que permite prever o resultado sem executar. Como a fila não informa o tamanho, o cliente passa n. Cada elemento faz no máximo duas viagens, e o custo é O(n). A função foi compilada e executada com as quatro combinações de pilha e fila (vetor ou lista), e todas produzem 3 2 1 4 5 6.

código cliente: reverse_k.c

// Reverses the first k of the n elements of q, keeping the order of the others.
// The queue has no size function, so the client passes n.
void reverse_first_k(Queue *q, int n, int k)
{
    Stack *s = s_create();
    for (int i = 0; i < k; i++)
        s_push(s, q_dequeue(q)); // The first k go to the stack...
    while (!s_is_empty(s))
        q_enqueue(q, s_pop(s)); // ...and come back reversed, at the end of the queue.
    for (int i = 0; i < n - k; i++)
        q_enqueue(q, q_dequeue(q)); // The other n - k go around once, to the end.
    s_free(s);
}

Fila dupla

A fila dupla (em inglês, deque, de double-ended queue) permite inserir e retirar nas duas pontas. Ela generaliza as duas estruturas anteriores. Usando só push_back e pop_front, é uma fila. Usando só push_back e pop_back, é uma pilha. Também se pode pensar nela como duas filas na mesma estrutura, uma em cada sentido.

O deque.h declara o tipo Deque com quatro operações de inserção e retirada, dq_push_front, dq_push_back, dq_pop_front e dq_pop_back, além de criar, verificar se está vazia, liberar e imprimir. Os nomes seguem os da biblioteca padrão de C++ (std::deque).

// Cost: O(n).
static void reallocate(Deque *d)
{
    d->n_max *= 2;
    d->v = (float *)realloc(d->v, d->n_max * sizeof(float));
    if (d->head != 0)
    {
        int k = d->n - d->head; // elements between head and the end of the old vector
        memmove(&d->v[d->n_max - k], &d->v[d->head], k * sizeof(float));
        d->head = d->n_max - k;
    }
}

void dq_push_back(Deque *d, float v)
{
    if (d->n == d->n_max)
        reallocate(d);
    int tail = (d->head + d->n) % d->n_max;
    d->v[tail] = v;
    d->n++;
}

float dq_pop_front(Deque *d)
{
    assert(!dq_is_empty(d));
    float v = d->v[d->head];
    d->head = (d->head + 1) % d->n_max;
    d->n--;
    return v;
}

Inserção no início (decremento circular)

Inserir no início é gravar na posição anterior a head, e para isso é preciso um decremento circular: antes da posição 0 vem n_max - 1. A conta intuitiva (head - 1) % n_max não funciona em C. Quando head = 0, ela vale -1 % 4, que em C é -1, não 3, porque o resto tem o sinal do dividendo. Somar n_max antes resolve: (head - 1 + n_max) % n_max está sempre entre 0 e n_max - 1. Custo O(1), ou O(n) quando realoca.

06_deque-array/deque.c

void dq_push_front(Deque *d, float v)
{
    if (d->n == d->n_max)
        reallocate(d);
    d->head = (d->head - 1 + d->n_max) % d->n_max; // + n_max: from 0, wraps to n_max - 1.
    d->v[d->head] = v;
    d->n++;
}

Adaptado de: Celes, W. Estrutura de Dados.

Retirada do fim

O último elemento está em (head + n - 1) % n_max: a posição de tail menos uma. Retirá-lo é só decrementar n, e head não muda. Custo O(1). Verificar se está vazia (O(1)), liberar (O(1)) e imprimir (O(n_max), por causa da linha Memory) são iguais aos da fila.

Implementação de fila dupla com lista

Estrutura com lista duplamente encadeada

Com lista simplesmente encadeada, três das quatro operações seriam fáceis. Inserir no início e retirar do início vêm da pilha, e inserir no fim vem da fila. A que não dá é retirar do fim: com tail apontando para o último, não há como chegar ao penúltimo, que passaria a ser o último, sem percorrer a lista desde head. A solução é a lista duplamente encadeada do módulo 11, em que cada nó tem também prev. A estrutura guarda head e tail. Como só as pontas são manipuladas, o código fica mais simples que o da lista dupla geral.

{
    float info;
    DequeNode *prev;
    DequeNode *next;
};

    Deque *d = (Deque *)malloc(sizeof(Deque));

As inserções são as da lista dupla. O nó novo nasce com o ponteiro "de fora" valendo NULL (prev no início, next no fim) e o "de dentro" apontando para a ponta atual. Se a estrutura estava vazia, o nó novo é as duas pontas. Senão, a ponta antiga passa a apontar de volta para ele. As duas são O(1).

void dq_push_front(Deque *d, float v)
{
    DequeNode *node = (DequeNode *)malloc(sizeof(DequeNode));
    node->info = v;
    node->prev = NULL;
    node->next = d->head;
    if (dq_is_empty(d))
        d->tail = node;
    else
        d->head->prev = node;
    d->head = node;
}

void dq_push_back(Deque *d, float v)
{
    DequeNode *node = (DequeNode *)malloc(sizeof(DequeNode));
    node->info = v;
    node->next = NULL;
    node->prev = d->tail;
    if (dq_is_empty(d))
        d->head = node;
    else
        d->tail->next = node;
    d->tail = node;
}

Funções de retirada (início e fim)

As duas retiradas são simétricas. Guardam o nó da ponta e seu valor, movem a ponta para o vizinho (next no início, prev no fim) e então conferem se a estrutura esvaziou. Se a nova ponta é NULL, a outra ponta também precisa virar NULL. Senão, o vizinho perde a ligação com o nó que sai. Só então o nó é liberado. Graças a prev, retirar do fim é O(1). Liberar a estrutura inteira é O(n), e imprimir, que segue next de head até NULL, também.

07_deque/deque.c


float dq_pop_front(Deque *d)
{
    assert(!dq_is_empty(d));
    DequeNode *t = d->head;
    float v = t->info;
    d->head = t->next;
    if (d->head == NULL) // the deque became empty
        d->tail = NULL;
    else
        d->head->prev = NULL;
    free(t);
    return v;
}

float dq_pop_back(Deque *d)
{
    assert(!dq_is_empty(d));
    DequeNode *t = d->tail;
    float v = t->info;
    d->tail = t->prev; // No walk: prev gives the new last node.
    if (d->tail == NULL) // the deque became empty
        d->head = NULL;
    else
        d->tail->next = NULL;
    free(t);
    return v;
}

void dq_free(Deque *d)
{
    DequeNode *p = d->head;
    while (p != NULL)
    {
        DequeNode *t = p->next; // Saved before free(p): p->next cannot be read afterwards.
        free(p);
        p = t;
    }
    free(d);
}

void dq_print(Deque *d)
{
    for (DequeNode *p = d->head; p != NULL; p = p->next)
        printf("%.2f ", p->info);
    printf("\n");
}

Problema resolvido: girar a fila dupla

Problema. Girar a fila dupla k posições. Com k > 0, os k primeiros elementos vão para o fim. Com k < 0, os -k últimos vão para o início. Girar 1 2 3 4 5 com k = 2 dá 3 4 5 1 2, e girar esse resultado com k = -3 dá 5 1 2 3 4.

Estratégia. Combina retirar de uma ponta e inserir na outra. Para girar para a esquerda, dq_push_back(d, dq_pop_front(d)) repetido k vezes. Para a direita, o espelho, com dq_pop_back e dq_push_front. Nenhum nó é criado nem destruído no saldo, e a fila dupla vazia é tratada antes, porque o pop abortaria. O custo é O(|k|), independente de n. A função foi compilada e executada com as duas implementações. Com a de lista, ela imprime exatamente as três linhas 1.00 2.00 3.00 4.00 5.00, 3.00 4.00 5.00 1.00 2.00 e 5.00 1.00 2.00 3.00 4.00. Com a de vetor, a linha Data de dq_print mostra as mesmas sequências.

código cliente: rotate.c

// Rotates the deque k positions: k > 0 moves k elements from the front to the back,
// k < 0 moves -k elements from the back to the front.
void rotate(Deque *d, int k)
{
    if (dq_is_empty(d))
        return;
    for (; k > 0; k--)
        dq_push_back(d, dq_pop_front(d));
    for (; k < 0; k++)
        dq_push_front(d, dq_pop_back(d));
}

Para reconhecer a estrutura num problema, pergunte quem precisa sair primeiro. Se é sempre o mais recente (voltar pelo caminho percorrido num labirinto, retomar a função que chamou a atual, como na pilha de execução, casar cada item com o anterior ainda pendente), é uma pilha. Se é o mais antigo (atender na ordem de chegada, manter uma janela das últimas medidas), é uma fila. Se o problema precisa das duas pontas (girar, ou consumir pelas duas extremidades), é uma fila dupla. Para justificar a escolha, simule a estrutura com os dados do problema e mostre, a cada passo, onde estão o topo, ou o início e o fim.

#include "stack.h"
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct stack
{
    int n_max; // Capacity of v.
    int n;     // Number of elements; the top is v[n-1].
    float *v;
};

Stack *s_create()
{
    Stack *s = (Stack *)malloc(sizeof(Stack));
    s->n = 0;
    s->n_max = 4;
    s->v = (float *)malloc(s->n_max * sizeof(float));
    return s;
}

// Doubles the capacity of s.
// Cost: O(n): realloc may copy the elements to a new block.
static void reallocate(Stack *s)
{
    s->n_max *= 2;
    s->v = (float *)realloc(s->v, s->n_max * sizeof(float));
}

void s_push(Stack *s, float v)
{
    if (s->n == s->n_max)
        reallocate(s);

    s->v[s->n++] = v;
}

float s_top(Stack *s)
{
    assert(!s_is_empty(s));
    return s->v[s->n - 1];
}

float s_pop(Stack *s)
{
    assert(!s_is_empty(s));
    return s->v[--s->n];
}

int s_is_empty(Stack *s)
{
    return (s->n == 0);
}

void s_free(Stack *s)
{
    free(s->v);
    free(s);
}

void s_print(Stack *s)
{
    printf("Size: %d\n", s->n);
    printf("Capacity: %d\n", s->n_max);
    printf("Top: %d\n", s->n - 1);
    printf("Data: (top) ");
    for (int i = s->n - 1; i >= 0; i--)
    {
        printf("%.2f ", s->v[i]);

#include "queue.h"
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct queue
{
    int n;
    int n_max; // Capacity of v.
    int head;  // Index of the first element (the tail is (head + n) % n_max)
    float *v;
};

Queue *q_create()
{
    Queue *q = (Queue *)malloc(sizeof(Queue));

    q->n = 0;
    q->n_max = 4;
    q->v = (float *)malloc(q->n_max * sizeof(float));
    q->head = 0;

    return q;
}

// Doubles the capacity of q.
// Cost: O(n): realloc may copy the elements to a new block.
static void reallocate(Queue *q)
{
    q->n_max *= 2;
    q->v = (float *)realloc(q->v, q->n_max * sizeof(float));
}

void q_enqueue(Queue *q, float v)
{
    if (q->n == q->n_max)
    {
        reallocate(q);

        // If the queue wraps around the end of the old vector, the block from head to
        // the old end must move to the end of the new vector. memmove (string.h) copies
        // a block of bytes, like a loop copying element by element.
        if (q->head != 0)
        {
            memmove(
                &q->v[q->n_max - q->n + q->head], // destination
                &q->v[q->head],                   // source
                (q->n - q->head) * sizeof(float)  // bytes to shift
            );
            q->head = q->n_max - q->n + q->head;
        }
    }
    int tail = (q->head + q->n) % q->n_max;
    q->v[tail] = v;
    q->n++;
}

float q_dequeue(Queue *q)
{
    assert(!q_is_empty(q));
    float v = q->v[q->head];
    q->head = (q->head + 1) % q->n_max;
    q->n--;
    return v;
}

int q_is_empty(Queue *q)
{
    return (q->n == 0);
}

void q_free(Queue *q)
{
    free(q->v);
    free(q);
}

void q_print(Queue *q)
{
    printf("Size: %d\n", q->n);
    printf("Capacity: %d\n", q->n_max);
    printf("Head: %d \t Tail: %d\n", q->head, (q->head + q->n) % q->n_max);
    printf("Data: ");
    for (int i = 0; i < q->n; i++)
    {
        printf("%.2f ", q->v[(q->head + i) % q->n_max]);
    }
    printf("\n");
    printf("Memory: ");
    for (int i = 0; i < q->n_max; i++)
    {
        printf("%.2f ", q->v[i]);
    }
    printf("\n");
}

Como funciona o projeto

A representação é a da fila circular. dq_push_back e dq_pop_front são o enqueue e o dequeue. As novidades são dq_push_front, que decrementa head circularmente, e dq_pop_back, que só decrementa n.

O primeiro dq_push_front acontece com head = 0, e o elemento vai para a última posição do vetor. Depois, um dq_push_back encontra o vetor cheio com a fila dando a volta, e a realocação move o trecho do início.

#include "deque.h"
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct deque
{
    int n;
    int n_max; // Capacity of v.
    int head;  // Index of the first element (the tail is (head + n) % n_max)
    float *v;
};

Deque *dq_create()
{
    Deque *d = (Deque *)malloc(sizeof(Deque));
    d->n = 0;
    d->n_max = 4;
    d->v = (float *)malloc(d->n_max * sizeof(float));
    d->head = 0;
    return d;
}

// Doubles the capacity of d, keeping the circular order (same as the queue).
// Cost: O(n).
static void reallocate(Deque *d)
{
    d->n_max *= 2;
    d->v = (float *)realloc(d->v, d->n_max * sizeof(float));
    if (d->head != 0)
    {
        int k = d->n - d->head; // elements between head and the end of the old vector
        memmove(&d->v[d->n_max - k], &d->v[d->head], k * sizeof(float));
        d->head = d->n_max - k;
    }
}

void dq_push_front(Deque *d, float v)
{
    if (d->n == d->n_max)
        reallocate(d);
    d->head = (d->head - 1 + d->n_max) % d->n_max; // + n_max: from 0, wraps to n_max - 1.
    d->v[d->head] = v;
    d->n++;
}

void dq_push_back(Deque *d, float v)
{
    if (d->n == d->n_max)
        reallocate(d);
    int tail = (d->head + d->n) % d->n_max;
    d->v[tail] = v;
    d->n++;
}

float dq_pop_front(Deque *d)
{
    assert(!dq_is_empty(d));
    float v = d->v[d->head];
    d->head = (d->head + 1) % d->n_max;
    d->n--;
    return v;
}

float dq_pop_back(Deque *d)
{
    assert(!dq_is_empty(d));
    int last = (d->head + d->n - 1) % d->n_max; // head does not move.
    d->n--;
    return d->v[last];
}

int dq_is_empty(Deque *d)
{
    return d->n == 0;
}

void dq_free(Deque *d)
{
    free(d->v);
    free(d);
}

void dq_print(Deque *d)
{
    printf("Size: %d\n", d->n);
    printf("Capacity: %d\n", d->n_max);
    printf("Head: %d \t Tail: %d\n", d->head, (d->head + d->n) % d->n_max);
    printf("Data: ");

    printf("\nMemory: ");

    printf("\n");
}

Pergunta de checagem

Se os nós desta fila dupla não tivessem prev (lista simplesmente encadeada, ainda com head e tail), quanto custaria dq_pop_back?

  • AO(1): tail já aponta para o último nó.
  • BO(1), mas só se a fila dupla tiver um elemento.

Não é isso. A resposta é O(n). Retirar o último é fácil, mas tail precisa passar a apontar para o penúltimo, e sem prev a única forma de achá-lo é percorrer desde head. Por isso a fila dupla usa a lista duplamente encadeada.

#include "deque.h"
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>

struct deque
{
    DequeNode *head;
    DequeNode *tail;
};

// A doubly linked node: prev is what makes removing from the end efficient.
struct deque_node
{
    float info;
    DequeNode *prev;
    DequeNode *next;
};

Deque *dq_create()
{
    Deque *d = (Deque *)malloc(sizeof(Deque));
    d->head = d->tail = NULL;
    return d;
}

int dq_is_empty(Deque *d)
{
    return d->head == NULL;
}

void dq_push_front(Deque *d, float v)
{
    DequeNode *node = (DequeNode *)malloc(sizeof(DequeNode));
    node->info = v;
    node->prev = NULL;
    node->next = d->head;
    if (dq_is_empty(d))
        d->tail = node;
    else
        d->head->prev = node;
    d->head = node;
}

void dq_push_back(Deque *d, float v)
{
    DequeNode *node = (DequeNode *)malloc(sizeof(DequeNode));
    node->info = v;
    node->next = NULL;
    node->prev = d->tail;
    if (dq_is_empty(d))
        d->head = node;
    else
        d->tail->next = node;
    d->tail = node;
}

float dq_pop_front(Deque *d)
{
    assert(!dq_is_empty(d));
    DequeNode *t = d->head;
    float v = t->info;
    d->head = t->next;
    if (d->head == NULL) // the deque became empty
        d->tail = NULL;
    else
        d->head->prev = NULL;
    free(t);
    return v;
}

float dq_pop_back(Deque *d)
{
    assert(!dq_is_empty(d));
    DequeNode *t = d->tail;
    float v = t->info;
    d->tail = t->prev; // No walk: prev gives the new last node.
    if (d->tail == NULL) // the deque became empty
        d->head = NULL;
    else
        d->tail->next = NULL;
    free(t);
    return v;
}

void dq_free(Deque *d)
{
    DequeNode *p = d->head;
    while (p != NULL)
    {
        DequeNode *t = p->next; // Saved before free(p): p->next cannot be read afterwards.
        free(p);
        p = t;
    }
    free(d);
}

void dq_print(Deque *d)
{
    for (DequeNode *p = d->head; p != NULL; p = p->next)
        printf("%.2f ", p->info);
    printf("\n");
}
